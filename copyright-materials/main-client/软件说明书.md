## 1. 引言

### 1.1 开发背景

随着人工智能技术的快速发展，数字生命体交互已成为人工智能应用的重要方向。数字生命主客户端系统（HeartSphere）旨在为用户提供一个完整的数字生命体交互平台，让用户能够创建、管理和与数字生命体进行深度交互。

### 1.2 开发目的

本系统的开发目的是：
- 提供一个完整的数字生命体交互平台
- 支持用户创建和管理自己的数字世界
- 实现与数字生命体的智能对话和互动
- 提供丰富的场景和角色扮演功能
- 支持剧本系统和剧情推进

### 1.3 开发意义

数字生命主客户端系统的开发具有以下意义：
- 推动数字生命体技术的发展和应用
- 为用户提供全新的交互体验
- 探索人工智能在数字世界中的应用
- 为数字生命体交互领域提供技术积累

## 2. 功能描述

### 2.1 AI对话系统

系统提供强大的AI对话功能，支持用户与数字生命体进行自然语言交互。

**主要功能：**
- 支持多轮对话，保持上下文理解
- 支持多种AI模型（Gemini、OpenAI、Qwen、豆包等）
- 支持对话历史记录和回放
- 支持对话情感分析和反馈

**技术实现：**
- 前端使用React组件实现对话界面，支持实时消息显示和输入
- 后端通过Spring Boot RESTful API接收对话请求
- 集成多种AI服务接口，支持模型切换和配置
- 使用JWT认证确保对话安全
- 对话历史存储在MySQL数据库中，支持分页查询
- 上下文管理通过对话会话ID关联，保持多轮对话的连贯性

**使用场景：**
- 用户可以与场景中的角色进行对话，了解角色背景和故事
- 用户可以通过对话推进剧情发展
- 用户可以通过对话获取场景相关信息
- 支持语音输入和文字输入两种方式

### 2.2 场景管理系统

用户可以创建和管理不同的场景（时代切片），每个场景代表一个独立的数字世界。

**主要功能：**
- 场景创建和编辑
- 场景分类和标签管理
- 场景预览和切换
- 场景共享和导入导出

**技术实现：**
- 场景数据存储在MySQL数据库中，包含场景基本信息、配置、角色列表等
- 前端提供场景编辑器，支持可视化编辑场景属性
- 场景切换通过React Router实现，保持状态隔离
- 场景共享通过心域连接功能实现，支持公开和私有两种模式
- 场景导入导出使用JSON格式，便于数据迁移和备份

**数据结构：**
- 场景基本信息：名称、描述、封面图、创建时间等
- 场景配置：时代背景、世界观设定、规则配置等
- 场景角色列表：场景中包含的所有角色
- 场景剧本列表：场景中的剧本事件

**使用场景：**
- 用户可以创建"我的大学"场景，重现大学生活
- 用户可以创建"赛博都市"场景，体验未来世界
- 用户可以创建"古代王朝"场景，体验历史故事
- 支持场景模板，快速创建新场景

### 2.3 角色扮演系统

用户可以在场景中创建角色（数字生命体），并与角色进行交互。

**主要功能：**
- 角色创建和编辑
- 角色属性配置（名称、头像、描述等）
- 角色技能配置
- 角色记忆管理

### 2.4 剧本系统

用户可以创建和管理剧本，定义剧情事件和触发条件。

**主要功能：**
- 剧本创建和编辑
- 剧本事件定义
- 剧本触发条件配置
- 剧本执行和推进

### 2.5 插件系统

系统提供可扩展的插件机制，支持功能扩展。

**主要功能：**
- 插件开发和管理
- 插件动态加载和卸载
- 插件与场景的集成
- 插件API和SDK

### 2.6 心域连接功能

支持用户共享自己的心域，或访问他人的心域（体验模式）。

**主要功能：**
- 心域共享设置
- 心域快速连接
- 体验模式访问
- 心域权限管理

### 2.7 跨时空信箱功能

支持用户在不同场景之间发送和接收消息。

**主要功能：**
- 跨场景消息发送
- 消息接收和管理
- 消息历史记录
- 消息通知

## 3. 系统架构

### 3.1 整体架构

系统采用前后端分离架构，包括以下层次：

```
┌─────────────────────────────────────────┐
│           客户端层 (Client)              │
│  ┌──────────┐  ┌──────────┐            │
│  │ Web前端  │  │ 移动端   │            │
│  │ React    │  │ Capacitor│            │
│  └──────────┘  └──────────┘            │
└─────────────────────────────────────────┘
                  │ HTTP/HTTPS
┌─────────────────────────────────────────┐
│           应用层 (Application)           │
│  ┌──────────────────────────────────┐  │
│  │   Spring Boot RESTful API        │  │
│  │   Controller → Service → Repo    │  │
│  └──────────────────────────────────┘  │
└─────────────────────────────────────────┘
                  │
┌─────────────────────────────────────────┐
│           数据层 (Data)                  │
│  ┌──────────┐  ┌──────────┐            │
│  │  MySQL   │  │  AI服务  │            │
│  │  数据库  │  │  接口    │            │
│  └──────────┘  └──────────┘            │
└─────────────────────────────────────────┘
```

### 3.2 前端架构

前端采用React + TypeScript + Vite技术栈：

- **组件化架构**：基于React组件化开发
- **状态管理**：使用React Hooks和Context API
- **路由管理**：使用React Router
- **UI框架**：使用Tailwind CSS
- **构建工具**：使用Vite进行快速构建

### 3.3 后端架构

后端采用Spring Boot微服务架构：

- **分层架构**：Controller → Service → Repository → Entity
- **数据访问**：使用Spring Data JPA
- **安全认证**：使用Spring Security + JWT
- **API文档**：使用SpringDoc OpenAPI (Swagger)
- **数据库迁移**：使用Flyway

### 3.4 模块划分

系统主要模块包括：
- 用户模块（User）：用户注册、登录、资料管理、权限管理
- 场景模块（Scene）：场景创建、编辑、删除、查询、共享
- 角色模块（Character）：角色创建、编辑、删除、属性配置、技能管理
- 对话模块（Chat）：AI对话、对话历史、上下文管理、情感分析
- 剧本模块（Script）：剧本创建、编辑、执行、触发条件配置
- 插件模块（Plugin）：插件开发、加载、卸载、API管理
- 心域连接模块（HeartConnect）：心域共享、快速连接、体验模式、权限管理

### 3.5 数据流设计

**用户请求流程：**
1. 用户在客户端发起请求（如创建场景）
2. 前端通过HTTP/HTTPS发送请求到后端API
3. 后端Controller接收请求，进行参数验证和权限检查
4. Service层处理业务逻辑，调用Repository进行数据操作
5. Repository层与MySQL数据库交互，执行SQL操作
6. 返回结果通过Service层、Controller层返回给前端
7. 前端更新UI，显示操作结果

**AI对话流程：**
1. 用户输入对话内容
2. 前端发送对话请求到后端API
3. 后端Service层构建对话上下文（包含历史对话）
4. 调用AI服务接口（Gemini、OpenAI等）
5. AI服务返回对话结果
6. 后端保存对话历史到数据库
7. 返回对话结果给前端显示

### 3.6 安全设计

**认证机制：**
- 使用JWT（JSON Web Token）进行用户认证
- Token包含用户ID、角色、权限等信息
- Token有过期时间，支持刷新机制
- 所有API请求需要在Header中携带Token

**授权机制：**
- 基于RBAC（基于角色的访问控制）
- 不同角色拥有不同的功能权限
- 数据访问权限基于用户ID进行隔离
- 敏感操作需要二次验证

**数据安全：**
- 使用HTTPS加密传输
- 敏感数据（密码、API密钥）加密存储
- SQL注入防护：使用参数化查询
- XSS防护：前端输入验证和输出转义

## 5. 技术特点

### 5.1 技术创新点

1. **数字生命体交互技术**：创新的数字生命体交互机制，支持多轮对话和上下文理解
2. **场景管理系统**：支持创建和管理多个独立的数字世界场景
3. **角色扮演系统**：支持创建和管理数字生命体角色，实现深度交互
4. **剧本系统**：支持创建和管理剧本，推进剧情发展
5. **插件系统**：可扩展的插件机制，支持功能扩展
6. **跨平台支持**：支持Web、iOS、Android多平台

### 5.2 技术优势

1. **前后端分离**：清晰的架构设计，便于维护和扩展
2. **模块化设计**：高内聚低耦合，便于功能扩展
3. **安全性**：完善的认证授权机制，保证数据安全
4. **性能优化**：代码分割、懒加载等优化策略
5. **用户体验**：流畅的交互体验，符合UX设计规范

### 5.3 技术难点

1. **AI对话上下文管理**：如何有效管理和维护对话上下文
   - 解决方案：使用对话会话ID关联，维护对话历史记录，构建上下文窗口
   - 技术实现：在数据库中存储对话历史，通过时间戳和会话ID组织对话序列
   - 优化策略：限制上下文长度，使用摘要技术压缩历史对话

2. **多场景数据隔离**：如何实现多场景之间的数据隔离
   - 解决方案：使用场景ID作为数据隔离标识，所有数据操作都关联场景ID
   - 技术实现：在数据库表设计中添加场景ID字段，建立外键关联
   - 权限控制：用户只能访问自己创建的场景或获得授权的场景

3. **跨平台兼容性**：如何保证不同平台的一致性体验
   - 解决方案：使用响应式设计，适配不同屏幕尺寸
   - 技术实现：使用Tailwind CSS的响应式类，PC和Mobile版本UI独立但业务逻辑复用
   - 测试策略：在不同设备和浏览器上进行兼容性测试

4. **性能优化**：如何优化大量数据的加载和渲染性能
   - 解决方案：使用分页加载、懒加载、虚拟滚动等技术
   - 技术实现：React.lazy进行代码分割，虚拟列表组件优化长列表渲染
   - 缓存策略：使用浏览器缓存和CDN加速静态资源加载

### 5.4 技术选型理由

**前端技术选型：**
- React 18+：成熟的组件化框架，生态丰富，性能优秀
- TypeScript：提供类型安全，减少运行时错误，提高代码质量
- Vite：快速的构建工具，提供优秀的开发体验
- Tailwind CSS：实用优先的CSS框架，快速构建美观界面

**后端技术选型：**
- Spring Boot 3.2.0：成熟的Java框架，提供完整的开发工具链
- Spring Data JPA：简化数据库操作，提高开发效率
- Spring Security：提供完善的安全认证和授权机制
- MySQL 8.0+：成熟的关系型数据库，性能稳定可靠

**AI服务集成：**
- 支持多种AI模型：Gemini、OpenAI、Qwen、豆包等
- 统一的AI服务接口，便于切换和扩展
- 支持模型配置和参数调整
- 支持流式响应，提供实时对话体验
