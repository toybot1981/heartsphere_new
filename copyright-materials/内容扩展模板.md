**示例扩展**：
```
#### 2.1.1 对话上下文管理

系统采用创新的对话上下文管理机制，能够有效维护多轮对话的连贯性。上下文管理包括以下关键组件：

1. **对话会话管理**
   - 每个对话会话分配唯一的会话ID
   - 会话ID关联用户ID和角色ID
   - 会话数据存储在MySQL数据库中

2. **对话历史记录**
   - 系统记录所有对话历史
   - 对话历史按时间顺序存储
   - 支持对话历史查询和回放

3. **上下文窗口管理**
   - 系统维护固定长度的上下文窗口
   - 超出窗口长度的历史对话使用摘要技术压缩
   - 上下文窗口长度可配置（默认4096 tokens）

4. **上下文构建**
   - 系统根据会话ID查询对话历史
   - 构建包含角色信息、场景信息的完整上下文
   - 将上下文发送给AI模型生成回复
```

**示例**：
```
[架构图占位符]

说明：
- 客户端层：包含Web前端（React）和移动端（Capacitor）
- 应用层：Spring Boot RESTful API，包含Controller、Service、Repository三层
- 数据层：MySQL数据库存储业务数据，AI服务接口提供AI能力
```

### 流程图

**位置**：功能描述章节

**要求**：
- 展示关键业务流程
- 使用标准流程图符号
- 标注决策点和处理步骤

**示例**：
```
[流程图占位符]
图2.1：AI对话流程图

流程说明：
1. 用户输入对话内容
2. 前端发送请求到后端API
3. 后端构建对话上下文（包含历史对话）
4. 调用AI服务接口（Gemini、OpenAI等）
5. AI服务返回对话结果
6. 后端保存对话历史到数据库
7. 返回对话结果给前端显示
```

## 内容扩展技巧

### 1. 详细化描述

将简要描述扩展为详细描述：
- 添加技术细节
- 添加实现方式
- 添加使用场景
- 添加优势说明

### 2. 添加示例

为每个功能添加使用示例：
- 操作步骤
- 输入输出示例
- 使用场景示例

### 3. 添加对比

添加技术对比和优势说明：
- 与传统方案对比
- 与其他产品对比
- 性能数据对比

### 4. 添加图表

为关键内容添加图表：
- 架构图
- 流程图
- 数据流图
- 功能截图
