# 源代码文档说明

## 要求

根据软件著作权申请要求，源代码文档需要：
- 共60页（前30页+后30页）
- 每页不少于50行代码
- 包含代表性源代码，体现软件核心功能
- 添加必要的代码注释和说明

## 源代码选择原则

### 前30页源代码（主要功能模块）

建议选择以下核心模块的源代码：

1. **前端核心组件**（约10页）
   - 管理页面组件（`admin/frontend/src/pages/`）
   - 用户管理组件
   - 内容审核组件
   - 数据分析组件
   - 教育版管理组件

2. **前端服务层**（约5页）
   - API服务（`admin/frontend/src/services/api/`）
   - 用户管理服务
   - 内容审核服务
   - 数据分析服务

3. **后端核心服务**（约10页）
   - Controller层（`admin/backend/src/main/java/com/heartsphere/admin/.../controller/`）
     - 用户管理Controller
     - 内容审核Controller
     - 数据分析Controller
   - Service层（`admin/backend/src/main/java/com/heartsphere/admin/.../service/`）
     - 用户管理Service
     - 内容审核Service
     - 数据分析Service

4. **后端数据层**（约5页）
   - Repository层
   - Entity层

### 后30页源代码（辅助功能）

建议选择以下辅助功能模块的源代码：

1. **工具类和工具函数**（约10页）
   - 前端工具函数（`admin/frontend/src/utils/`）
   - 后端工具类
   - 公共组件

2. **配置和初始化**（约5页）
   - 前端配置文件（`admin/frontend/vite.config.ts`等）
   - 后端配置类
   - 应用配置文件

3. **权限和安全**（约10页）
   - 权限管理相关代码
   - 安全配置类
   - JWT认证相关代码

4. **数据处理和DTO**（约5页）
   - DTO类
   - 类型定义

## 注意事项

1. **代码格式**：保持代码格式规范，包含必要的注释
2. **敏感信息**：去除敏感信息（API密钥、密码等）
3. **完整性**：确保代码片段完整，能够体现功能逻辑
4. **注释说明**：添加必要的注释，说明代码功能
5. **文件名**：在文档中标注源代码文件名和路径

## 文档格式

源代码文档需要：
1. 使用等宽字体（如Courier New）
2. 保持代码缩进格式
3. 添加代码块说明（功能、文件路径等）
4. 每页不少于50行代码
5. 转换为Word文档格式后，确保格式正确

## 生成步骤

1. 从代码库中选择代表性源代码文件
2. 按照前30页+后30页的要求组织代码
3. 添加必要的代码注释和说明
4. 格式化为Word文档（.docx）
5. 检查每页代码行数（≥50行）
6. 添加页眉页脚和页码
