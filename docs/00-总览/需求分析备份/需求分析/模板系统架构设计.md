# 模板系统架构设计

**基于GraphEngine的可组合、参数化模板系统**

---

## 一、设计理念

### 1.1 核心创新点

1. **模板即配置（Template as Configuration）**
   - 模板不是完整的Graph，而是Graph的"配方"
   - 通过参数化配置生成不同的Graph实例
   - 模板 = Graph结构骨架 + 参数定义 + 默认值

2. **可组合性（Composability）**
   - 小模板可以组合成大模板
   - 模板可以引用其他模板（模板继承）
   - 支持模板的"混搭"（Mix & Match）

3. **渐进式复杂度（Progressive Complexity）**
   - L1用户：选择模板，调整参数
   - L2用户：组合模板，自定义参数
   - L3用户：直接使用Graph编辑器

## 二、系统架构

### 2.1 整体架构

```
用户层
  ↓
模板应用层
  ├─ 模板选择
  ├─ 参数配置
  └─ 预览测试
  ↓
模板引擎层
  ├─ 模板解析
  ├─ 参数绑定
  ├─ 模板组合
  └─ Graph生成
  ↓
GraphEngine（现有）
  ├─ Graph定义
  ├─ 节点执行
  └─ 流程执行
```

### 2.2 模板分层

```
完整模板（Complete Template）
  └─ 完整的角色/场景模板，直接可用
      ↓
组合模板（Composite Template）
  └─ 由多个组件模板组合
      ↓
组件模板（Component Template）
  └─ 流程片段模板（如：对话-选择流程）
      ↓
原子模板（Atomic Template）
  └─ 单个节点模板（可选，用于高级组合）
```

## 三、模板数据结构

### 3.1 模板定义

```
模板 {
  标识信息 {
    id, name, version, type, category
  }
  
  参数定义 {
    [参数列表] {
      参数名, 类型, 默认值, 约束条件, 显示配置
    }
  }
  
  Graph骨架 {
    nodes: [节点模板],
    edges: [边模板],
    references: [引用的其他模板ID]  // 可选的模板组合
  }
  
  元数据 {
    描述, 预览图, 标签, 作者, 创建时间, 统计信息
  }
}
```

### 3.2 节点模板

```
节点模板 {
  nodeType: 节点类型,
  nodeId: 节点ID（可以是参数表达式）,
  config: {
    // 节点配置，其中部分字段可以是参数占位符
    // 例如: "${characterName}" 表示使用参数characterName的值
  }
}
```

### 3.3 参数定义

```
参数 {
  参数名: string,
  类型: enum { STRING, NUMBER, BOOLEAN, ENUM, SLIDER },
  默认值: any,
  约束: {
    最小值, 最大值, 可选值列表, 必填
  },
  显示: {
    标签, 提示, 控件类型, 分组
  },
  影响范围: [受影响的节点ID列表]
}
```

## 四、关键流程

### 4.1 模板使用流程

```
1. 用户选择模板
   ↓
2. 系统展示参数配置界面
   - 根据模板的参数定义生成配置表单
   - 显示参数的默认值
   ↓
3. 用户配置参数（可选）
   - 修改参数值
   - 参数验证（实时或提交时）
   ↓
4. 模板引擎处理
   ├─ 参数绑定：将用户参数值绑定到模板
   ├─ 模板展开：如果模板引用了其他模板，递归展开
   ├─ Graph生成：将模板结构转换为Graph定义
   └─ 验证：验证生成的Graph的有效性
   ↓
5. 保存为用户作品
   - 创建Graph定义
   - 关联到用户账号
```

### 4.2 模板组合流程

```
1. 用户选择基础模板
   ↓
2. 用户选择扩展模板（可选多个）
   ↓
3. 模板兼容性检查
   ├─ 参数冲突检测
   ├─ 节点ID冲突检测
   └─ 依赖关系检查
   ↓
4. 组合规则应用
   ├─ 参数合并（合并参数定义，处理冲突）
   ├─ 结构合并（合并节点和边，处理ID冲突）
   └─ 生成组合模板
   ↓
5. 用户确认并保存/使用
```

### 4.3 模板推荐流程

```
1. 收集用户信息
   - 用户画像（年龄、兴趣、能力等级）
   - 使用历史
   - 当前场景
   ↓
2. 模板匹配
   - 基于分类和标签匹配
   - 基于用户画像匹配
   - 基于使用历史推荐
   ↓
3. 生成推荐列表
   - 个性化推荐
   - 热门推荐
   - 组合推荐
   ↓
4. 用户选择
```

## 五、核心接口设计

### 5.1 模板查询

**获取模板列表**
- 输入：分类、标签、搜索关键词、排序、分页
- 输出：模板列表（含基础信息和统计）
- 功能：浏览、搜索模板

**获取模板详情**
- 输入：模板ID
- 输出：完整模板定义（含参数定义、Graph骨架、元数据）
- 功能：查看模板详细信息

**获取模板预览**
- 输入：模板ID、参数值（可选）
- 输出：预览数据（Graph结构预览、示例对话）
- 功能：预览模板效果

### 5.2 模板使用

**应用模板（核心接口）**
- 输入：模板ID、用户配置的参数值
- 输出：生成的Graph定义ID
- 功能：将模板转换为用户作品

**组合模板**
- 输入：基础模板ID、扩展模板ID列表、组合配置
- 输出：组合后的模板ID（临时或持久化）
- 功能：组合多个模板

**验证参数**
- 输入：模板ID、参数值
- 输出：验证结果、错误信息
- 功能：验证参数是否符合约束

### 5.3 模板推荐

**获取推荐模板**
- 输入：用户ID、场景类型（可选）
- 输出：推荐模板列表（含推荐理由）
- 功能：个性化推荐

**获取模板组合推荐**
- 输入：用户ID、基础模板ID（可选）
- 输出：推荐的模板组合列表
- 功能：推荐可组合的模板

## 六、模板引擎核心机制

### 6.1 参数绑定机制

1. **参数占位符识别**
   - 在Graph骨架中识别参数占位符（如：`${paramName}`）
   - 支持简单表达式（如：`${paramName}_suffix`）

2. **参数值替换**
   - 用用户提供的参数值替换占位符
   - 处理默认值（如果用户未提供参数）

3. **参数验证**
   - 检查参数值是否符合约束
   - 检查必填参数是否已提供

### 6.2 模板组合机制

1. **结构合并**
   - 合并多个模板的节点和边
   - 处理节点ID冲突（自动重命名或用户指定）
   - 处理边的连接（根据组合规则）

2. **参数合并**
   - 合并参数定义
   - 处理参数名冲突
   - 生成组合模板的参数定义

### 6.3 Graph生成机制

1. **模板展开**
   - 如果模板引用了其他模板，递归展开
   - 处理模板的嵌套引用

2. **Graph转换**
   - 将展开后的模板结构转换为Graph定义
   - 生成完整的节点和边配置
   - 调用现有的GraphEngine创建Graph定义

3. **Graph验证**
   - 验证Graph的有效性（节点完整性、边的连接等）
   - 调用GraphEngine的验证机制

## 七、示例场景

### 7.1 简单场景：使用"学习伙伴"模板

```
1. 用户选择"学习伙伴"模板
2. 系统展示参数配置：
   - 角色名称（默认："学习助手"）
   - 性格倾向（滑块：严肃 ↔ 活泼，默认：中等）
   - 知识水平（滑块：0-100，默认：50）
3. 用户调整参数（可选）
4. 系统生成Graph定义
5. 用户保存并使用
```

### 7.2 组合场景：组合"基础对话"和"选择分支"模板

```
1. 用户选择"基础对话"模板作为基础
2. 用户选择"选择分支"模板作为扩展
3. 系统检查兼容性（参数、结构）
4. 系统合并两个模板：
   - 合并参数定义
   - 合并节点和边（自动处理ID冲突）
5. 生成组合模板
6. 用户配置参数并使用
```

## 八、实施优先级

### 8.1 第一阶段（MVP）

- **单模板使用**
  - 模板定义和存储
  - 基础参数类型（STRING, NUMBER, SLIDER）
  - 参数绑定机制
  - 模板到Graph的转换

- **基础模板库**
  - 10-20个系统模板
  - 基础参数配置界面

### 8.2 第二阶段

- **模板组合**
  - 模板组合机制
  - 组合规则和冲突处理
  - 组合模板的预览

- **模板推荐**
  - 基于分类和标签的推荐
  - 基于用户画像的推荐

### 8.3 第三阶段

- **用户模板**
  - 用户创建模板功能
  - 模板审核机制
  - 模板市场

- **高级功能**
  - 复杂参数类型和表达式
  - 模板版本管理
  - 模板分析和优化

---

## 九、设计亮点总结

1. **基于现有GraphEngine**
   - 模板系统是GraphEngine的上层抽象
   - 最终生成标准的Graph定义
   - 充分利用现有能力

2. **参数化设计**
   - 模板通过参数化实现个性化
   - 用户只需调整参数，无需理解Graph结构

3. **可组合性**
   - 支持模板的组合和复用
   - 提高模板的灵活性和复用性

4. **渐进式复杂度**
   - 不同能力的用户使用不同层级的功能
   - 从简单到复杂，平滑过渡
