### 2.1 数据模型设计

#### 任务1.1：相册表设计

**表名：** `photo_albums`

**设计要点：**
- 关联到插件实例（scene_plugins.id）
- 支持用户权限控制（user_id）
- 支持标签和分类
- 支持软删除
- 封面照片管理

**字段设计：**
```sql
CREATE TABLE photo_albums (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    plugin_instance_id BIGINT NOT NULL COMMENT '插件实例ID（关联scene_plugins.id）',
    name VARCHAR(255) NOT NULL COMMENT '相册名称',
    description TEXT COMMENT '相册描述',
    cover_photo_id BIGINT COMMENT '封面照片ID',
    cover_photo_url VARCHAR(500) COMMENT '封面照片URL（冗余字段）',
    photo_count INT DEFAULT 0 COMMENT '照片数量',
    tags JSON COMMENT '标签列表，如：["恋爱", "纪念"]',
    is_public BOOLEAN DEFAULT FALSE COMMENT '是否公开',
    is_deleted BOOLEAN DEFAULT FALSE COMMENT '是否已删除（软删除）',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_user_id (user_id, is_deleted, created_at),
    INDEX idx_plugin_instance_id (plugin_instance_id, is_deleted),
    INDEX idx_tags ((CAST(tags AS CHAR(255) ARRAY))),  -- JSON索引（MySQL 8.0+）
    FOREIGN KEY (plugin_instance_id) REFERENCES scene_plugins(id) ON DELETE CASCADE
) COMMENT '相册表';
```

**设计考虑：**
- `cover_photo_url`作为冗余字段，避免频繁JOIN查询
- `photo_count`作为冗余字段，避免COUNT查询
- JSON索引用于标签搜索（MySQL 8.0+支持）
- 软删除支持数据恢复

#### 任务1.2：照片表设计

**表名：** `photos`

**设计要点：**
- 关联到相册（album_id）
- 支持文件元数据（大小、尺寸、MIME类型）
- 支持拍摄时间和地点
- 支持标签和心情标签
- 支持排序
- 支持软删除

**字段设计：**
```sql
CREATE TABLE photos (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    album_id BIGINT NOT NULL COMMENT '相册ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    title VARCHAR(255) COMMENT '照片标题',
    description TEXT COMMENT '照片描述',
    photo_url VARCHAR(500) NOT NULL COMMENT '照片URL（原始图）',
    thumbnail_url VARCHAR(500) COMMENT '缩略图URL',
    file_name VARCHAR(255) COMMENT '原始文件名',
    file_size BIGINT COMMENT '文件大小（字节）',
    width INT COMMENT '图片宽度（像素）',
    height INT COMMENT '图片高度（像素）',
    mime_type VARCHAR(100) COMMENT 'MIME类型，如：image/jpeg',
    taken_at DATETIME COMMENT '拍摄时间（用户可编辑）',
    location VARCHAR(255) COMMENT '地点信息',
    tags JSON COMMENT '标签列表',
    mood_tags JSON COMMENT '心情标签，如：["快乐", "温馨"]',
    sort_order INT DEFAULT 0 COMMENT '排序顺序',
    is_deleted BOOLEAN DEFAULT FALSE COMMENT '是否已删除（软删除）',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '上传时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_album_id (album_id, sort_order, is_deleted),
    INDEX idx_user_id (user_id, is_deleted, created_at),
    INDEX idx_taken_at (taken_at),
    INDEX idx_tags ((CAST(tags AS CHAR(255) ARRAY))),
    INDEX idx_created_at (created_at),
    FOREIGN KEY (album_id) REFERENCES photo_albums(id) ON DELETE CASCADE
) COMMENT '照片表';
```

**设计考虑：**
- `thumbnail_url`用于快速加载预览
- `taken_at`支持用户编辑，可能与`created_at`不同
- `sort_order`支持自定义排序
- 多个索引优化查询性能

#### 任务1.3：文件存储设计

**存储方案选择：**
- **MinIO对象存储**（推荐）
  - 优点：专业、可扩展、支持CDN
  - 缺点：需要额外部署
- **本地文件系统**（备选）
  - 优点：简单、无需额外服务
  - 缺点：扩展性差、备份困难

**文件路径设计：**
```
MinIO Bucket: photo-albums
路径规则: /{userId}/{albumId}/{photoId}/{filename}
          /{userId}/{albumId}/{photoId}/thumb_{filename}
```

**缩略图策略：**
- 自动生成缩略图（上传时）
- 缩略图尺寸：300x300（保持比例）
- 使用Java图像处理库（Thumbnailator或ImageIO）

**文件命名规则：**
- 原始文件：`{timestamp}_{originalFilename}`
- 缩略图：`thumb_{timestamp}_{originalFilename}`
- 避免文件名冲突

```java
@Entity
@Table(name = "photo_albums")
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class PhotoAlbum {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(name = "user_id", nullable = false)
    private Long userId;
    
    @Column(name = "plugin_instance_id", nullable = false)
    private Long pluginInstanceId;
    
    @Column(name = "name", nullable = false, length = 255)
    private String name;
    
    @Column(name = "description", columnDefinition = "TEXT")
    private String description;
    
    @Column(name = "cover_photo_id")
    private Long coverPhotoId;
    
    @Column(name = "cover_photo_url", length = 500)
    private String coverPhotoUrl;
    
    @Column(name = "photo_count", nullable = false)
    @Builder.Default
    private Integer photoCount = 0;
    
    @Column(name = "tags", columnDefinition = "JSON")
    @Convert(converter = JsonListConverter.class)
    private List<String> tags;
    
    @Column(name = "is_public", nullable = false)
    @Builder.Default
    private Boolean isPublic = false;
    
    @Column(name = "is_deleted", nullable = false)
    @Builder.Default
    private Boolean isDeleted = false;
    
    @CreationTimestamp
    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;
    
    @UpdateTimestamp
    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;
    
    // 关联关系
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "plugin_instance_id", insertable = false, updatable = false)
    private ScenePlugin pluginInstance;
    
    @OneToMany(mappedBy = "album", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Photo> photos;
}
```

**设计要点：**
- 使用Lombok简化代码
- JSON字段使用Converter转换
- 软删除字段
- 时间戳自动管理

## 三、技术细节

### 3.1 JSON字段处理

**方案：**
- 使用自定义Converter将List<String>转换为JSON
- 或使用@Type注解（Hibernate 5.2+）

**JsonListConverter实现：**
```java
@Converter
public class JsonListConverter implements AttributeConverter<List<String>, String> {
    private static final ObjectMapper objectMapper = new ObjectMapper();
    
    @Override
    public String convertToDatabaseColumn(List<String> attribute) {
        try {
            return objectMapper.writeValueAsString(attribute);
        } catch (Exception e) {
            throw new RuntimeException("JSON转换失败", e);
        }
    }
    
    @Override
    public List<String> convertToEntityAttribute(String dbData) {
        try {
            if (dbData == null) {
                return new ArrayList<>();
            }
            return objectMapper.readValue(dbData, 
                objectMapper.getTypeFactory().constructCollectionType(List.class, String.class));
        } catch (Exception e) {
            throw new RuntimeException("JSON解析失败", e);
        }
    }
}
```

## 七、注意事项

1. **JSON字段**
   - MySQL 8.0+支持JSON类型和索引
   - 如果使用较低版本，考虑使用TEXT类型
   - JSON字段的查询性能需要测试

2. **文件存储**
   - 确定使用MinIO还是本地文件系统
   - 考虑文件备份策略
   - 考虑CDN加速（如果使用MinIO）

3. **性能考虑**
   - 照片数量可能很大，需要考虑分页
   - 索引设计要考虑查询场景
   - 冗余字段（photo_count、cover_photo_url）减少查询

4. **数据安全**
   - 用户数据隔离（user_id）
   - 软删除支持数据恢复
   - 文件访问权限控制
