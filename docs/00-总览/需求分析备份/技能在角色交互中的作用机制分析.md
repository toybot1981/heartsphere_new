# 技能在角色交互中的作用机制分析

## 📋 概述

本文档详细分析技能系统如何在角色交互中产生作用，包括前端Function Calling流程、后端技能执行流程，以及完整的交互链路。

## 🔄 完整交互流程

### 1. 用户发送消息

```
用户输入 → ChatWindow.handleSend() → generateAIResponse()
```

### 2. 技能准备阶段

**位置**: `frontend/components/chat/utils/generateAIResponse.ts`

```typescript
// 获取角色可用技能（用于 Function Calling）
if (character.id) {
  try {
    // 1. 获取角色的已装备且启用的技能
    functionDefinitions = await skillService.getCharacterAvailableSkills(character.id);
    
    // 2. 设置 Function Call 回调
    onFunctionCall = async (functionCall: FunctionCall) => {
      // 解析参数
      const parameters = JSON.parse(functionCall.arguments);
      
      // 执行技能
      const result = await skillService.executeSkill(
        functionCall.name,  // 技能ID
        character.id!,
        parameters
      );
      
      // 返回结果给AI继续处理
      return result;
    };
  } catch (error) {
    // 如果获取技能失败，继续正常对话
  }
}
```

### 3. AI调用阶段

**位置**: `frontend/services/ai/adapters/OpenAIAdapter.ts` (或其他适配器)

```typescript
// AI服务调用时传入functionDefinitions和onFunctionCall
await aiService.generateTextStream({
  prompt: userText,
  systemInstruction: systemInstruction,
  messages: historyMessages,
  functionDefinitions: functionDefinitions,  // 技能函数定义
  onFunctionCall: onFunctionCall,           // 技能执行回调
});
```

**AI决策过程**:
1. AI分析用户输入和对话上下文
2. AI判断是否需要调用技能（基于functionDefinitions）
3. 如果需要，AI生成function_call请求
4. 前端捕获function_call，执行`onFunctionCall`回调

### 4. 技能执行阶段

#### 4.1 前端执行 (`SkillService.executeSkill`)

**位置**: `frontend/services/skill/SkillService.ts`

```typescript
async executeSkill(
  skillId: string,
  characterId: number,
  parameters: Record<string, any>,
  token?: string
): Promise<any> {
  // 调用后端API执行技能
  const response = await fetch(
    `${API_BASE_URL}/skills/execute`,
    {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${token}`,
      },
      body: JSON.stringify({
        skillId,
        characterId,
        parameters,
      }),
    }
  );
  
  const result = await response.json();
  return result.data;
}
```

#### 4.2 后端执行 (`SkillExecutor.execute`)

**位置**: `backend/src/main/java/com/heartsphere/skill/service/SkillExecutor.java`

```java
public SkillExecutionResult execute(SkillExecutionContext context) {
    // 1. 获取技能定义
    SkillDefinition skill = skillRegistry.getSkill(context.getSkillId());
    
    // 2. 验证技能（检查是否装备、是否启用、使用限制等）
    validateSkill(skill, context);
    
    // 3. 根据执行类型执行技能
    Object result = executeSkillLogic(skill, context);
    
    // 4. 记录执行日志
    recordExecution(skill, context, result);
    
    // 5. 更新使用统计
    updateUsageStats(context);
    
    return SkillExecutionResult.builder()
        .success(true)
        .result(result)
        .build();
}
```

**执行类型支持**:
- `RULE_BASED`: 基于规则的执行（如CBT技能）
- `SCRIPT`: JavaScript脚本执行
- `API`: 调用外部API
- `GRAPH`: 执行Graph流程
- `DATABASE`: 数据库查询

### 5. 结果返回阶段

```
技能执行结果 → 返回给AI → AI继续生成回复 → 流式输出给用户
```

**位置**: `frontend/services/ai/adapters/OpenAIAdapter.ts`

```typescript
// 执行 function call
const functionResult = await request.onFunctionCall(functionCallBuffer);

// 将 function call 结果添加到消息历史
messages.push({
  role: 'function',
  name: functionCallBuffer.name,
  content: JSON.stringify(functionResult),
});

// 递归调用以继续流式响应（AI基于技能结果继续生成）
await this.processStreamWithFunctionCalls(
  model,
  messages,
  request,
  onChunk,
  depth + 1,
  maxDepth
);
```

## 🎯 关键组件说明

### 1. SkillRegistry (技能注册表)

**位置**: `backend/src/main/java/com/heartsphere/skill/service/SkillRegistry.java`

**职责**:
- 管理所有技能定义
- 获取角色已装备的技能
- 将技能转换为Function Definition（用于AI Function Calling）
- 检查自动触发技能

**关键方法**:
```java
// 获取角色可用技能
List<SkillDefinition> getCharacterSkills(Long characterId);

// 转换为Function Definition
List<FunctionDefinitionDTO> toFunctionDefinitions(List<SkillDefinition> skills);

// 检查自动触发技能
List<SkillDefinition> findAutoTriggerSkills(Long characterId, String userInput);
```

### 2. SkillExecutor (技能执行器)

**位置**: `backend/src/main/java/com/heartsphere/skill/service/SkillExecutor.java`

**职责**:
- 执行技能逻辑
- 验证技能可用性
- 记录执行日志
- 更新使用统计

**执行流程**:
1. 验证技能（装备状态、启用状态、使用限制）
2. 根据执行类型选择执行器
3. 执行技能逻辑
4. 记录执行结果
5. 更新统计信息

### 3. CharacterSkillService (角色技能服务)

**位置**: `backend/src/main/java/com/heartsphere/skill/service/CharacterSkillService.java`

**职责**:
- 管理角色技能装备关系
- 处理技能装备/卸载
- 管理技能启用/禁用状态

## 🔍 技能触发机制

### 1. Function Calling触发（主动触发）

**触发条件**:
- 角色已装备该技能
- 技能已启用
- AI判断需要调用该技能

**流程**:
```
用户输入 → AI分析 → AI决定调用技能 → 执行技能 → AI基于结果生成回复
```

### 2. 自动触发（Auto Trigger）

**触发条件**:
- 角色已装备该技能
- 技能已启用
- 技能设置了`autoTrigger = true`
- 用户输入包含技能的关键词（`autoTriggerKeywords`）

**实现位置**: `backend/src/main/java/com/heartsphere/skill/service/SkillRegistry.java`

```java
public List<SkillDefinition> findAutoTriggerSkills(Long characterId, String userInput) {
    // 获取角色的自动触发技能
    List<CharacterSkillBinding> bindings = getAutoTriggerBindings(characterId);
    
    // 检查用户输入是否包含关键词
    return bindings.stream()
        .filter(binding -> {
            SkillDefinition skill = getSkill(binding.getSkillId());
            return containsKeywords(userInput, skill.getAutoTriggerKeywords());
        })
        .map(binding -> getSkill(binding.getSkillId()))
        .collect(Collectors.toList());
}
```

**使用场景**:
- 在生成AI响应前，检查是否有自动触发技能
- 如果有，可以预先执行或提示AI使用该技能

## 🛠️ 实现细节

### 1. Function Definition格式

技能需要转换为AI可理解的Function Definition格式：

```json
{
  "name": "cbt-cognitive-restructuring",
  "description": "CBT认知重构 - 帮助识别和重构负面思维模式",
  "parameters": {
    "type": "object",
    "properties": {
      "action": {
        "type": "string",
        "enum": ["identify", "evaluate", "restructure", "challenge"],
        "description": "操作类型"
      },
      "patientId": {
        "type": "string",
        "description": "患者ID"
      },
      "situation": {
        "type": "string",
        "description": "触发情境描述"
      }
    },
    "required": ["action"]
  }
}
```

### 2. 技能执行结果格式

技能执行后返回的结果会被AI继续处理：

```json
{
  "success": true,
  "result": {
    "action": "identify",
    "automaticThought": "我完全搞砸了",
    "cognitiveDistortion": "全或无思维",
    "suggestion": "尝试从更平衡的角度看待这个情况..."
  }
}
```

### 3. 消息历史更新

Function Calling会在消息历史中添加两条消息：

```typescript
// 1. Assistant消息（包含function_call）
{
  role: 'assistant',
  content: null,
  function_call: {
    name: 'cbt-cognitive-restructuring',
    arguments: '{"action":"identify","situation":"..."}'
  }
}

// 2. Function消息（包含执行结果）
{
  role: 'function',
  name: 'cbt-cognitive-restructuring',
  content: JSON.stringify(skillResult)
}
```

**AI处理**:
1. AI识别到用户表达负面思维
2. AI决定调用`cbt-cognitive-restructuring`技能

## 🔧 优化建议

### 1. 技能优先级

当前实现中，技能优先级（`priority`字段）用于：
- 多个技能同时匹配时的选择
- 自动触发技能的执行顺序

**建议**: 在Function Calling时，按优先级排序functionDefinitions，让AI优先考虑高优先级技能。

### 2. 技能使用限制

当前支持：
- `maxUsagePerDay`: 每日最大使用次数

**建议**: 
- 添加使用频率限制（防止短时间内重复调用）
- 添加冷却时间机制

### 3. 技能结果缓存

**建议**: 
- 对于相同参数的技能调用，可以缓存结果
- 减少重复计算，提高响应速度

### 4. 技能执行监控

**当前**: 已有`skill_executions`表记录执行历史

**建议**:
- 添加执行性能监控
- 添加错误率统计
- 添加使用趋势分析

## 📝 总结

技能系统通过Function Calling机制无缝集成到角色交互中：

1. **准备阶段**: 获取角色可用技能，转换为Function Definitions
2. **调用阶段**: AI分析用户输入，决定是否调用技能
3. **执行阶段**: 前端调用后端API执行技能逻辑
4. **返回阶段**: 技能结果返回给AI，AI基于结果生成回复

整个流程对用户透明，技能的执行结果自然地融入到对话中，增强了角色的专业能力和交互体验。
