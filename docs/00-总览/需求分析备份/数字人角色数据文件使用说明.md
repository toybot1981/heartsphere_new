## 二、使用方法

### 2.1 SQL文件导入

#### 方法1：使用MySQL命令行
```bash
mysql -h 127.0.0.1 -u root -p123456 heartsphere --default-character-set=utf8mb4 < backend/src/main/resources/db/migration/add_daily_life_assistant_characters.sql
```

#### 方法2：使用数据库管理工具
1. 打开数据库管理工具（如Navicat、DBeaver等）
2. 连接到heartsphere数据库
3. 打开SQL文件：`backend/src/main/resources/db/migration/add_daily_life_assistant_characters.sql`
4. 执行SQL脚本

#### 方法3：通过Spring Boot应用
如果使用Flyway或Liquibase，将SQL文件放在migration目录下，应用启动时会自动执行。

### 2.2 验证导入结果

执行以下SQL查询验证数据：

```sql
-- 查看时代表
SELECT * FROM system_eras WHERE name = '日常生活助手';

-- 查看角色列表
SELECT id, name, role, system_era_id, sort_order 
FROM system_characters 
WHERE system_era_id = (SELECT id FROM system_eras WHERE name = '日常生活助手' LIMIT 1) 
ORDER BY sort_order;

-- 查看角色详情
SELECT * FROM system_characters WHERE name IN ('时小光', '康小健', '学小知', '心小暖', '心小安', '暖小阳');
```

### 2.3 JSON文件使用

JSON文件可以用于：
1. **API导入**: 通过管理后台API导入角色数据
2. **数据参考**: 查看完整的角色数据结构
3. **批量导入**: 编写脚本批量导入多个角色

## 三、数据结构说明

### 3.1 时代表（system_eras）字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| name | VARCHAR(100) | 时代表名称 |
| description | TEXT | 时代表描述 |
| image_url | TEXT | 时代表图片URL |
| is_active | BOOLEAN | 是否激活 |
| sort_order | INT | 排序顺序 |

### 3.2 角色表（system_characters）字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| name | VARCHAR(100) | 角色名称 |
| description | TEXT | 角色描述 |
| bio | TEXT | 角色背景故事 |
| avatar_url | TEXT | 头像URL |
| background_url | TEXT | 背景图片URL |
| tags | TEXT | 标签（逗号分隔） |
| role | VARCHAR(50) | 角色定位 |
| first_message | TEXT | 首条消息 |
| system_instruction | TEXT | 系统指令（角色设定） |
| gender | VARCHAR(20) | 性别 |
| age | INT | 年龄 |
| mbti | VARCHAR(10) | MBTI人格类型 |
| speech_style | TEXT | 说话风格 |
| catchphrases | TEXT | 口头禅（逗号分隔） |
| secrets | TEXT | 角色秘密 |
| motivations | TEXT | 角色动机 |
| relationships | TEXT | 人际关系 |
| system_era_id | BIGINT | 所属时代表ID |
| is_active | BOOLEAN | 是否激活 |
| sort_order | INT | 排序顺序 |

## 五、注意事项

### 5.1 数据导入前
- 确保数据库连接正常
- 确保`system_eras`和`system_characters`表已创建
- 建议先备份数据库

### 5.2 数据导入后
- 检查时代表是否创建成功
- 检查6个角色是否全部插入
- 检查角色数据是否完整
- 可以通过管理后台查看角色列表

### 5.3 图片资源
- 当前使用的都是placeholder URL
- 需要替换为实际的图片URL
- 图片建议尺寸：
  - 头像：400x600px
  - 背景：1080x1920px

### 5.4 后续扩展
- 可以根据需要添加更多角色
- 可以修改现有角色的设定
- 可以通过管理后台进行角色管理

## 六、常见问题

### Q1: 导入失败怎么办？
**A**: 检查以下几点：
1. 数据库连接是否正常
2. 表结构是否正确
3. 字符编码是否为utf8mb4
4. 是否有重复数据（时代表可能已存在）

### Q2: 如何修改角色数据？
**A**: 可以通过以下方式：
1. 直接修改数据库
2. 通过管理后台API修改
3. 重新执行SQL（先删除再插入）

### Q3: 如何添加新角色？
**A**: 参考现有SQL格式，添加新的INSERT语句即可。

### Q4: 角色图片如何设置？
**A**: 
1. 准备角色图片（头像和背景）
2. 上传到服务器或CDN
3. 更新数据库中的`avatar_url`和`background_url`字段
