# 插件机制与相册组件 - 完整设计文档

**目标：打造灵活的插件系统，支持用户动态添加/删除组件（如家庭温馨相册）到现实世界场景中**

---

## 一、整体设计理念

### 1.1 插件系统核心概念

1. **插件即组件（Plugin as Component）**
   - 插件是可独立运行的功能模块
   - 插件可以动态加载和卸载
   - 插件与主系统通过标准接口交互

2. **场景集成（Scene Integration）**
   - 插件可以嵌入到"现实世界"场景中
   - 用户可以在场景中灵活添加/删除插件
   - 插件之间可以相互协作

3. **数据隔离（Data Isolation）**
   - 每个插件有独立的数据存储
   - 插件数据与主系统数据隔离
   - 支持插件数据的导入/导出

### 2.2 后端架构详细设计

#### 2.2.1 插件管理器核心类

**PluginManager（插件管理器）**
- 职责：插件的注册、加载、卸载、生命周期管理
- 核心方法：
  - `registerPlugin(plugin: IPlugin)`: 注册插件
  - `loadPlugin(pluginId: String)`: 加载插件
  - `unloadPlugin(pluginId: String)`: 卸载插件
  - `getPlugin(pluginId: String)`: 获取插件实例
  - `listPlugins()`: 列出所有插件
  - `getActivePlugins()`: 获取活跃插件列表

**PluginRegistry（插件注册表）**
- 职责：管理插件的注册信息
- 核心方法：
  - `register(metadata: PluginMetadata)`: 注册插件元数据
  - `discover()`: 发现可用插件
  - `getMetadata(pluginId: String)`: 获取插件元数据
  - `validatePlugin(plugin: IPlugin)`: 验证插件

**PluginLifecycleManager（生命周期管理器）**
- 职责：管理插件的生命周期
- 核心方法：
  - `initialize(plugin: IPlugin, config: PluginConfig)`: 初始化插件
  - `activate(plugin: IPlugin)`: 激活插件
  - `deactivate(plugin: IPlugin)`: 停用插件
  - `destroy(plugin: IPlugin)`: 销毁插件

**PluginPermissionManager（权限管理器）**
- 职责：管理插件的权限
- 核心方法：
  - `checkPermission(pluginId: String, permission: String)`: 检查权限
  - `grantPermission(pluginId: String, permission: String)`: 授予权限
  - `revokePermission(pluginId: String, permission: String)`: 撤销权限

**PluginEventBus（事件总线）**
- 职责：处理插件间和插件与系统的通信
- 核心方法：
  - `publish(event: PluginEvent)`: 发布事件
  - `subscribe(eventType: String, handler: EventHandler)`: 订阅事件
  - `unsubscribe(eventType: String, handler: EventHandler)`: 取消订阅

### 3.1 插件系统数据模型

#### 3.1.1 插件表（plugins）

```sql
CREATE TABLE plugins (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    plugin_id VARCHAR(100) UNIQUE NOT NULL COMMENT '插件唯一标识',
    name VARCHAR(255) NOT NULL COMMENT '插件名称',
    version VARCHAR(50) NOT NULL COMMENT '插件版本',
    description TEXT COMMENT '插件描述',
    author VARCHAR(255) COMMENT '作者',
    icon_url VARCHAR(500) COMMENT '插件图标URL',
    category VARCHAR(100) COMMENT '插件分类',
    status VARCHAR(20) DEFAULT 'INACTIVE' COMMENT '状态: ACTIVE, INACTIVE, DISABLED',
    permissions JSON COMMENT '所需权限列表',
    dependencies JSON COMMENT '依赖的其他插件ID列表',
    min_system_version VARCHAR(50) COMMENT '最低系统版本要求',
    config_schema JSON COMMENT '配置模式定义',
    is_system_plugin BOOLEAN DEFAULT FALSE COMMENT '是否为系统插件',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_category (category),
    INDEX idx_status (status)
) COMMENT '插件表';
```

#### 3.1.2 用户插件表（user_plugins）

```sql
CREATE TABLE user_plugins (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    plugin_id VARCHAR(100) NOT NULL COMMENT '插件ID',
    status VARCHAR(20) DEFAULT 'INACTIVE' COMMENT '状态: ACTIVE, INACTIVE',

    installed_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '安装时间',

    INDEX idx_user_id (user_id),
    INDEX idx_plugin_id (plugin_id),
    FOREIGN KEY (plugin_id) REFERENCES plugins(plugin_id) ON DELETE CASCADE
```

## 四、API接口详细设计

### 4.1 插件管理API

#### 4.1.1 插件查询

**GET /api/plugins**
- 功能：获取插件列表
- 请求参数：
  - `category` (string, optional): 分类筛选
  - `status` (string, optional): 状态筛选
  - `keyword` (string, optional): 搜索关键词
  - `page` (int, default: 0): 页码
  - `size` (int, default: 20): 每页数量
- 响应数据：
  ```json
  {
    "plugins": [
      {
        "pluginId": "photo-album",
        "name": "家庭温馨相册",
        "version": "1.0.0",
        "description": "记录家庭美好时刻",
        "iconUrl": "...",
        "category": "lifestyle",
        "status": "ACTIVE"
      }
    ],
    "total": 10,
    "page": 0,
    "size": 20
  }
  ```

**GET /api/plugins/{pluginId}**
- 功能：获取插件详情
- 响应数据：完整的插件元数据

#### 4.1.2 用户插件管理

**GET /api/user/plugins**
- 功能：获取用户已安装的插件列表
- 响应数据：用户插件列表（含状态和配置）

**POST /api/user/plugins/{pluginId}/install**
- 功能：安装插件
- 请求参数：
  ```json
  {
    "sceneId": "scene-123", // 可选，如果要在特定场景中安装
    "initialConfig": {} // 初始配置
  }
  ```
- 响应数据：安装结果

**DELETE /api/user/plugins/{pluginId}/uninstall**
- 功能：卸载插件
- 响应数据：卸载结果

**POST /api/user/plugins/{pluginId}/activate**
- 功能：激活插件
- 响应数据：激活结果

**POST /api/user/plugins/{pluginId}/deactivate**
- 功能：停用插件
- 响应数据：停用结果

#### 4.1.3 场景插件管理

**GET /api/scenes/{sceneId}/plugins**
- 功能：获取场景中的插件列表
- 响应数据：场景插件列表（含位置和配置）

**POST /api/scenes/{sceneId}/plugins/{pluginId}/add**
- 功能：添加插件到场景
- 请求参数：
  ```json
  {
    "positionX": 100,
    "positionY": 200,
    "width": 400,
    "height": 300,
    "config": {}
  }
  ```
- 响应数据：插件实例信息

**DELETE /api/scenes/{sceneId}/plugins/{pluginInstanceId}**
- 功能：从场景中删除插件
- 响应数据：删除结果

**PUT /api/scenes/{sceneId}/plugins/{pluginInstanceId}/position**
- 功能：更新插件位置和大小
- 请求参数：
  ```json
  {
    "positionX": 150,
    "positionY": 250,
    "width": 450,
    "height": 350
  }
  ```

**PUT /api/scenes/{sceneId}/plugins/{pluginInstanceId}/config**
- 功能：更新插件配置
- 请求参数：插件配置对象

## 六、插件生命周期详细设计

### 6.1 插件生命周期状态

```
UNINSTALLED → INSTALLED → INITIALIZED → ACTIVATED → DEACTIVATED → DESTROYED
                ↓            ↓            ↓
              UNINSTALL   DEACTIVATE    DESTROY
```

### 6.2 生命周期方法执行顺序

**安装流程：**
1. 用户点击"安装插件"
2. 系统检查插件依赖
3. 系统创建用户插件记录（INSTALLED）
4. 系统调用 `initialize(context, config)`（INITIALIZED）
5. 系统调用 `activate()`（ACTIVATED）
6. 系统调用 `render(container)`
7. 插件UI显示

**卸载流程：**
1. 用户点击"卸载插件"
2. 系统调用 `unmount()`
3. 系统调用 `deactivate()`（DEACTIVATED）
4. 系统调用 `destroy()`（DESTROYED）
5. 系统删除用户插件记录（UNINSTALLED）

### 6.3 错误处理

- **初始化失败**：回滚到INSTALLED状态，记录错误日志
- **激活失败**：保持INITIALIZED状态，提示用户
- **渲染失败**：显示错误UI，允许重试
- **卸载失败**：记录错误，强制清理资源

## 七、安全性设计

### 7.1 权限控制

**插件权限类型：**
- `READ_USER_DATA`: 读取用户数据
- `WRITE_USER_DATA`: 写入用户数据
- `READ_SCENE_DATA`: 读取场景数据
- `WRITE_SCENE_DATA`: 写入场景数据
- `FILE_UPLOAD`: 文件上传
- `NETWORK_ACCESS`: 网络访问
- `SYSTEM_API`: 系统API访问

**权限检查机制：**
- 插件声明所需权限
- 用户安装时授权
- 运行时检查权限
- 权限不足时拒绝操作

### 7.2 数据隔离

**数据隔离策略：**
- 每个插件有独立的数据命名空间
- 插件只能访问自己的数据
- 通过插件管理器访问共享数据
- 数据访问审计日志

### 7.3 输入验证

**验证规则：**
- 所有插件输入都需要验证
- 文件类型和大小限制
- SQL注入防护
- XSS攻击防护
- CSRF防护
