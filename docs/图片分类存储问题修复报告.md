# 图片分类存储问题修复报告

## 问题描述

在资源编辑页面，上传图片时存在传参问题，导致所有图片都被默认存储成了 `general` 分类。

## 问题分析

### 1. 编辑资源时的 category 传递问题

**位置**: `frontend/admin/components/ResourcesManagement.tsx`

**问题**:
- 编辑资源时上传图片，使用的 category 逻辑是：`editingResource?.category || resourceCategory || 'general'`
- 如果 `resourceCategory` 是 `'all'`，会回退到 `'general'`
- 没有正确处理 `resourceCategory === 'all'` 的情况

**修复前**:
```typescript
const category = editingResource?.category || resourceCategory || 'general';
```

**修复后**:
```typescript
const baseCategory = editingResource?.category || 
                     (resourceCategory && resourceCategory !== 'all' ? resourceCategory : null) || 
                     'general';
const category = 'resource_' + baseCategory;
```

### 2. 创建资源与编辑资源的 category 不一致

**问题**:
- 创建资源时（`SystemResourceService.createResource`）使用：`"resource_" + category`
- 编辑资源时直接使用 `category`，没有加 `"resource_"` 前缀
- 导致创建和编辑时图片存储路径不一致

**修复**:
- 编辑资源时也使用 `"resource_" + category` 前缀，与创建资源保持一致

## 修复内容

### 1. 前端修复

**文件**: `frontend/admin/components/ResourcesManagement.tsx`

**修改**:
- 修复编辑资源时上传图片的 category 传递逻辑
- 添加 `resource_` 前缀，与创建资源时的逻辑保持一致
- 正确处理 `resourceCategory === 'all'` 的情况

### 2. 后端逻辑

**文件**: `backend/src/main/java/com/heartsphere/admin/service/SystemResourceService.java`

**当前逻辑**:
- 创建资源时使用 `"resource_" + category` 作为存储路径
- 这是正确的，因为 `system_resources` 表的资源需要与用户资源区分

## 存储路径规则

### 系统资源（system_resources）
- **存储路径**: `uploads/images/resource_{category}/{year}/{month}/{filename}`
- **相对路径**: `resource_{category}/{year}/{month}/{filename}`
- **示例**: `resource_character/2025/01/uuid.png`

### 用户资源
- **存储路径**: `uploads/images/{userId}/{category}/{year}/{month}/{filename}`
- **相对路径**: `{userId}/{category}/{year}/{month}/{filename}`
- **示例**: `70/character/2025/01/uuid.png`

### 其他系统资源（system_characters, system_eras 等）
- **存储路径**: `uploads/images/{category}/{year}/{month}/{filename}`
- **相对路径**: `{category}/{year}/{month}/{filename}`
- **示例**: `character/2025/01/uuid.png`

## 验证方法

1. **创建新资源**:
   - 选择分类（如 `character`）
   - 上传图片
   - 检查图片是否存储到 `resource_character/...` 目录

2. **编辑资源**:
   - 选择一个资源进行编辑
   - 上传新图片
   - 检查图片是否存储到 `resource_{category}/...` 目录（与资源的 category 一致）

3. **检查数据库**:
   - 运行 `analyze_general_images.sql` 查询脚本
   - 检查是否还有使用 `general` 分类的资源
