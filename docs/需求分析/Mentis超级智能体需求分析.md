**文档版本**: v1.0  
**创建日期**: 2025-01-06  
**模块名称**: Mentis（门提斯 / 心知）  
**定位**: HeartSphere完全独立的超级智能体模块

---

## 一、项目概述

### 1.1 定位

Mentis 是 HeartSphere 中的**超级智能体**，是一个完全独立的模块。Mentis 模拟 Manus 的设计理念，是一个**超级个体**，具备 **Computer-Use** 能力，可以在对话过程中操控虚拟机来完成任务。

### 1.2 核心理念

- **自主性**：类似 AutoGPT/AgentGPT 的自主智能体，能够自主规划、决策和执行任务
- **Computer-Use**：具备计算机操控能力，可以执行命令、运行脚本、操作应用程序
- **虚拟机环境**：在隔离的虚拟机环境中执行任务，确保安全性和可控性
- **对话驱动**：用户通过自然语言对话来驱动任务执行，智能体理解意图并转化为具体行动

### 1.3 与其他模块的关系

Mentis 是一个**完全独立的模块**，与 HeartSphere 的其他模块（如角色系统、记忆系统、技能系统）解耦，但可以通过 API 进行交互和协作。

## 二、核心能力需求

### 2.1 对话能力

- **自然语言理解**：理解用户的自然语言指令和需求
- **意图识别**：识别用户想要执行的任务类型
- **上下文理解**：理解对话上下文，支持多轮对话和任务延续
- **主动交互**：在任务执行过程中主动询问、确认、反馈

### 2.2 Computer-Use 能力

- **命令执行**：在虚拟机中执行系统命令（如 Shell、PowerShell）
- **脚本运行**：执行 Python、JavaScript 等脚本
- **应用程序操作**：操作桌面应用程序（GUI 自动化）
- **文件操作**：创建、读取、修改、删除文件
- **网络操作**：发起 HTTP 请求、访问 API、下载资源
- **屏幕交互**：截图、识别屏幕元素、模拟鼠标和键盘操作

### 2.3 虚拟机管理能力

- **虚拟机创建**：按需创建和配置虚拟机实例
- **状态管理**：管理虚拟机的运行状态（启动、暂停、停止、快照）
- **环境隔离**：每个会话使用独立的虚拟机环境，确保任务隔离
- **资源控制**：控制虚拟机的 CPU、内存、磁盘等资源
- **状态持久化**：保存虚拟机快照，支持任务恢复和回溯

### 2.4 任务执行能力

- **任务规划**：将用户需求分解为可执行的任务步骤
- **任务编排**：按照依赖关系编排任务执行顺序
- **执行监控**：实时监控任务执行状态和进度
- **错误处理**：自动识别和处理执行错误，尝试修复和重试
- **结果反馈**：将执行结果以自然语言形式反馈给用户

### 2.5 安全与权限

- **权限控制**：控制虚拟机中的操作权限，防止危险操作
- **沙箱隔离**：虚拟机环境完全隔离，不影响宿主机系统
- **操作审计**：记录所有操作日志，便于审计和回溯
- **资源限制**：限制虚拟机的资源使用，防止资源耗尽

## 三、系统架构概览

### 3.1 分层架构

```
┌─────────────────────────────────────────┐
│        对话接口层 (Chat Interface)        │
│  - REST API / WebSocket                 │
│  - 消息处理与路由                        │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│        智能体核心层 (Agent Core)          │
│  - 对话理解与意图识别                     │
│  - 任务规划与编排                        │
│  - 执行策略决策                          │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│        执行引擎层 (Execution Engine)      │
│  - 命令执行器                            │
│  - 脚本执行器                            │
│  - GUI 自动化执行器                      │
│  - 任务状态管理                          │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│        虚拟机管理层 (VM Manager)          │
│  - 虚拟机生命周期管理                     │
│  - 资源管理与监控                        │
│  - 状态快照与恢复                        │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│        基础设施层 (Infrastructure)        │
│  - 虚拟机平台 (Docker/KVM/云平台)        │
│  - 存储系统                              │
│  - 网络系统                              │
└─────────────────────────────────────────┘
```

### 3.2 核心组件

1. **MentisAgent**：智能体核心，负责对话理解和任务规划
2. **ExecutionEngine**：执行引擎，负责具体任务的执行
3. **VMManager**：虚拟机管理器，负责虚拟机的创建和管理
4. **ComputerUseExecutor**：Computer-Use 能力执行器
5. **TaskPlanner**：任务规划器，负责任务分解和编排
6. **SessionManager**：会话管理器，负责会话生命周期管理

## 四、数据模型概览

### 4.1 核心实体

- **MentisSession**：会话实体，表示一次用户与 Mentis 的完整对话会话
- **MentisTask**：任务实体，表示单个任务的执行记录
- **MentisMessage**：消息实体，表示对话中的消息
- **MentisVmState**：虚拟机状态实体，记录虚拟机状态快照

### 4.2 数据关系

```
MentisSession (会话)
  ├── MentisMessage (消息列表)
  ├── MentisTask (任务列表)
  └── MentisVmState (虚拟机状态列表)
```

## 五、技术选型概述

### 5.1 后端技术栈

- **框架**：Spring Boot 3.x（与现有 HeartSphere 后端保持一致）
- **AI 能力**：Spring AI Alibaba DashScope（复用现有 AI 服务）
- **数据库**：MySQL（会话、任务、消息持久化）
- **缓存**：Redis（会话状态、临时数据缓存）

### 5.2 虚拟机技术

- **容器方案**：Docker（轻量级，适合简单任务）
- **虚拟机方案**：QEMU/KVM（完整虚拟机，适合复杂任务）
- **云平台方案**：支持云虚拟机（阿里云 ECS、腾讯云 CVM 等）

### 5.3 Computer-Use 技术

- **命令行执行**：Java Process API、SSH 客户端
- **脚本执行**：Python Interpreter、Node.js Runtime
- **GUI 自动化**：Selenium、PyAutoGUI、Playwright
- **屏幕交互**：屏幕截图、OCR、鼠标键盘模拟

## 六、关键特性

### 6.1 对话驱动

用户通过自然语言与 Mentis 对话，Mentis 理解意图后自动规划并执行任务。

- **执行日志**：展示任务执行的详细日志

### 6.3 安全隔离

- 每个会话使用独立的虚拟机环境
- 虚拟机完全隔离，不影响宿主机
- 支持资源限制和权限控制

### 6.4 任务恢复

- 支持任务暂停和恢复
- 支持虚拟机快照和回滚
- 支持任务失败后的重试机制

## 八、技术挑战

### 8.1 虚拟机管理

- **资源消耗**：虚拟机资源消耗较大，需要合理的资源调度和管理
- **启动速度**：虚拟机启动速度影响用户体验，需要优化启动流程
- **状态管理**：虚拟机状态管理复杂，需要完善的状态保存和恢复机制

### 8.2 Computer-Use 实现

- **跨平台兼容**：不同操作系统的命令和工具差异，需要统一抽象
- **GUI 自动化**：GUI 自动化的稳定性和准确性是一个挑战
- **错误处理**：任务执行中的错误识别和处理需要完善的机制

### 8.3 任务规划

- **任务分解**：如何将用户需求准确分解为可执行的任务步骤
- **任务编排**：如何处理任务之间的依赖关系和执行顺序
- **动态调整**：任务执行过程中如何根据实际情况动态调整计划
