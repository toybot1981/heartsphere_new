# Mentis 测试话术文档

**日期**：2026-01-13  
**版本**：1.0  
**用途**：用户测试和功能验证

## 一、概述

本文档提供了 Mentis 系统的全面测试话术，特别是针对 **COMPUTER_USE** 场景的对话示例。这些话术可以帮助测试人员验证系统的意图识别、任务分解和执行能力。

---

## 二、测试场景分类

### 2.1 CHAT 类型任务

**特点**：普通对话，不需要执行任务

#### 场景 1：简单问候
```
用户: 你好，请介绍一下自己
预期: AI 应该识别为 CHAT 类型，直接回复介绍信息，不创建任务
```

#### 场景 2：知识问答
```
用户: 什么是人工智能？
预期: AI 应该识别为 CHAT 类型，直接回答，不创建任务
```

#### 场景 3：多轮对话
```
用户: 你好
AI: 你好！我是 Mentis，很高兴为你服务。

用户: 你能做什么？
AI: 我可以帮你执行命令、运行脚本、进行 GUI 自动化操作等。

用户: 那帮我查一下天气
AI: [应该识别为 COMPUTER_USE，创建任务并执行]
```

---

### 2.2 COMMAND 类型任务

**特点**：执行系统命令

#### 场景 1：简单命令
```
用户: 帮我执行 ls -la
预期: 
- 识别为 COMMAND 类型
- 创建任务
- 执行命令
- 返回文件列表
```

#### 场景 2：查看系统信息
```
用户: 执行 uname -a 查看系统信息
预期:
- 识别为 COMMAND 类型
- 执行命令
- 返回系统信息
```

#### 场景 3：文件操作
```
用户: 执行命令创建一个文件 test.txt，内容是 "Hello World"
预期:
- 识别为 COMMAND 类型（或分解为多个 COMMAND 步骤）
- 执行 echo "Hello World" > test.txt
- 验证文件创建成功
```

---

### 2.3 SCRIPT 类型任务

**特点**：执行脚本代码

#### 场景 1：Python 脚本
```
用户: 帮我执行一个Python脚本：print('Hello from Python!')
预期:
- 识别为 SCRIPT 类型
- 创建任务
- 执行 Python 脚本
- 返回输出结果
```

#### 场景 2：计算脚本
```
用户: 执行Python脚本计算1到100的和
预期:
- 识别为 SCRIPT 类型
- 生成 Python 代码
- 执行脚本
- 返回计算结果（5050）
```

#### 场景 3：数据处理脚本
```
用户: 写一个Python脚本，读取一个CSV文件并统计行数
预期:
- 识别为 SCRIPT 类型
- 生成 Python 代码（需要先创建测试 CSV 文件）
- 执行脚本
- 返回统计结果
```

## 三、复合场景测试

### 场景 1：多步骤任务
```
用户: 帮我查一下明天北京的天气，然后告诉我应该穿什么衣服
预期:
- 第一步：COMPUTER_USE - 查询天气
- 第二步：CHAT - 根据天气建议穿衣
- 两个步骤应该顺序执行
```

### 场景 2：上下文相关任务
```
用户: 帮我查一下Python的最新版本
AI: [执行 COMPUTER_USE 任务，返回版本信息]

用户: 那帮我查一下这个版本的发布时间
预期:
- AI 应该记住上下文（Python 版本）
- 识别为 COMPUTER_USE 类型
- 查询该版本的发布时间
```

### 场景 3：错误恢复
```
用户: 帮我查一下明天北京的天气
AI: [执行失败，例如网络错误]

用户: 再试一次
预期:
- AI 应该重新执行 COMPUTER_USE 任务
- 或者提供错误信息和解决方案
```

## 七、常见问题

### Q1: 查询类任务被识别为 CHAT 而不是 COMPUTER_USE

**解决方案**：
- 检查 `LLMIntentRecognizer` 的 prompt
- 检查 `createDefaultResult` 方法的关键词匹配
- 查看后端日志中的意图识别结果

### Q2: COMPUTER_USE 任务没有被分解为多个步骤

**解决方案**：
- 检查 `TaskPlanner` 的实现
- 检查 `TaskDecomposer` 的实现
- 查看后端日志中的任务分解结果

### Q3: GUI 操作没有执行

**解决方案**：
- 检查虚拟机是否创建成功
- 检查浏览器是否安装
- 检查 `ComputerUseExecutor` 的实现
- 查看后端日志中的执行错误

### Q4: 任务执行超时

**解决方案**：
- 检查网络连接
- 检查目标网站是否可访问
- 增加超时时间设置
- 优化任务分解逻辑
