## 一、测试概述

### 1.1 测试目标

本次测试计划针对6个日常生活助手角色（时小光、康小健、学小知、心小暖、心小安、暖小阳）共48个技能进行全面测试，验证：

1. **技能激活能力**：技能是否能被正确激活（通过预设话术或自然对话）
2. **Function Calling机制**：Function Calling是否正确触发和执行
3. **技能执行质量**：技能执行结果是否符合预期
4. **用户体验**：技能在AI回复中的显示是否正确，用户体验是否流畅
5. **系统稳定性**：技能系统是否稳定可靠

### 1.2 测试范围

- **角色范围**：6个日常生活助手角色
- **技能范围**：每个角色8个技能，共48个技能
- **测试类型**：
  - 预设话术测试（使用 `skillPrompts.ts` 中定义的话术）
  - 自然对话测试（使用与技能相关的自然语言描述）
- **测试环境**：开发环境和生产环境（如适用）

### 1.3 测试方法

- **混合测试方法**：
  - 手动测试：验证用户体验和对话质量
  - 自动化测试：提高效率和覆盖率
  - 两者结合：获得更全面的测试结果

## 三、测试用例设计

### 3.1 测试用例结构

每个技能的测试用例包含：

1. **预设话术测试**：
   - 使用 `skillPrompts.ts` 中定义的话术
   - 预期结果：技能应该被激活，Function Calling应该被触发
   - 验证点：
     - 技能名称是否正确显示（"✨ 应用了 {skillName} 技能"）
     - Function Calling是否被触发
     - 技能执行结果是否相关

2. **自然对话测试**：
   - 使用与技能相关的自然语言描述
   - 预期结果：AI应该智能识别用户意图并激活相应技能
   - 验证点：
     - AI是否能正确识别用户意图
     - 技能是否被激活
     - Function Calling是否被触发

### 3.2 测试数据收集指标

每个测试用例需要收集以下数据：

1. **基本信息**：
   - 测试时间戳
   - 角色名称和ID
   - 技能名称和ID
   - 测试类型（预设话术/自然对话）

2. **激活状态**：
   - 激活状态（成功/失败）
   - Function Calling触发情况（是/否）
   - 技能名称显示情况（是/否）

3. **性能指标**：
   - 响应时间（从发送消息到收到回复的时间）
   - 技能执行时间（从Function Calling到返回结果的时间）

4. **质量指标**：
   - 技能执行结果相关性评分（1-5分，人工评估）
   - 技能执行结果完整性评分（1-5分，人工评估）
   - 用户体验评分（1-5分，人工评估）

5. **错误信息**（如失败）：
   - 错误类型（技能未配置、Function Calling未触发、执行错误等）
   - 错误消息
   - 错误日志（如有）

### 3.3 验收标准

1. **技能激活成功率**：
   - 预设话术测试：≥ 95%
   - 自然对话测试：≥ 80%

2. **Function Calling触发率**：
   - 预设话术测试：≥ 95%
   - 自然对话测试：≥ 80%

3. **响应时间**：
   - 平均响应时间：≤ 5秒
   - 最大响应时间：≤ 10秒

4. **技能执行质量**：
   - 相关性评分：≥ 4分（平均）
   - 完整性评分：≥ 4分（平均）
   - 用户体验评分：≥ 4分（平均）

## 四、测试执行流程

### 4.1 准备工作

1. **环境准备**：
   - 确保后端服务正常运行
   - 确保前端应用正常运行
   - 确保数据库连接正常
   - 确保AI服务可用

2. **数据准备**：
   - 确认6个角色的数据存在
   - 确认48个技能的配置完整
   - 准备测试账号（如需要）

3. **工具准备**：
   - 准备测试脚本（如适用）
   - 准备测试数据收集表格
   - 准备测试报告模板

### 4.2 测试执行步骤

1. **按角色顺序执行**：
   - 时小光（8个技能）
   - 康小健（8个技能）
   - 学小知（8个技能）
   - 心小暖（8个技能）
   - 心小安（8个技能）
   - 暖小阳（8个技能）

2. **每个角色内部按技能顺序执行**：
   - 先执行预设话术测试
   - 再执行自然对话测试
   - 记录测试结果

3. **数据收集**：
   - 实时收集测试数据
   - 记录错误信息（如有）
   - 截图保存（如适用）

### 4.3 测试中断和恢复

- **如果测试中断**：
  - 记录中断位置（角色、技能、测试类型）
  - 保存已收集的测试数据
  - 分析中断原因

- **恢复测试**：
  - 从上次中断的位置继续
  - 重新测试上次未完成的用例
