# 修复说明：支持提示词驱动技能

**修复日期**: 2026-01-10  
**问题**: 已装备的技能因为缺少 `function_schema` 而被过滤掉，无法被AI识别和使用

---

## 一、问题背景

### 1.1 function_schema 的作用

`function_schema` 用于 **AI Function Calling**：
- 定义技能输入参数的结构（JSON Schema格式）
- 使AI能够自动识别和调用技能
- 自动提取和传递参数

### 1.2 问题发现

- 管理端显示角色已装备8个技能
- 但前端API返回技能列表为空（`skillsCount: 0`）
- 原因是这些技能缺少 `function_schema`，被后端过滤掉了

### 1.3 设计理念

**`function_schema` 不是必须的！**

系统应该支持两种技能驱动方式：
1. **Function Calling**（有 `function_schema`）：自动调用，参数结构化
2. **提示词驱动**（无 `function_schema`）：AI根据系统指令自然使用

---

## 二、修复方案

### 2.1 后端修改

#### 新增DTO类

**文件**: `backend/src/main/java/com/heartsphere/skill/dto/CharacterAvailableSkillsDTO.java`

```java
public class CharacterAvailableSkillsDTO {
    // Function Calling 技能（有 function_schema）
    private List<FunctionDefinitionDTO> functionCallingSkills;
    
    // 提示词驱动技能（无 function_schema）
    private List<PromptDrivenSkillDTO> promptDrivenSkills;
}
```

#### 新增API端点

**文件**: `backend/src/main/java/com/heartsphere/skill/controller/SkillController.java`

**新增方法**: `getCharacterAllSkills()`
- 路径: `/api/skills/character/{characterId}/all`
- 返回: 包含两类技能的完整信息
- 保持 `/available` 端点向后兼容（只返回Function Calling技能）

**关键逻辑**:
```java
// 分离两类技能
List<FunctionDefinitionDTO> functionCallingSkills = ...; // 有 function_schema 的

List<PromptDrivenSkillDTO> promptDrivenSkills = skills.stream()
    .filter(skill -> skill.getFunctionSchema() == null || skill.getFunctionSchema().isEmpty())
    .map(...) // 提取基本信息
    .collect(...);
```

### 2.2 前端修改

#### 新增服务方法

**文件**: `frontend/services/skill/SkillService.ts`

**新增方法**: `getCharacterAllSkills()`
- 调用新的 `/all` API端点
- 返回包含两类技能的对象
- 如果新API失败，fallback到旧的 `/available` API

#### 修改AI响应生成

**文件**: `frontend/components/chat/utils/generateAIResponse.ts`

**修改点**:
1. 使用 `getCharacterAllSkills()` 替代 `getCharacterAvailableSkills()`
2. 同时获取两类技能：`functionCallingSkills` 和 `promptDrivenSkills`
3. 在系统指令中分别描述两类技能的使用方式

**系统指令示例**:
```text
[可用技能]

【Function Calling 技能】（可通过工具自动调用）：
- time_audit: 时间审计
- task_breakdown: 任务分解

【提示词驱动技能】（通过对话自然使用）：
- 习惯养成追踪：帮助用户建立和追踪日常习惯...
- 拖延症诊断：通过对话诊断用户的拖延类型...

重要提示：
1. Function Calling技能：如果用户需求匹配，立即调用工具
2. 提示词驱动技能：在对话中自然地使用，无需调用工具
```
