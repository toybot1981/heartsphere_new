# 测试执行流程和验收标准

**文档版本**: V1.0  
**创建日期**: 2026-01-09

## 一、测试执行流程

### 1.1 准备工作

#### 1.1.1 环境准备

1. **后端服务**：
   - 确保后端服务正常运行（`http://localhost:8081` 或生产环境）
   - 检查技能API端点可用性
   - 验证Function Calling机制正常

2. **前端应用**：
   - 确保前端应用正常运行（`http://localhost:3000` 或生产环境）
   - 确认AI对话功能正常
   - 验证技能显示功能正常

3. **数据库**：
   - 确认6个角色的数据存在
   - 确认48个技能的配置完整
   - 验证技能绑定关系正确

4. **AI服务**：
   - 确保AI服务可用（Gemini/OpenAI/Qwen等）
   - 验证Function Calling支持
   - 测试基础对话功能

#### 1.1.2 数据准备

1. **角色数据**：
   - 确认6个角色的基本信息（名称、ID、头像等）
   - 记录角色的技能列表

2. **技能数据**：
   - 确认48个技能的配置完整
   - 验证技能ID、名称、描述等字段正确

3. **测试账号**：
   - 准备测试账号（如需要）
   - 验证账号权限正常

#### 1.1.3 工具准备

1. **测试脚本**：
   - 准备测试脚本（如适用）
   - 验证脚本功能正常

2. **数据收集工具**：
   - 准备测试数据收集表格
   - 准备测试记录表

3. **测试报告模板**：
   - 准备测试报告模板
   - 准备统计数据汇总表

### 1.2 测试执行步骤

#### 1.2.1 按角色顺序执行

1. **时小光**（8个技能，16个测试用例）
2. **康小健**（8个技能，16个测试用例）
3. **学小知**（8个技能，16个测试用例）
4. **心小暖**（8个技能，16个测试用例）
5. **心小安**（8个技能，16个测试用例）
6. **暖小阳**（8个技能，16个测试用例）

#### 1.2.2 每个角色内部执行顺序

1. **按技能顺序执行**：
   - 技能1（预设话术测试 → 自然对话测试）
   - 技能2（预设话术测试 → 自然对话测试）
   - ...
   - 技能8（预设话术测试 → 自然对话测试）

2. **每个技能的测试流程**：
   - **步骤1**：发送预设话术/自然对话
   - **步骤2**：观察AI回复
   - **步骤3**：检查技能是否激活（检查"✨ 应用了 {skillName} 技能"显示）
   - **步骤4**：检查Function Calling是否触发（查看控制台日志）
   - **步骤5**：评估技能执行结果质量
   - **步骤6**：记录测试结果（成功/失败、响应时间、评分等）
   - **步骤7**：记录错误信息（如失败）

#### 1.2.3 数据收集

1. **实时收集**：
   - 每完成一个测试用例，立即记录测试数据
   - 记录响应时间
   - 记录错误信息（如有）

2. **数据验证**：
   - 检查数据完整性
   - 检查数据准确性

3. **数据保存**：
   - 保存测试数据到文件（JSON/CSV格式）
   - 定期备份测试数据

### 1.3 测试中断和恢复

#### 1.3.1 测试中断处理

- **记录中断位置**：
  - 角色名称
  - 技能ID和名称
  - 测试类型（预设话术/自然对话）
  - 中断时间

- **保存已收集数据**：
  - 保存当前已完成的测试数据
  - 备份测试数据文件

- **分析中断原因**：
  - 系统故障
  - 网络问题
  - 其他原因

#### 1.3.2 测试恢复

- **从上次中断位置继续**：
  - 读取中断记录
  - 从上次中断的测试用例继续执行

- **验证数据一致性**：
  - 检查已保存的测试数据
  - 确认没有重复测试

## 二、验收标准

### 2.1 技能激活成功率

#### 2.1.1 预设话术测试

- **验收标准**: ≥ 95%
- **计算方法**: (成功激活数 / 总测试用例数) × 100%
- **目标**: 48个预设话术测试用例中，至少45个成功激活

#### 2.1.2 自然对话测试

- **验收标准**: ≥ 80%
- **计算方法**: (成功激活数 / 总测试用例数) × 100%
- **目标**: 48个自然对话测试用例中，至少38个成功激活

### 2.2 Function Calling触发率

#### 2.2.1 预设话术测试

- **验收标准**: ≥ 95%
- **计算方法**: (Function Calling触发数 / 成功激活数) × 100%
- **目标**: 成功激活的技能中，至少95%触发了Function Calling

#### 2.2.2 自然对话测试

- **验收标准**: ≥ 80%
- **计算方法**: (Function Calling触发数 / 成功激活数) × 100%
- **目标**: 成功激活的技能中，至少80%触发了Function Calling

### 2.3 响应时间

#### 2.3.1 平均响应时间

- **验收标准**: ≤ 5秒
- **计算方法**: 所有测试用例的响应时间平均值
- **目标**: 平均响应时间不超过5秒

#### 2.3.2 最大响应时间

- **验收标准**: ≤ 10秒
- **计算方法**: 所有测试用例的响应时间最大值
- **目标**: 单个测试用例的响应时间不超过10秒

### 2.4 技能执行质量

#### 2.4.1 相关性评分

- **验收标准**: ≥ 4分（平均）
- **评分标准**:
  - 5分：完全相关，完美匹配技能功能
  - 4分：高度相关，基本匹配技能功能
  - 3分：一般相关，部分匹配技能功能
  - 2分：低相关性，不太匹配技能功能
  - 1分：不相关，完全不匹配技能功能
- **计算方法**: 所有测试用例的相关性评分平均值

#### 2.4.2 完整性评分

- **验收标准**: ≥ 4分（平均）
- **评分标准**:
  - 5分：非常完整，提供了全面的信息和建议
  - 4分：较完整，提供了主要信息和建议
  - 3分：一般完整，提供了一些信息和建议
  - 2分：不完整，提供的信息和建议较少
  - 1分：非常不完整，几乎没有提供信息和建议
- **计算方法**: 所有测试用例的完整性评分平均值

#### 2.4.3 用户体验评分

- **验收标准**: ≥ 4分（平均）
- **评分标准**:
  - 5分：非常好的用户体验，流畅自然
  - 4分：良好的用户体验，基本流畅
  - 3分：一般的用户体验，偶尔不流畅
  - 2分：较差的用户体验，经常不流畅
  - 1分：非常差的用户体验，完全不流畅
- **计算方法**: 所有测试用例的用户体验评分平均值

### 2.5 技能名称显示

#### 2.5.1 显示正确率

- **验收标准**: ≥ 95%
- **计算方法**: (正确显示的技能名称数 / 成功激活数) × 100%
- **目标**: 成功激活的技能中，至少95%正确显示了技能名称

#### 2.5.2 显示格式

- **验收标准**: "✨ 应用了 {skillName} 技能"
- **格式要求**:
  - 包含✨符号
  - 包含"应用了"文字
  - 包含技能名称
  - 包含"技能"文字
  - 格式正确，样式符合设计规范

### 2.6 错误处理

#### 2.6.1 错误信息记录

- **验收标准**: 所有失败用例都有错误信息记录
- **记录内容**:
  - 错误类型（技能未配置、Function Calling未触发、执行错误等）
  - 错误消息
  - 错误日志（如有）

#### 2.6.2 错误处理质量

- **验收标准**: 错误信息清晰、可追溯
- **质量要求**:
  - 错误信息描述准确
  - 错误信息包含足够的上下文
  - 错误信息可以帮助定位问题

## 三、测试结果判定

### 3.1 测试通过标准

满足以下所有条件，判定为测试通过：

1. **技能激活成功率**：
   - 预设话术测试：≥ 95%
   - 自然对话测试：≥ 80%

2. **Function Calling触发率**：
   - 预设话术测试：≥ 95%
   - 自然对话测试：≥ 80%

3. **响应时间**：
   - 平均响应时间：≤ 5秒
   - 最大响应时间：≤ 10秒

4. **技能执行质量**：
   - 平均相关性评分：≥ 4分
   - 平均完整性评分：≥ 4分
   - 平均用户体验评分：≥ 4分

5. **技能名称显示正确率**：≥ 95%

### 3.2 测试不通过处理

如果测试不通过，需要：

1. **问题分析**：
   - 分析失败原因
   - 分类问题类型
   - 评估问题严重程度

2. **问题修复**：
   - 修复技能配置问题
   - 修复Function Calling问题
   - 修复技能执行问题

3. **重新测试**：
   - 修复后重新执行失败的测试用例
   - 验证问题是否已解决

## 四、测试报告要求

### 4.1 测试报告内容

测试报告必须包含以下内容：

1. **测试概述**：
   - 测试目标
   - 测试范围
   - 测试方法
   - 测试环境

2. **测试执行摘要**：
   - 测试开始时间
   - 测试结束时间
   - 测试总时长
   - 测试用例总数
   - 成功用例数
   - 失败用例数
   - 通过率

3. **详细测试结果**：
   - 每个角色的详细测试结果
   - 每个技能的测试结果
   - 测试数据记录

4. **统计数据**：
   - 技能激活成功率
   - Function Calling触发率
   - 响应时间统计
   - 质量评分统计

5. **问题汇总**：
   - 失败用例清单
   - 问题分类
   - 问题原因分析
   - 问题优先级

6. **改进建议**：
   - 技能配置改进建议
   - Function Calling改进建议
   - 技能执行改进建议
   - 用户体验改进建议

### 4.2 测试报告格式

- **文档格式**: Markdown
- **文档编码**: UTF-8
- **图表格式**: Markdown表格或图片（如有）
