# 图片分类迁移第三步 - 数据库迁移指南

## 目标
更新数据库中的 URL 路径，将 `general` 分类的图片路径迁移到正确的分类。

## 迁移规则

| 表名 | 字段 | 迁移规则 |
|------|------|----------|
| `journal_entries` | `image_url` | `general` → `journal` |
| `characters` | `avatar_url`, `background_url` | `general` → `character` |
| `eras` | `image_url` | `general` → `era` |
| `system_characters` | `avatar_url`, `background_url` | `general` → `character` |
| `system_eras` | `image_url` | `general` → `era` |
| `system_main_stories` | `avatar_url`, `background_url` | `general` → `character` |
| `system_resources` | `url` | 根据 `category` 字段确定 |

## 执行步骤

### 步骤 1: 备份（重要！）

在执行迁移前，必须先备份数据库和文件系统：

```bash
bash backend/scripts/backup_before_migration.sh
```

或者手动备份：
```bash
# 备份数据库
mysqldump -u root -p heartsphere > database_backup_$(date +%Y%m%d_%H%M%S).sql

# 备份文件系统
cp -r backend/uploads/images backups/uploads_images_backup_$(date +%Y%m%d_%H%M%S)
```

### 步骤 2: 执行数据库迁移

#### 方式一：使用脚本自动执行

```bash
bash backend/scripts/execute_migration_step3.sh
```

脚本会：
1. 检查是否已备份
2. 执行迁移 SQL
3. 验证迁移结果
4. 生成日志文件

#### 方式二：使用数据库管理工具

1. 打开数据库管理工具
2. 连接到 `heartsphere` 数据库
3. 执行 SQL 文件：`backend/scripts/migrate_general_images_to_correct_category.sql`
4. 查看执行结果

#### 方式三：使用 MySQL 命令行

```bash
mysql -u root -p heartsphere < backend/scripts/migrate_general_images_to_correct_category.sql
```

### 步骤 3: 验证迁移结果

迁移脚本执行完成后，会自动显示验证结果。如果还有剩余记录，会显示：

```
table_name          | remaining_count
--------------------|----------------
journal_entries     | 0
characters          | 0
...
```

如果 `remaining_count` 都为 0，说明迁移成功。

### 步骤 4: 手动验证（可选）

可以执行以下查询验证：

```sql
-- 检查是否还有使用 general 的URL
SELECT 'journal_entries' as table_name, COUNT(*) as remaining_count
FROM journal_entries
WHERE image_url LIKE '%/general/%'
UNION ALL
SELECT 'characters', COUNT(*)
FROM characters
WHERE avatar_url LIKE '%/general/%' OR background_url LIKE '%/general/%'
-- ... 其他表
```

## 迁移脚本说明

### 迁移逻辑

迁移脚本使用 `REPLACE` 函数替换 URL 路径：
- `REPLACE(url, '/general/', '/journal/')` - 替换路径中的 `/general/` 为 `/journal/`
- `REPLACE(url, 'general/', 'journal/')` - 替换路径开头的 `general/` 为 `journal/`

### 处理的情况

1. **路径中间包含 general**: `some/path/general/2025/12/file.png` → `some/path/journal/2025/12/file.png`
2. **路径开头是 general**: `general/2025/12/file.png` → `journal/2025/12/file.png`
3. **用户资源路径**: `70/general/2025/12/file.png` → `70/character/2025/12/file.png`

### system_resources 特殊处理

`system_resources` 表根据 `category` 字段确定迁移目标：
- 如果 `category = 'character'` 且 URL 包含 `general`，迁移到 `character`
- 如果 `category = 'era'` 且 URL 包含 `general`，迁移到 `era`
- 如果 `category = 'journal'` 且 URL 包含 `general`，迁移到 `journal`

## 注意事项

1. **备份**: 执行前必须备份数据库和文件系统
2. **测试**: 建议先在测试环境执行
3. **验证**: 执行后验证迁移结果
4. **回滚**: 如果出现问题，使用备份恢复

## 回滚方法

如果迁移出现问题，可以使用备份恢复：

```bash
# 恢复数据库
mysql -u root -p heartsphere < backups/migration_YYYYMMDD_HHMMSS/database_backup.sql

# 恢复文件系统
cp -r backups/migration_YYYYMMDD_HHMMSS/uploads_images_backup/* backend/uploads/images/
```
