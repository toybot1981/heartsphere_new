# 用户场景和角色图片修复完成报告

## 问题分析

### 问题描述
用户 ty1 选择的预置场景和预置角色对应的图片没有与系统的配置保持一致。

### 根本原因

1. **场景问题**：
   - 用户场景的图片URL格式：`70/era/2025/12/xxx.png`（包含用户ID前缀）
   - 预置场景的图片URL格式：`era/2025/12/xxx.png`（系统路径，无用户ID）
   - 虽然文件名相同，但路径不同，导致图片无法正确显示

2. **角色问题**：
   - 用户角色的图片URL格式：`70/character/2025/12/xxx.png`（包含用户ID前缀）
   - 预置角色的图片URL格式：`character/2025/12/xxx.png`（系统路径，无用户ID）
   - 路径不一致导致图片无法正确显示

3. **之前脚本的局限性**：
   - 之前的更新脚本只更新了空值或占位符的记录
   - 没有更新已有但路径不一致的图片URL

## 解决方案

### 修复策略
1. **场景修复**：
   - 对于有 `system_era_id` 的场景，直接使用预置场景的图片URL（系统路径）
   - 即使已有图片，也要更新为预置场景的图片URL，确保路径一致

2. **角色修复**：
   - 对于匹配到预置角色的角色，使用预置角色的图片URL（系统路径）
   - 分别更新 `avatar_url` 和 `background_url`
   - 确保路径与预置角色完全一致

### 修复脚本
`backend/scripts/fix_user_era_character_images_to_match_system.sql`

## 技术细节

### 字符集处理
- 使用 `COLLATE utf8mb4_unicode_ci` 确保字符串比较时字符集一致
- 避免字符集排序规则不匹配导致的错误

### 更新逻辑
1. **场景更新**：
   ```sql
   UPDATE eras e
   INNER JOIN system_eras se ON e.system_era_id = se.id
   SET e.image_url = se.image_url
   WHERE se.image_url IS NOT NULL 
     AND se.image_url != ''
     AND se.image_url NOT LIKE 'placeholder://%'
     AND (e.image_url IS NULL 
          OR e.image_url = ''
          OR e.image_url LIKE 'placeholder://%'
          OR e.image_url != se.image_url);
   ```

2. **角色更新**：
   - 通过名称匹配预置角色
   - 分别更新头像和背景
   - 确保路径与预置角色完全一致
