# 系统资源上传逻辑修复完成报告

## 问题描述

后台管理中的系统资源图片URL包含了userId（如 `90/general/2026/01/41528b65-1b74-433b-845d-c3b5e8a2fadb.png`），但系统资源不应该包含userId，应该是 `general/2026/01/41528b65-1b74-433b-845d-c3b5e8a2fadb.png`。

## 问题原因

1. **前端问题**：在 `ResourcesManagement.tsx` 中，编辑资源时上传图片使用了 `uploadImage(file, 'general')`，这个函数调用 `/api/images/upload` 接口
2. **后端问题**：`ImageController.uploadImage()` 接口会获取当前用户ID并保存为用户资源（包含userId），没有区分系统资源和用户资源

## 修复方案

### 1. 后端修复

**文件**: `backend/src/main/java/com/heartsphere/controller/ImageController.java`

**修改**:
- `uploadImage()` 方法：添加 `isSystemResource` 参数，如果为 `true`，则不包含userId
- `uploadBase64Image()` 方法：添加 `isSystemResource` 参数支持

**代码变更**:
```java
@PostMapping("/upload")
public ResponseEntity<Map<String, Object>> uploadImage(
        @RequestParam("file") MultipartFile file,
        @RequestParam(value = "category", defaultValue = "general") String category,
        @RequestParam(value = "isSystemResource", defaultValue = "false") Boolean isSystemResource) {
    // ...
    if (isSystemResource != null && isSystemResource) {
        // 系统资源：不包含userId
        relativePath = imageStorageService.saveImage(file, category, null);
    } else {
        // 用户资源：包含userId
        String userId = getCurrentUserId();
        relativePath = imageStorageService.saveImage(file, category, userId);
    }
    // ...
}
```

### 2. 前端修复

**文件**: `frontend/services/api/image/image.ts`

**修改**:
- `uploadImage()` 方法：添加 `isSystemResource` 参数

**代码变更**:
```typescript
uploadImage: (
  file: File,
  category: string = 'general',
  token?: string,
  isSystemResource: boolean = false
): Promise<ImageUploadResponse> => {
  const formData = new FormData();
  formData.append('file', file);
  formData.append('category', category);
  if (isSystemResource) {
    formData.append('isSystemResource', 'true');
  }
  // ...
}
```

**文件**: `frontend/admin/components/ResourcesManagement.tsx`

**修改**:
- 编辑资源时上传图片，使用 `imageApi.uploadImage(file, 'general', adminToken, true)`，传入 `isSystemResource=true`
- 移除对 `useImageUpload` hook 的依赖（因为需要直接调用 `imageApi` 并传入 `isSystemResource` 参数）

**代码变更**:
```typescript
// 系统资源上传，不包含userId
const url = await imageApi.uploadImage(file, 'general', adminToken, true);
```

**文件**: `frontend/admin/hooks/useImageUpload.ts`

**修改**:
- `uploadImage()` 方法：添加 `isSystemResource` 参数支持

## 修复结果

- ✅ 系统资源上传不再包含userId
- ✅ 用户资源上传仍然包含userId（保持向后兼容）
- ✅ 管理端编辑资源时上传图片，自动使用系统资源模式

## 验证方法

1. **创建系统资源**：
   - 通过管理端创建新资源，检查URL格式应为 `category/year/month/filename`（不包含userId）

2. **编辑系统资源**：
   - 编辑现有资源并上传新图片，检查URL格式应为 `category/year/month/filename`（不包含userId）

3. **用户资源上传**：
   - 通过用户端上传图片，检查URL格式应为 `userId/category/year/month/filename`（包含userId）

## 注意事项

1. **向后兼容**：`isSystemResource` 参数默认为 `false`，保持向后兼容
2. **数据库迁移**：已有的包含userId的系统资源URL需要迁移（参考之前的修复脚本）
3. **前端调用**：管理端上传系统资源时，必须传入 `isSystemResource=true`
