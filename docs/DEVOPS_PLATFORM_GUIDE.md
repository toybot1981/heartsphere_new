# DevOps 平台使用指南

## 概述

本 DevOps 平台提供了完整的 CI/CD 流程管理、CMDB 资产管理、代码质量检测、自动化测试和自动修复功能。

## 功能模块

### 1. CMDB (配置管理数据库)

CMDB 用于管理 IT 资产及其关系。

#### 主要功能
- 资产管理：服务器、数据库、应用、服务、依赖、配置项
- 关系管理：资产之间的依赖和关联关系
- 历史记录：资产变更历史追踪
- 审计日志：所有操作的审计记录
- 自动发现：自动发现和注册资产
- 监控：资产健康状态监控

#### 使用方式
1. 进入 DevOps 工作台 -> CMDB 管理
2. 创建资产类型（如：服务器、应用）
3. 添加资产并配置属性
4. 建立资产之间的关系
5. 查看资产历史和审计日志

### 2. 部署流程管理

部署流程管理提供完整的 CI/CD 流程定义和执行。

#### 主要功能
- 流程模板：定义可重用的部署流程
- 流程执行：执行部署流程并实时查看进度
- 步骤管理：配置流程步骤（代码扫描、测试、构建、部署）
- 环境变量：管理不同环境的配置
- 远程服务器：配置和管理远程部署目标
- 执行历史：查看历史执行记录

#### 使用方式
1. 进入 DevOps 工作台 -> 部署流程
2. 创建流程模板，配置步骤
3. 配置环境变量和远程服务器
4. 执行流程并查看实时日志
5. 查看执行历史和结果

### 3. 代码扫描和质量门禁

自动进行代码扫描和质量检查。

#### 支持的扫描工具
- ESLint (前端)
- Checkstyle (后端)
- SonarQube (全栈)

#### 质量门禁规则
- 代码扫描分数阈值：80.0
- 严重问题数：0
- 测试通过率：100%
- 测试覆盖率：80%

#### 使用方式
1. 在部署流程中添加代码扫描步骤
2. 配置扫描工具和规则
3. 执行流程，自动进行扫描
4. 查看扫描结果和质量门禁状态

### 4. 自动化测试

支持多种类型的自动化测试。

#### 测试类型
- 单元测试 (Unit Tests)
- 集成测试 (Integration Tests)
- 端到端测试 (E2E Tests)
- 性能测试 (Performance Tests)
- 安全测试 (Security Tests)

#### 使用方式
1. 在部署流程中添加测试步骤
2. 配置测试框架和参数
3. 执行流程，自动运行测试
4. 查看测试结果和覆盖率

### 5. 自动修复引擎

自动检测和修复常见问题。

#### 支持的问题类型
- 代码质量问题（格式化、未使用的导入/变量、语法错误）
- 测试失败（断言、路径、数据、环境）
- 配置问题（环境变量、配置文件、依赖版本、构建配置）

#### 修复流程
1. 问题检测：自动检测流程执行中的问题
2. 修复提议：生成修复方案
3. 审批流程：
   - 低风险问题：自动应用
   - 高风险问题：需要手动审批
4. 修复应用：执行修复操作
5. 修复验证：重新运行测试验证修复效果
6. 回滚：如需要可回滚修复

#### 使用方式
1. 流程执行失败时，系统自动检测问题
2. 查看检测到的问题和修复方案
3. 对于高风险问题，进行审批
4. 系统自动应用修复并验证
5. 查看修复结果和历史

## 测试项目

平台提供了测试项目 (`test-project/`) 用于验证 DevOps 功能。

### 项目结构
```
test-project/
├── frontend/      # React + TypeScript 前端
├── backend/       # Spring Boot 后端
├── scripts/       # 构建和测试脚本
├── test-data/     # 测试数据
└── test-env/      # 环境配置
```

### 使用测试项目
1. 在 DevOps 工作台创建部署流程
2. 配置流程步骤：
   - 代码扫描（ESLint/Checkstyle）
   - 单元测试
   - 构建
   - 部署
3. 执行流程，验证全流程功能

## API 文档

### CMDB API
- `GET /api/cmdb/assets` - 获取资产列表
- `POST /api/cmdb/assets` - 创建资产
- `GET /api/cmdb/assets/{id}` - 获取资产详情
- `PUT /api/cmdb/assets/{id}` - 更新资产
- `DELETE /api/cmdb/assets/{id}` - 删除资产
- `GET /api/cmdb/assets/{id}/relationships` - 获取资产关系
- `GET /api/cmdb/assets/{id}/history` - 获取资产历史

### 部署流程 API
- `GET /api/devops/pipelines` - 获取流程列表
- `POST /api/devops/pipelines` - 创建流程
- `POST /api/devops/pipelines/execute` - 执行流程
- `GET /api/devops/pipelines/executions/{id}` - 获取执行状态
- `GET /api/devops/pipelines/executions/{id}/detail` - 获取执行详情

### 自动修复 API
- `POST /api/devops/auto-fix/detect-and-fix/{executionId}` - 检测并修复
- `GET /api/devops/auto-fix/records` - 获取修复记录
- `POST /api/devops/auto-fix/records/{id}/approve` - 批准修复
- `POST /api/devops/auto-fix/records/{id}/reject` - 拒绝修复
- `POST /api/devops/auto-fix/records/{id}/verify` - 验证修复
- `POST /api/devops/auto-fix/records/{id}/rollback` - 回滚修复

## 最佳实践

### 1. 流程设计
- 将流程步骤按顺序组织
- 使用并行步骤提高效率
- 配置适当的依赖关系
- 设置必需步骤和可选步骤

### 2. 环境管理
- 为不同环境配置独立的环境变量
- 使用环境变量模板提高复用性
- 保护敏感信息（密码、密钥）

### 3. 质量门禁
- 设置合理的质量门禁阈值
- 定期审查质量指标
- 根据项目需求调整规则

### 4. 自动修复
- 定期审查自动修复记录
- 对于高风险修复，确保审批流程
- 验证修复效果后再部署

### 5. CMDB 管理
- 及时更新资产信息
- 建立完整的资产关系图
- 记录所有变更历史

## 故障排查

### 流程执行失败
1. 查看执行详情和日志
2. 检查步骤执行状态
3. 查看错误信息
4. 使用自动修复功能（如适用）

### 代码扫描失败
1. 检查扫描工具配置
2. 查看扫描结果详情
3. 修复代码质量问题
4. 重新执行扫描

### 测试失败
1. 查看测试结果详情
2. 检查测试环境配置
3. 修复测试用例
4. 使用自动修复功能（如适用）

### 部署失败
1. 检查远程服务器连接
2. 验证环境变量配置
3. 查看部署日志
4. 检查目标环境状态
