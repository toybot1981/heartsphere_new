# 图片分类迁移第四步 - 文件系统迁移指南

## 目标
将文件系统中的图片文件从 `general` 目录移动到正确的分类目录。

## 前提条件

✅ **已完成**：
- 第一步：文件系统分析
- 第二步：数据库查询
- 第三步：数据库迁移（URL 已更新）

## 迁移策略

由于数据库中的 URL 已经更新，文件系统迁移需要根据以下策略：

### 系统资源（general 目录）

**默认策略**：迁移到 `character` 目录
- 大部分系统资源是角色相关的图片
- 如果文件应该在其他分类，需要手动调整

**迁移路径**：
- `uploads/images/general/2025/12/file.png` → `uploads/images/character/2025/12/file.png`

### 用户资源（{userId}/general 目录）

**默认策略**：迁移到 `{userId}/character` 目录
- 用户资源通常是角色相关的图片

**迁移路径**：
- `uploads/images/70/general/2025/12/file.png` → `uploads/images/70/character/2025/12/file.png`

## 执行方式

### 方式一：使用智能迁移脚本（推荐）

```bash
bash backend/scripts/migrate_general_images_files_smart.sh
```

脚本会：
1. 统计需要迁移的文件
2. 询问确认
3. 执行迁移
4. 验证结果

### 方式二：手动迁移

如果需要更精确的控制，可以手动迁移：

```bash
# 1. 查看需要迁移的文件
find backend/uploads/images/general -type f

# 2. 创建目标目录
mkdir -p backend/uploads/images/character/2025/12

# 3. 移动文件
mv backend/uploads/images/general/2025/12/file.png backend/uploads/images/character/2025/12/

# 4. 删除空目录
find backend/uploads/images/general -type d -empty -delete
```

## 注意事项

1. **备份已完成**：第三步已自动备份文件系统
2. **默认策略**：脚本使用默认策略（迁移到 character），如果需要其他分类，需要手动调整
3. **验证**：迁移后需要验证文件是否在正确的位置

## 验证方法

### 1. 检查文件是否已迁移

```bash
# 检查 general 目录是否还有文件
find backend/uploads/images/general -type f | wc -l

# 应该返回 0

# 检查目标目录是否有文件
find backend/uploads/images/character -type f | wc -l
```

### 2. 验证数据库 URL 和文件系统是否匹配

可以执行以下查询验证：

```sql
-- 检查数据库中的 URL 是否能在文件系统中找到对应的文件
SELECT url FROM system_resources WHERE url LIKE 'character/%' LIMIT 10;
```

然后检查文件系统中是否存在对应的文件。

## 回滚方法

如果迁移出现问题，可以使用备份恢复：

```bash
# 恢复文件系统
cp -r backups/migration_YYYYMMDD_HHMMSS/uploads_images_backup/* backend/uploads/images/
```
