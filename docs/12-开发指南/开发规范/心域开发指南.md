## 一、项目概述

### 1.1 项目简介

心域（HeartSphere）是一个数字生命体交互系统，提供AI对话、场景管理、角色扮演、剧本系统等核心功能。系统采用前后端分离架构，支持Web、移动端（Capacitor）等多平台。

### 1.2 技术栈

#### 后端技术栈
- **框架**: Spring Boot 3.2.0
- **语言**: Java 17
- **ORM**: Spring Data JPA
- **数据库**: MySQL 8.0+
- **安全**: Spring Security + JWT
- **数据库迁移**: Flyway
- **构建工具**: Maven 3.9+
- **API文档**: SpringDoc OpenAPI (Swagger)

#### 前端技术栈
- **框架**: React 18+ + TypeScript
- **构建工具**: Vite
- **UI库**: Tailwind CSS
- **状态管理**: React Hooks / Context API
- **路由**: React Router
- **HTTP客户端**: Fetch API / Axios
- **移动端**: Capacitor 8.0+

#### AI服务
- **大模型**: Gemini、OpenAI、Qwen、豆包等
- **AI服务**: 自研AI服务 + AipexBase集成
- **代码生成**: AI代码生成服务

## 三、设计规范

### 3.1 架构设计原则

1. **前后端分离**: 标准RESTful API，前后端独立开发部署
2. **模块化设计**: 功能模块化，低耦合高内聚
3. **可扩展性**: 支持功能扩展和性能扩展
4. **安全性**: 数据安全、接口安全、权限控制
5. **可维护性**: 代码清晰、文档完善、易于理解

### 3.2 数据库设计规范

#### 3.2.1 命名规范
- **表名**: 小写字母+下划线，复数形式（如：`user_profiles`）
- **字段名**: 小写字母+下划线（如：`created_at`）
- **主键**: 统一使用 `id`，类型为 `BIGINT`
- **外键**: `{表名}_id`（如：`user_id`）

#### 3.2.2 字段规范
- **时间字段**: 
  - `created_at`: 创建时间（TIMESTAMP，NOT NULL，DEFAULT CURRENT_TIMESTAMP）
  - `updated_at`: 更新时间（TIMESTAMP，NOT NULL，DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP）
- **软删除**: 使用 `deleted_at` 字段（TIMESTAMP，NULL）
- **状态字段**: 使用枚举类型或TINYINT
- **文本字段**: 根据实际需求选择VARCHAR长度，避免过长

#### 3.2.3 索引规范
- **主键索引**: 自动创建
- **外键索引**: 所有外键字段必须创建索引
- **查询字段索引**: 频繁查询的字段创建索引
- **组合索引**: 多字段查询创建组合索引

#### 3.2.4 数据库迁移
- **使用Flyway**: 所有数据库变更通过Flyway迁移脚本
- **命名规范**: `V{版本号}__{描述}.sql`（如：`V1__Create_User_Table.sql`）
- **版本号**: 递增整数，不跳跃
- **回滚脚本**: 重要变更提供回滚脚本

### 3.3 API设计规范

#### 3.3.1 RESTful API规范
- **URL命名**: 小写字母+连字符（如：`/api/user-profiles`）
- **HTTP方法**: 
  - GET: 查询
  - POST: 创建
  - PUT: 完整更新
  - PATCH: 部分更新
  - DELETE: 删除
- **版本控制**: URL中包含版本号（如：`/api/v1/user-profiles`）

#### 3.3.2 请求规范
- **Content-Type**: `application/json`
- **认证**: 使用Bearer Token（`Authorization: Bearer {token}`）
- **请求体**: JSON格式，字段命名使用camelCase

#### 3.3.3 响应规范
- **统一响应格式**:
```json
{
  "code": 200,
  "message": "成功",
  "data": { /* 数据 */ },
  "timestamp": "2025-01-04T10:00:00"
}
```

- **状态码规范**:
  - `200 OK`: 成功
  - `201 Created`: 创建成功
  - `400 Bad Request`: 请求错误
  - `401 Unauthorized`: 未授权
  - `403 Forbidden`: 禁止访问
  - `404 Not Found`: 资源不存在
  - `500 Internal Server Error`: 服务器错误

#### 3.3.4 分页规范
- **请求参数**: `page`（页码，从1开始）、`size`（每页数量，默认10）
- **响应格式**:

    "totalElements": 100,
    "totalPages": 10,
    "page": 1,

#### 3.3.5 CORS配置规范

**统一原则**: 所有CORS配置统一在 `WebSecurityConfig` 中管理，Controller层不单独配置CORS。

##### 3.3.5.1 全局CORS配置

**配置位置**: `backend/src/main/java/com/heartsphere/config/WebSecurityConfig.java`

**标准配置**:
```java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    CorsConfiguration config = new CorsConfiguration();
    
    // 允许所有来源（使用模式匹配，支持凭证）
    config.addAllowedOriginPattern("*");
    
    // 允许所有HTTP方法
    config.addAllowedMethod("*");
    
    // 当使用 setAllowCredentials(true) 时，不能使用通配符，必须明确列出所有请求头
    // 标准请求头
    config.addAllowedHeader("Origin");
    config.addAllowedHeader("Content-Type");
    config.addAllowedHeader("Accept");
    config.addAllowedHeader("Authorization");
    config.addAllowedHeader("X-Requested-With");
    config.addAllowedHeader("Cache-Control");
    config.addAllowedHeader("Pragma");
    
    // 自定义请求头（根据项目需要添加）
    // config.addAllowedHeader("X-Custom-Header");
    
    // 允许携带凭证（Cookie、Authorization等）
    config.setAllowCredentials(true);
    
    // 预检请求的缓存时间（秒）
    config.setMaxAge(3600L);
    
    // 应用到所有路径
    source.registerCorsConfiguration("/**", config);
    
    return source;
}
```

##### 3.3.5.2 Controller层CORS配置规范

**禁止使用**: Controller层**禁止**使用 `@CrossOrigin` 注解

**原因**:
1. Controller层的 `@CrossOrigin` 注解会**覆盖**全局配置
2. 容易导致配置不一致
3. 难以统一管理和维护

**正确做法**:
```java
// ❌ 错误：不要在Controller上使用@CrossOrigin
@RestController
@RequestMapping("/api/user-profiles")
@CrossOrigin(origins = "*")  // 禁止使用
public class UserProfileController {
    // ...
}

// ✅ 正确：只使用全局CORS配置
@RestController
@RequestMapping("/api/user-profiles")
public class UserProfileController {
    // ...
}
```

##### 3.3.5.3 特殊场景处理

**场景1：需要添加自定义请求头**

如果某个功能需要使用自定义请求头（如 `X-Share-Config-Id`、`X-Shared-Mode`），应在全局CORS配置中添加：

```java
// 在 WebSecurityConfig.corsConfigurationSource() 中添加
config.addAllowedHeader("X-Share-Config-Id");
config.addAllowedHeader("X-Shared-Mode");
```

**场景2：需要限制特定来源**

生产环境应限制允许的来源：

```java
// 开发环境：允许所有来源
if (isDevelopment()) {
    config.addAllowedOriginPattern("*");
} else {
    // 生产环境：明确指定允许的来源
    config.addAllowedOrigin("https://yourdomain.com");
    config.addAllowedOrigin("https://www.yourdomain.com");
}
```

**场景3：需要暴露响应头**

如果前端需要访问自定义响应头，需要明确暴露：

```java
config.addExposedHeader("X-Custom-Header");
config.addExposedHeader("X-Total-Count");
```

##### 3.3.5.4 环境配置

**开发环境**:
- 允许所有来源（`addAllowedOriginPattern("*")`）
- 允许所有HTTP方法
- 允许所有标准请求头

**生产环境**:
- 明确指定允许的来源（不使用通配符）
- 只允许必要的HTTP方法
- 只允许必要的请求头
- 使用环境变量配置允许的来源列表

**配置示例**:
```java
@Value("${app.cors.allowed-origins:}")
private String allowedOrigins;

@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    
    if (StringUtils.hasText(allowedOrigins)) {
        // 生产环境：从配置读取允许的来源
        Arrays.stream(allowedOrigins.split(","))
            .forEach(config::addAllowedOrigin);
    } else {
        // 开发环境：允许所有来源
        config.addAllowedOriginPattern("*");
    }
    
    // ... 其他配置
}
```

**application.yml配置**:
```yaml
app:
  cors:
    # 生产环境配置（逗号分隔）
    allowed-origins: https://yourdomain.com,https://www.yourdomain.com
```

##### 3.3.5.5 CORS配置检查清单

创建新Controller时，检查以下项目：

- [ ] Controller上**没有**使用 `@CrossOrigin` 注解
- [ ] 如果使用自定义请求头，已在全局CORS配置中添加
- [ ] 如果使用自定义响应头，已在全局CORS配置中暴露
- [ ] 生产环境已配置允许的来源列表

##### 3.3.5.6 常见问题

**问题1**: Controller使用 `@CrossOrigin(origins = "*")` 但前端仍报CORS错误

**原因**: `@CrossOrigin` 注解没有指定 `allowedHeaders`，导致自定义请求头被拒绝

**解决**: 移除Controller上的 `@CrossOrigin` 注解，使用全局配置

**问题2**: 使用 `addAllowedOrigin("*")` 和 `setAllowCredentials(true)` 同时报错

**原因**: 当 `allowCredentials` 为 `true` 时，不能使用 `addAllowedOrigin("*")`

**解决**: 使用 `addAllowedOriginPattern("*")` 替代 `addAllowedOrigin("*")`

**问题3**: 预检请求（OPTIONS）返回405错误

**原因**: Spring Security没有允许OPTIONS请求

**解决**: 在 `SecurityFilterChain` 中允许OPTIONS请求：
```java
.requestMatchers(request -> "OPTIONS".equals(request.getMethod())).permitAll()
```

      setError(null);
    } catch (err) {

## 十、常见问题与解决方案

### 9.1 开发环境问题

#### 问题1: Maven构建慢
**解决方案**:
- 配置Maven镜像（使用阿里云镜像）
- 使用多线程构建（`-T 4`）
- 优化pom.xml依赖

#### 问题2: 前端依赖安装失败
**解决方案**:
- 使用npm镜像（`npm config set registry`）
- 清除缓存重新安装（`npm cache clean --force`）
- 使用yarn替代npm

### 9.2 数据库问题

#### 问题1: 数据库连接失败
**解决方案**:
- 检查数据库服务是否启动
- 检查连接配置是否正确
- 检查防火墙设置

#### 问题2: 迁移脚本执行失败
**解决方案**:
- 检查SQL语法是否正确
- 检查版本号是否冲突
- 查看Flyway日志

### 9.3 部署问题

#### 问题1: 服务启动失败
**解决方案**:
- 检查日志文件
- 检查环境变量配置
- 检查端口是否被占用

#### 问题2: 前端页面空白
**解决方案**:
- 检查构建是否成功
- 检查Nginx配置
- 检查浏览器控制台错误
