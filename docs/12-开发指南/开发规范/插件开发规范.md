## 一、插件开发概述

### 1.1 什么是插件？

插件是心域系统中可独立运行的功能模块，可以动态加载和卸载。插件可以嵌入到"现实世界"场景中，为用户提供丰富的功能扩展。

### 1.2 插件的特点

- **独立性**：插件是独立的功能模块，可以单独开发和测试
- **可扩展性**：通过插件机制，系统功能可以无限扩展
- **灵活性**：用户可以灵活添加/删除插件
- **标准化**：所有插件遵循统一的接口和规范

### 1.3 插件类型

- **系统插件**：由官方提供的插件，如相册插件、日记插件
- **用户插件**：用户自己开发的插件（未来支持）

#### 3.1.5 Controller类规范

**基本结构：**
```java
@RestController
@RequestMapping("/api/plugins/{pluginId}")
@Slf4j
public class EntityController extends BaseController {
    
    @Autowired
    private EntityService service;
    
    /**
     * 创建实体
     */
    @PostMapping("/entities")
    public ResponseEntity<EntityDTO> create(
            @PathVariable String pluginId,
            @RequestBody CreateRequest request,
            @RequestHeader(value = "Authorization", required = false) String authHeader) {
        
        // 1. 身份验证
        var user = validateUser(authHeader);
        
        // 2. 调用Service
        EntityDTO result = service.create(request, user.getId());
        
        // 3. 返回结果
        return ResponseEntity.ok(result);
    }
    
    /**
     * 查询实体列表
     */
    @GetMapping("/entities")
    public ResponseEntity<Page<EntityDTO>> list(
            @PathVariable String pluginId,
            @RequestParam(required = false) String keyword,
            @RequestParam(defaultValue = "0") int page,
            @RequestParam(defaultValue = "20") int size,
            @RequestHeader(value = "Authorization", required = false) String authHeader) {
        
        var user = validateUser(authHeader);
        QueryRequest request = QueryRequest.builder()
            .keyword(keyword)
            .page(page)
            .size(size)
            .build();
        
        Page<EntityDTO> result = service.list(request, user.getId());
        return ResponseEntity.ok(result);
    }
}
```

**规范要求：**
- 使用`@RestController`注解
- 继承`BaseController`（如果存在）
- 路径使用复数形式：`/entities`、`/photos`
- 使用`ResponseEntity`返回结果
- 统一异常处理
- 参数验证使用`@Valid`注解
- 日志记录关键操作

## 四、数据库规范

### 4.1 表设计规范

**表命名：**
- 使用复数形式：`photo_albums`、`photos`
- 使用下划线分隔：`photo_albums`（不使用驼峰）
- 插件相关表使用插件前缀：`photo_albums`、`photo_album_configs`

**字段命名：**
- 使用下划线分隔：`user_id`、`created_at`
- 布尔字段使用`is_`前缀：`is_deleted`、`is_public`
- 时间字段使用`_at`后缀：`created_at`、`updated_at`

**字段类型：**
- ID使用`BIGINT`
- 字符串根据长度选择`VARCHAR(n)`或`TEXT`
- 布尔值使用`BOOLEAN`
- 时间使用`DATETIME`或`TIMESTAMP`
- JSON数据使用`JSON`类型（MySQL 8.0+）

**索引规范：**
- 主键自动创建索引
- 外键字段创建索引
- 经常查询的字段创建索引
- 联合索引考虑查询顺序
- 索引命名：`idx_{table}_{field}`

### 4.2 迁移脚本规范

**文件命名：**
```
V{YYYYMMDD}{NN}__{description}.sql
```

**示例：**
```
V20250104__create_photo_album_tables.sql
```

**脚本内容：**
```sql

-- 日期：2025-01-04
```

- 使用`CREATE TABLE IF NOT EXISTS`

- 外键使用命名约束

## 五、API规范

### 5.1 URL设计规范

**路径结构：**
```
/api/plugins/{pluginId}/resources
```

**示例：**
```
/api/plugins/photo-album/albums
/api/plugins/photo-album/albums/{albumId}/photos
```

**HTTP方法：**
- GET：查询（列表、详情）
- POST：创建
- PUT：更新（完整更新）
- PATCH：部分更新（如果支持）
- DELETE：删除

### 5.2 请求规范

**参数传递：**
- 路径参数：资源ID
- 查询参数：筛选、排序、分页
- 请求体：创建和更新的数据

**分页参数：**
- `page`：页码（从0开始）
- `size`：每页数量（默认20）
- `sort`：排序字段（如：`created_at,desc`）

**响应格式：**
```json
{
  "code": 200,
  "message": "成功",
  "data": { /* 数据 */ },
  "timestamp": "2025-01-04T10:00:00"
}
```

**错误响应：**
```json
{
  "code": 400,
  "message": "错误信息",
  "data": null,
  "timestamp": "2025-01-04T10:00:00"
}
```

### 5.3 状态码规范

- `200 OK`：成功
- `201 Created`：创建成功
- `400 Bad Request`：请求错误
- `401 Unauthorized`：未授权
- `403 Forbidden`：禁止访问
- `404 Not Found`：资源不存在
- `500 Internal Server Error`：服务器错误
