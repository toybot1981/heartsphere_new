# Change: 建立心理知识库框架（Establish Psychology Knowledge Base Framework）

## Why

当前 psychology-mentor 模块已有基础的 `KnowledgeBaseService`，但功能还比较简单，主要是通过 AI 生成内容，缺乏：
1. **结构化知识库存储**：没有持久化的知识库数据存储机制
2. **外部资源整合**：没有整合经典的心理学、心理治疗网站资源
3. **知识分类体系**：缺乏系统的知识分类和标签体系
4. **资源采集框架**：没有建立资源采集、验证、存储的标准化流程

为了建立专业、可靠的心理知识库，需要：
1. 搜集和整理经典的心理学、心理治疗网站资源
2. 建立知识库的数据模型和存储结构
3. 设计知识分类体系和标签系统
4. 建立资源采集、验证、存储的框架
5. 为后续知识库内容的批量导入和AI增强做准备

该框架将为 psychology-mentor 模块提供坚实的知识库基础，支持：
- 疗法理论知识库的扩展
- 临床案例库的丰富
- 心理学概念和术语的标准化
- AI生成内容的验证和补充

## What Changes

### 1. 知识库数据模型
- **ADDED**: 知识库实体模型
  - `PsychologyKnowledge` - 心理学知识条目实体
  - `KnowledgeCategory` - 知识分类实体
  - `KnowledgeSource` - 知识来源实体
  - `KnowledgeTag` - 知识标签实体
  - 支持知识条目的版本管理和审核状态

### 2. 资源搜集和整理
- **ADDED**: 心理学资源清单文档
  - 经典心理学网站列表（APA、Psychology Today等）
  - 心理治疗流派官方网站
  - 学术期刊和论文资源
  - 专业书籍和教材资源
  - 每个资源包含：URL、描述、可信度评级、适用领域

### 3. 知识分类体系
- **ADDED**: 知识分类标准
  - 疗法理论（Therapy Theory）
  - 干预技术（Intervention Techniques）
  - 临床案例（Clinical Cases）
  - 心理学概念（Psychology Concepts）
  - 研究证据（Research Evidence）
  - 专业术语（Professional Terms）

### 4. 资源采集框架
- **ADDED**: 资源采集服务
  - `ResourceCollectorService` - 资源采集服务接口
  - 支持多种采集方式：网页爬取、API集成、手动导入
  - 资源验证和去重机制
  - 采集任务管理和状态跟踪

### 5. 知识库管理接口
- **ADDED**: 知识库管理API
  - 知识条目CRUD操作
  - 知识分类管理
  - 知识搜索和检索
  - 知识来源管理
  - 批量导入接口

### 6. 数据库迁移
- **ADDED**: Flyway 迁移脚本
  - 创建知识库相关表结构
  - 初始化知识分类数据
  - 创建索引和约束

### 7. 文档和规范
- **ADDED**: 知识库框架文档
  - 资源搜集指南
  - 知识分类标准文档
  - 资源采集流程文档
  - API使用文档

## Scope

### In Scope
- 建立知识库数据模型和数据库表结构
- 搜集和整理经典心理学、心理治疗网站资源清单
- 设计知识分类体系和标签系统
- 实现基础的知识库管理API
- 建立资源采集框架（接口和基础实现）
- 创建知识库框架文档

### Out of Scope
- 实际爬取和导入大量知识库内容（这是后续任务）
- AI自动生成知识库内容（已有基础功能，后续增强）
- 知识库的前端管理界面（后续任务）
- 知识库的全文搜索功能（后续任务）
- 知识库的版本控制和审核工作流（后续任务）

## Success Criteria

1. ✅ 知识库数据模型设计完成，数据库表结构创建成功
2. ✅ 心理学资源清单文档完成，包含至少20个经典资源
3. ✅ 知识分类体系定义完成，支持6个主要分类
4. ✅ 基础的知识库管理API实现完成，支持CRUD操作
5. ✅ 资源采集框架接口定义完成，支持扩展
6. ✅ 知识库框架文档完成，包含使用指南

## Dependencies

- **依赖模块**: psychology-mentor 模块（已存在）
- **数据库**: MySQL 8.0+（已配置）
- **技术栈**: Spring Boot 3.2.0, Spring Data JPA, Flyway（已配置）

## Risks

1. **资源质量**: 需要确保搜集的资源具有权威性和可信度
   - **缓解**: 建立资源可信度评级机制，优先使用权威机构资源
2. **数据模型扩展性**: 未来可能需要支持更复杂的知识结构
   - **缓解**: 设计灵活的数据模型，支持JSON字段存储扩展信息
3. **采集合规性**: 网页爬取需要遵守robots.txt和版权要求
   - **缓解**: 优先使用API和公开数据，明确标注来源
