# Change: 系统大重构 - 拆分为三个子项目

## Why

当前 HeartSphere 项目采用单体架构，所有功能（客户端、管理端、Mentis）都混在一个代码库中，存在以下问题：

1. **代码组织混乱**：
   - 客户端、管理端、Mentis 的代码混杂在一起，难以区分和维护
   - 前端代码中 `frontend/admin/`、`frontend/mobile/`、`frontend/wechat/` 等目录混在一起
   - 后端代码中不同模块的 controller、service 都在同一个包结构下

2. **部署和扩展困难**：
   - 无法独立部署和扩展各个子系统
   - 客户端、管理端、Mentis 的更新和发布耦合在一起
   - 无法针对不同子系统进行独立的性能优化和资源分配

3. **团队协作效率低**：
   - 不同团队开发不同子系统时容易产生代码冲突
   - 难以实现并行开发和独立发布
   - 代码审查范围过大，影响效率

4. **共享代码管理混乱**：
   - 缺乏明确的共享代码管理机制
   - 公共工具类、类型定义、API 基础库等散落在各处
   - 难以识别和维护真正需要共享的代码

## What Changes

### 项目结构重组

将整个 HeartSphere 项目拆分为三个独立的子项目：

1. **客户端项目（client）**：
   - 包含 PC Web、Mobile（Capacitor）、微信小程序三个版本
   - 每个版本都有独立的 frontend
   - 共享一个 backend（客户端后端服务）

2. **管理端项目（admin）**：
   - 独立的 frontend（管理后台界面）
   - 独立的 backend（管理端后端服务）

3. **Mentis 项目（mentis）**：
   - 独立的 frontend（Mentis 交互界面）
   - 独立的 backend（Mentis 智能体服务）

### 共享代码库（shared）

创建共享代码库，包含三个子项目共用的内容：

1. **共享后端模块（shared-backend）**：
   - 公共实体类（Entity）
   - 公共工具类（Utils）
   - 公共配置类（Config）
   - 公共异常类（Exception）
   - 公共 DTO 和接口定义
   - 数据库迁移脚本（Flyway）

2. **共享前端模块（shared-frontend）**：
   - 公共类型定义（TypeScript types）
   - 公共工具函数（Utils）
   - 公共组件库（UI Components）
   - 公共 API 基础库（Request/Response 处理）
   - 公共常量定义

3. **共享配置和文档（shared-config）**：
   - 数据库配置
   - 公共环境变量配置
   - 共享文档和规范

### 新的项目结构

```
heartsphere/
├── client/                    # 客户端项目
│   ├── frontend-pc/          # PC Web 前端
│   ├── frontend-mobile/      # Mobile 前端
│   ├── frontend-miniprogram/ # 微信小程序
│   └── backend/              # 客户端后端
├── admin/                     # 管理端项目
│   ├── frontend/             # 管理端前端
│   └── backend/              # 管理端后端
├── mentis/                    # Mentis 项目
│   ├── frontend/             # Mentis 前端
│   └── backend/              # Mentis 后端
└── shared/                    # 共享代码库
    ├── backend/              # 共享后端模块
    ├── frontend/             # 共享前端模块
    └── config/               # 共享配置
```

## Impact

### 影响的文件

- **项目根目录结构**：完全重组
- **所有前端代码**：需要按子项目重新组织
- **所有后端代码**：需要按子项目重新组织
- **构建配置文件**：`package.json`、`pom.xml` 等需要拆分
- **部署脚本**：需要更新以适应新的项目结构
- **CI/CD 配置**：需要为每个子项目单独配置

### 影响的规范

- **项目结构规范**：需要定义新的项目结构规范
- **共享代码规范**：需要定义共享代码的使用和管理规范
- **依赖管理规范**：需要定义子项目如何引用共享模块
- **部署规范**：需要更新部署流程以适应新的项目结构

### 影响的工作流

- **开发工作流**：需要支持多项目并行开发
- **构建工作流**：需要支持独立构建和联合构建
- **测试工作流**：需要支持独立测试和集成测试
- **发布工作流**：需要支持独立发布和版本管理

## Notes

- 这是一个**大型重构**，需要分阶段实施
- 需要仔细识别和提取共享代码，避免过度共享或共享不足
- 迁移过程中需要保持系统可用性，建议采用渐进式迁移
- 需要更新所有相关文档和开发指南
