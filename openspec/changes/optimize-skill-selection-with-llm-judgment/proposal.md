# 优化技能选择和激活机制：采用 LLM 驱动的三层渐进式加载

## Context

当前系统的技能激活机制存在以下问题：

1. **规则驱动限制**：使用关键词匹配和字符串包含进行技能评分，无法理解语义
2. **未充分利用三层架构**：虽然实现了 Level 1/2/3 的三层架构，但 Level 2/3 只在执行时加载，没有作为提示词给大模型
3. **缺乏语义理解**：无法处理同义词、语义相似但措辞不同的表达
4. **与 Claude 的差异**：Claude 将 Level 1/2/3 都作为提示词交给大模型判断，而当前系统只将 Level 1 转换为 Function Definition

## Goals

### Goals

1. **采用 LLM 驱动的技能选择**：将技能选择从规则驱动改为 LLM 驱动，提升语义理解能力
2. **实现三层渐进式提示词加载**：参照 Claude，将 Level 1/2/3 都作为提示词加载给大模型
3. **渐进式决策机制**：先加载 Level 1 进行初步筛选，再加载 Level 2/3 进行深度评估
4. **保持性能优化**：通过渐进式加载减少初始开销，只在需要时加载详细内容
5. **向后兼容**：保留现有的规则驱动机制作为备选方案

### Non-Goals

- **完全移除规则驱动**：保留作为备选方案和降级策略
- **改变技能执行机制**：技能执行逻辑保持不变
- **修改数据库结构**：不改变现有的技能定义表结构

## Decisions

### Decision 1: 三层渐进式 LLM 判断机制

**采用三层渐进式提示词加载，每层都交给大模型判断**：

1. **Level 1（元数据）**：初始加载，转换为提示词，大模型进行初步筛选
2. **Level 2（指令）**：对候选技能加载 Level 2，大模型进行深度评估
3. **Level 3（资源）**：对最终候选技能加载 Level 3，大模型进行最终决策

**优势**：
- 充分利用大模型的语义理解能力
- 渐进式加载减少初始开销
- 更准确的技能选择

**备选方案**：
- 一次性加载所有层级（性能差）
- 只使用 Level 1（准确性差）

### Decision 2: 混合决策机制

**采用 LLM 驱动 + 规则驱动的混合机制**：

1. **快速路径**：规则驱动进行初步筛选（可选）
2. **精确路径**：LLM 驱动进行深度评估
3. **降级策略**：LLM 失败时回退到规则驱动

**优势**：
- 性能与准确性的平衡
- 容错能力强
- 向后兼容

### Decision 3: 提示词结构设计

**设计标准化的技能提示词格式**：

```
[技能元数据]
- 技能ID: {skillId}
- 技能名称: {name}
- 技能描述: {description}
- 技能分类: {category}

[技能指令]
{Level 2 指令内容}

[技能资源]
{Level 3 资源内容}
```

**优势**：
- 结构清晰，易于大模型理解
- 支持渐进式加载
- 便于调试和优化

## Impact

### 正面影响

1. **准确性提升**：LLM 驱动的技能选择更准确，能理解语义
2. **灵活性增强**：无需手动配置关键词，自动理解用户意图
3. **用户体验改善**：更智能的技能激活，减少误匹配

### 潜在风险

1. **性能影响**：LLM 调用增加延迟，需要通过渐进式加载优化
2. **成本增加**：LLM API 调用成本，需要缓存和优化
3. **依赖增强**：对 LLM 服务的依赖增加，需要降级策略

## Success Criteria

1. **准确性**：技能选择准确率提升 20% 以上
2. **性能**：初始加载时间不超过当前实现的 150%
3. **兼容性**：现有技能定义无需修改即可使用
4. **可调试性**：提供详细的技能选择日志和调试信息
