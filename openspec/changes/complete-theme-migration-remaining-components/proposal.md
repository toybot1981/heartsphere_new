# Change: 完成剩余组件的主题迁移

## Why

主题系统基础设施已经建立（`add-theme-skin-management-system`），但仍有大量组件使用硬编码颜色，未适配主题系统。根据统计：

- **已迁移**: 约 22 个文件使用 CSS 变量（504 个匹配项）
- **待迁移**: 约 112 个文件仍使用硬编码颜色（1028 个匹配项）
- **完成率**: 约 16.4%

这些未迁移的组件导致：
1. **用户体验不一致**: 切换主题时，部分页面和组件不会更新，造成视觉割裂
2. **维护困难**: 硬编码颜色分散在各处，难以统一管理和调整
3. **扩展性差**: 添加新主题时，需要逐个修改组件，工作量大且容易遗漏

## What Changes

### 范围
- **仅针对 main 工程**: `main/frontend/components/` 和 `main/frontend/mobile/` 目录下的组件
- **不包括**: admin、company 等其他子项目

### 迁移策略
采用**分阶段、按优先级**的迁移策略：

#### 阶段 1: 高优先级组件（核心功能）
- ChatWindow.tsx 主容器（子组件已完成）
- 主要模态框组件（LoginModal, SettingsModal 等）
- 移动端主要页面（6个）

#### 阶段 2: 中优先级组件（功能模块）
- HeartConnect 相关组件（11个）
- QuickConnect 相关组件（10个）
- Portal 相关组件（4个）
- Character 相关组件（8个）
- Scenario 相关组件（5个）
- Scene Wizard 相关组件（5个）
- Plugin 相关组件（5个）
- Mailbox 相关组件（6个）

#### 阶段 3: 低优先级组件（辅助功能）
- 其他辅助组件和工具组件（约70个）
- 示例组件（可选）

### 迁移模式
统一使用以下迁移模式：

1. **背景色**: `bg-black` → `style={{ backgroundColor: 'var(--bg-primary)' }}`
2. **文字颜色**: `text-white` → `style={{ color: 'var(--text-primary)' }}`
3. **边框颜色**: `border-white/10` → `style={{ borderColor: 'var(--bg-overlay)' }}`
4. **悬停效果**: 使用 `onMouseEnter/onMouseLeave` 实现
5. **移动端**: 使用移动端专用变量（`--tabbar-*`, `--card-*` 等）

## Impact

### 影响的文件
- **PC端组件**: 约 100+ 个文件需要迁移
- **移动端组件**: 约 40+ 个文件需要迁移
- **总计**: 约 140+ 个文件

### 影响的规范
- 无新增规范，遵循已有的主题系统规范
- 确保所有组件遵循统一的迁移模式

### 影响的工作流
- 前端开发人员需要确保新组件使用 CSS 变量
- 代码审查需要检查主题兼容性
- 测试需要验证主题切换功能

## Notes

- **渐进式迁移**: 分阶段完成，每个阶段完成后进行测试验证
- **向后兼容**: 确保迁移后的组件在"科技风格"主题下仍然正常显示
- **性能考虑**: 使用 CSS 变量确保主题切换性能良好
- **测试要求**: 每个组件迁移后都要测试在不同主题下的显示效果
- **文档更新**: 更新迁移进度文档，记录已完成和待完成的组件
- **参考实现**: 已迁移的组件（如 HeaderBar, MessageBubble 等）可作为参考模板
