## ADDED Requirements

### Requirement: 统一管理后台
系统 SHALL 提供一个统一的管理后台（admin），用于管理所有客户端产品（client、edu、mentis、company）的配置、用户、数据和系统。

#### Scenario: 统一管理入口
- **WHEN** 访问管理后台
- **THEN** 应该提供一个统一的管理入口
- **AND** 该入口应该能够管理所有客户端产品
- **AND** 该入口应该提供统一的管理界面和导航

#### Scenario: 产品管理功能
- **WHEN** 管理员查看产品管理页面
- **THEN** 应该能够查看所有客户端产品（client、edu、mentis、company）的列表
- **AND** 应该能够查看每个产品的运行状态和统计信息
- **AND** 应该能够配置和更新每个产品的设置
- **AND** 应该能够启用或禁用某个产品

#### Scenario: 用户和权限管理功能
- **WHEN** 管理员查看用户和权限管理页面
- **THEN** 应该能够统一管理所有产品的用户
- **AND** 应该能够分配用户权限和角色
- **AND** 应该能够查看用户行为分析和统计
- **AND** 应该能够跨产品管理用户权限

#### Scenario: 数据管理功能
- **WHEN** 管理员查看数据管理页面
- **THEN** 应该能够统一查看和管理各产品的数据
- **AND** 应该能够导出和备份各产品的数据
- **AND** 应该能够查看数据统计和分析
- **AND** 应该能够跨产品查询和统计数据

#### Scenario: 系统管理功能
- **WHEN** 管理员查看系统管理页面
- **THEN** 应该能够管理系统配置和参数
- **AND** 应该能够查看系统日志和监控信息
- **AND** 应该能够监控系统性能和告警
- **AND** 应该能够管理各产品的系统配置

### Requirement: 管理后台架构
管理后台 SHALL 采用独立的前后端架构，通过 API 调用各产品的后端服务，不直接访问各产品的数据库或内部状态。

#### Scenario: 独立的管理后台后端
- **WHEN** 查看管理后台后端服务
- **THEN** 应该是一个独立的 Spring Boot 应用
- **AND** 应该提供统一的管理 API
- **AND** 应该通过 API 调用各产品的后端服务
- **AND** 不应该直接访问各产品的数据库

#### Scenario: 独立的管理后台前端
- **WHEN** 查看管理后台前端应用
- **THEN** 应该是一个独立的 React 应用
- **AND** 应该通过 API 调用管理后台后端服务
- **AND** 应该提供统一的管理界面和交互体验
- **AND** 不应该直接调用各产品的后端 API

#### Scenario: API 代理机制
- **WHEN** 管理后台需要访问某个产品的数据或功能
- **THEN** 管理后台后端应该通过 API 调用该产品的后端服务
- **AND** 管理后台后端应该作为 API 代理，转发请求和响应
- **AND** 管理后台后端应该处理跨产品的数据聚合和统计

### Requirement: 管理后台安全
管理后台 SHALL 实现严格的安全控制，包括身份认证、权限控制、操作审计等。

#### Scenario: 身份认证
- **WHEN** 用户访问管理后台
- **THEN** 必须通过身份认证（登录）
- **AND** 应该支持多种认证方式（密码、双因素认证等）
- **AND** 应该实现会话管理和超时控制

#### Scenario: 权限控制
- **WHEN** 管理员执行管理操作
- **THEN** 应该根据管理员的角色和权限控制访问范围
- **AND** 应该支持细粒度的权限控制（如只能管理特定产品）
- **AND** 应该实现操作权限的动态检查

#### Scenario: 操作审计
- **WHEN** 管理员执行管理操作
- **THEN** 应该记录操作日志和审计信息
- **AND** 应该记录操作时间、操作人、操作内容等
- **AND** 应该提供操作审计查询和报告功能
