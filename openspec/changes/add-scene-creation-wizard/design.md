# Design: 场景创建向导

## Context

用户需要在已有世界中添加新场景时，当前只能通过 `EraConstructorModal` 逐个创建场景。首次注册时可以使用 `InitializationWizard` 批量创建，但后续添加场景时缺少类似的批量创建功能。

## Goals / Non-Goals

### Goals
- 提供批量创建场景的功能，提升用户效率
- 保持与 `InitializationWizard` 的一致性，降低学习成本
- 支持选择多个预置场景、角色、主线剧情和剧本
- 支持自定义名称（手动输入或AI生成）
- 模块化设计，便于维护和复用

### Non-Goals
- 不支持创建自定义场景（仅支持从预置场景创建）
- 不支持编辑已创建的场景（编辑功能由 `EraConstructorModal` 提供）
- 不提供场景预览功能（用户可以在创建后查看）

## Decisions

### Decision 1: 组件结构设计

**决策**：将向导拆分为多个子组件，每个步骤独立为一个组件。

**理由**：
- 提高代码可维护性，每个组件职责单一
- 便于复用（例如，场景选择步骤可以在其他地方复用）
- 便于测试，每个组件可以独立测试

**实现**：
- `SceneCreationWizard.tsx` - 主组件，管理步骤状态和数据
- `SceneSelectionStep.tsx` - 场景选择步骤
- `CharacterSelectionStep.tsx` - 角色选择步骤
- `MainStorySelectionStep.tsx` - 主线剧情选择步骤
- `ScriptSelectionStep.tsx` - 剧本选择步骤
- `SceneCreationSummary.tsx` - 创建摘要预览（可选）

### Decision 2: 数据加载策略

**决策**：按需加载数据，当用户选择场景后，才加载该场景的角色、主线剧情和剧本。

**理由**：
- 减少初始加载时间
- 避免加载不必要的数据
- 提升用户体验

**实现**：
- 初始只加载预置场景列表
- 当用户选择场景后，通过 `useEffect` 监听 `selectedEras` 变化，加载对应的角色、主线剧情和剧本

### Decision 3: 批量创建顺序

**决策**：按照场景 → 角色 → 主线剧情 → 剧本的顺序创建。

**理由**：
- 场景是基础，必须先创建
- 角色、主线剧情、剧本都依赖于场景，必须在场景创建后才能创建
- 角色、主线剧情、剧本之间没有依赖关系，可以并行创建（但为了简化错误处理，按顺序创建）

**实现**：
1. 创建所有选中的场景，保存原场景ID到新场景ID的映射关系
2. 创建选中的角色，根据场景映射关系确定目标场景ID
3. 创建选中的主线剧情，根据场景映射关系确定目标场景ID
4. 创建选中的剧本，根据场景映射关系确定目标场景ID

### Decision 4: 错误处理策略

**决策**：部分创建失败时，继续创建其他项目，最后统一显示创建结果。

**理由**：
- 提升用户体验，即使部分创建失败，也能创建成功的项目
- 用户可以知道哪些创建成功、哪些创建失败，便于后续处理

**实现**：
- 使用 try-catch 捕获每个创建操作的错误
- 记录创建成功和失败的项目
- 创建完成后，显示创建结果摘要（成功数量、失败数量、失败原因）

### Decision 5: 图片分辨率规则

**决策**：场景列表中的图片使用 `thumbnail` 分辨率（200×200）。

**理由**：
- 符合项目的图片分辨率规则（头像和预置资源选择框使用缩略图）
- 提升加载速度，减少网络流量

**实现**：
- 使用 `LazyImage` 组件，设置 `purpose="thumbnail"`
- 使用 `generateVariantUrl` 生成图片变体URL

### Decision 6: AI生成名称功能

**决策**：复用 `InitializationWizard` 中的AI生成名称逻辑。

**理由**：
- 保持功能一致性
- 减少代码重复

**实现**：
- 调用 `aiService.generateTextStream()` 生成名称
- 使用相同的提示词模板

## Risks / Trade-offs

### Risk 1: 创建失败时的数据一致性

**风险**：如果部分创建失败，可能导致数据不一致（例如，场景创建成功，但角色创建失败）。

**缓解措施**：
- 显示详细的创建结果，告知用户哪些创建成功、哪些创建失败
- 用户可以手动创建失败的项目，或重新运行向导

### Risk 2: 大量数据创建时的性能问题

**风险**：如果用户选择大量场景、角色、剧本，批量创建可能耗时较长。

**缓解措施**：
- 显示创建进度，让用户知道当前进度
- 考虑未来优化：使用后台任务队列，异步创建

### Risk 3: 网络错误导致的数据丢失

**风险**：如果创建过程中网络中断，可能导致部分数据已创建，但用户不知道。

**缓解措施**：
- 创建完成后刷新场景列表，显示已创建的场景
- 如果创建失败，显示错误信息，用户可以重新运行向导（已创建的场景不会重复创建，因为会检查是否已存在）

## Migration Plan

### 无迁移需求

此功能是新增功能，不影响现有功能，无需迁移。

### 向后兼容

- 现有的 `EraConstructorModal` 功能保持不变
- 用户可以选择使用向导创建，或继续使用原有的单个创建方式

## Open Questions

1. **是否需要支持编辑已创建的场景？**
   - 当前设计：不支持编辑，编辑功能由 `EraConstructorModal` 提供
   - 如果需要，可以在向导中添加"编辑模式"，但会增加复杂度

2. **是否需要支持创建自定义场景？**
   - 当前设计：仅支持从预置场景创建
   - 如果需要，可以在向导中添加"创建自定义场景"选项，跳转到 `EraConstructorModal`

3. **移动端是否需要独立的向导实现？**
   - 当前设计：PC和移动端可以共用同一个向导组件（响应式设计）
   - 如果需要更好的移动端体验，可以创建移动端专用版本
