# Change: 根据优化后的 web-automation-testing 技能补充测试方案，实现测试过程的跟踪

## Why

当前 web-automation-testing 技能在执行测试时，虽然支持失败时采集页面上下文并生成 Cursor 分析工件，但缺乏**测试过程的实时跟踪**和**页面内容异常检测**能力：

1. **进度可见性不足**：测试执行过程中，用户无法实时了解当前执行到哪个用例、哪个步骤，只能等待最终报告
2. **成功用例的页面内容未验证**：当前仅在失败时采集页面上下文，但成功用例的页面内容可能也存在异常（如显示错误信息、空内容、格式错误等），这些异常未被检测
3. **测试过程时间线缺失**：缺乏测试执行过程中的事件时间线（用例开始/结束、步骤执行、修复尝试、服务重启等），不利于问题追溯和性能分析
4. **异常内容未自动分析**：当检测到页面内容异常时，应自动生成 Cursor 分析工件，便于 AI 辅助分析

基于优化后的 web-automation-testing 技能（已支持 Cursor 分析工件、数据库验证、日志检查、服务重启），需要补充**测试过程跟踪**能力，提升测试的可观测性和问题定位效率。

## What Changes

- **新增**：测试过程实时进度跟踪
  - `test_executor.py` 在执行每个用例和步骤时输出进度信息（如 `[1/10] case_1_1: 登录管理端 - Step 3/8: 输入密码`）
  - 支持进度输出到控制台和日志文件，便于实时监控
  - 测试结果 JSON 中包含每个用例/步骤的执行时间戳和耗时
- **新增**：页面内容异常检测与分析
  - 在成功用例的验证步骤后，检查页面内容是否正常（如是否包含错误信息、空内容、异常格式等）
  - 当检测到页面内容异常时，自动采集页面上下文并生成 Cursor 分析工件（即使用例标记为"通过"）
  - 在测试结果中标记为"通过但内容异常"，并在报告中突出显示
- **新增**：测试过程时间线记录
  - `test_runner.py` 和 `test_executor.py` 记录关键事件的时间戳：用例开始/结束、步骤执行、失败/成功、修复尝试、服务重启、日志检查等
  - 测试结果 JSON 中包含 `timeline` 字段，记录事件序列
  - 报告生成器在报告中展示时间线（可选的时间线视图）
- **新增**：测试过程跟踪配置
  - 测试计划中可配置：是否启用进度输出、是否启用内容异常检测、时间线详细程度等
  - 支持环境变量控制跟踪行为（如 `TEST_TRACKING_VERBOSE=1`）
- **修改**：报告生成器增强
  - 在报告中展示测试过程时间线（按时间排序的事件列表）
  - 突出显示"通过但内容异常"的用例
  - 引用自动生成的 Cursor 分析工件（包括异常内容分析）

## Impact

- **受影响的能力**：修改 capability `web-automation-testing`（本变更内以 MODIFIED 形式出现在 `specs/web-automation-testing/spec.md`）
- **受影响的代码/资产**：
  - `.claude/skills/web-automation-testing/scripts/test_executor.py` - 添加进度输出、时间线记录、内容异常检测
  - `.claude/skills/web-automation-testing/scripts/test_runner.py` - 添加时间线记录、进度聚合
  - `.claude/skills/web-automation-testing/scripts/report_generator.py` - 增强报告，展示时间线和异常内容
  - `.claude/skills/web-automation-testing/references/` - 新增或更新文档说明测试过程跟踪功能
- **依赖与前置**：
  - 无新增外部依赖；使用现有的 Playwright、JSON 处理能力
  - 测试计划 JSON 格式向后兼容（新增字段为可选）
