# DevOps 工作台设计文档

## 架构设计

### 整体架构

DevOps 工作台采用前后端分离架构：

```
┌─────────────────┐
│  Admin Frontend │
│  (React/TS)     │
│                 │
│  DevOpsWorkbench│
│  Component      │
└────────┬────────┘
         │ HTTP/REST API
         │
┌────────▼────────┐
│  Admin Backend  │
│  (Spring Boot)  │
│                 │
│  DevOpsWorkbench│
│  Controller     │
│  Service        │
└────────┬────────┘
         │
         │ Execute Scripts
         │
┌────────▼────────┐
│  Script Engine  │
│  (Process Exec) │
│  + Scheduler    │
└─────────────────┘
```

- 日志流状态（WebSocket 或 Server-Sent Events）
- 历史记录状态

#### 核心服务

**DevOpsWorkbenchService**:
- `executeScript(ScriptExecutionRequest)`: 执行脚本
- `getExecutionStatus(String executionId)`: 获取执行状态
- `getExecutionLogs(String executionId)`: 获取执行日志
- `getExecutionHistory(Pageable)`: 获取执行历史
- `validatePermission(String scriptId, Admin admin)`: 验证权限
- `cancelExecution(String executionId)`: 取消执行

**ScriptExecutionEngine**:
- 安全执行系统命令
- 收集实时日志
- 处理执行结果
- 超时控制
- 环境隔离

**ScheduledTaskService**:
- 创建定时任务
- 管理定时任务
- 执行定时任务
- 通知任务结果

## 脚本配置系统

    requires:

      - maven
      - node
    parameters:
      - name: clean
        type: boolean
        default: false
        description: 是否清理缓存
    permissions:

  - id: deploy-backend-prod

      - dev

### 脚本分类

- **build**: 构建相关脚本
- **deploy**: 部署相关脚本
- **test**: 测试相关脚本
- **scan**: 代码扫描相关脚本
- **database**: 数据库管理脚本
- **server**: 服务器管理脚本
- **other**: 其他脚本

## 脚本执行引擎

### 执行流程

1. **权限验证**: 检查管理员是否有权限执行该脚本
2. **参数验证**: 验证脚本参数的有效性
3. **环境检查**: 检查所需的环境和工具是否可用
4. **确认检查**: 对于高风险操作，需要二次确认
5. **执行脚本**: 在隔离的环境中执行脚本
6. **日志收集**: 实时收集脚本输出
7. **结果处理**: 处理执行结果和错误
8. **记录存储**: 存储执行记录和日志

### 安全机制

1. **命令注入防护**:
   - 参数白名单验证
   - 参数转义和过滤
   - 禁止执行危险命令（rm -rf /, format 等）

2. **权限控制**:
   - 基于角色的访问控制（RBAC）
   - 脚本级别的权限配置
   - 环境级别的权限控制

3. **环境隔离**:
   - 开发/测试/生产环境分离
   - 脚本执行在受限环境中
   - 资源限制（CPU、内存、磁盘）

4. **审计日志**:
   - 记录所有脚本执行操作
   - 记录执行者、时间、参数、结果
   - 支持审计查询和导出

## 实时日志流

### 实现方案

使用 Server-Sent Events (SSE) 或 WebSocket 实现实时日志流：

```java
@GetMapping(value = "/executions/{executionId}/logs/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter streamLogs(@PathVariable String executionId) {
    SseEmitter emitter = new SseEmitter(Long.MAX_VALUE);
    logStreamService.addEmitter(executionId, emitter);
    return emitter;
}
```

前端使用 EventSource 接收日志：

```typescript
const eventSource = new EventSource(`/api/admin/devops/executions/${executionId}/logs/stream`);
eventSource.onmessage = (event) => {
    const log = JSON.parse(event.data);
    appendLog(log);
};
```

## 定时任务管理

### 定时任务配置

使用 Spring Scheduled 或 Quartz 实现定时任务：

```java
@Entity
public class ScheduledTask {
    @Id
    private String id;
    private String scriptId;
    private String cronExpression;
    private boolean enabled;
    private String createdBy;
    private LocalDateTime createdAt;
    // ...
}
```

### 定时任务执行

1. 定时任务触发时，创建 ScriptExecution 记录
2. 执行脚本
3. 记录执行结果
4. 发送通知（可选）

## 数据库设计

### ScriptExecution 实体

```java
@Entity
@Table(name = "script_executions")
public class ScriptExecution {
    @Id
    private String id;
    
    private String scriptId;
    private String scriptName;
    
    @ManyToOne
    private Admin executedBy;
    
    private LocalDateTime startedAt;
    private LocalDateTime finishedAt;
    private ExecutionStatus status; // RUNNING, SUCCESS, FAILED, CANCELLED
    
    private String parameters; // JSON
    private String output; // 执行输出
    private String error; // 错误信息
    private Integer exitCode;
    
    private String logFilePath;
    
    @ManyToOne(optional = true)
    private ScheduledTask scheduledTask;
}
```

### ScheduledTask 实体

```java
@Entity
@Table(name = "scheduled_tasks")
public class ScheduledTask {
    @Id
    private String id;
    
    private String scriptId;
    private String scriptName;
    private String cronExpression;
    private boolean enabled;
    
    @ManyToOne
    private Admin createdBy;
    
    private LocalDateTime createdAt;
    private LocalDateTime lastExecutedAt;
    private LocalDateTime nextExecutionTime;
}
```

## API 设计

### 脚本管理 API

- `GET /api/admin/devops/scripts` - 获取脚本列表
- `GET /api/admin/devops/scripts/{id}` - 获取脚本详情
- `POST /api/admin/devops/scripts/{id}/execute` - 执行脚本
- `GET /api/admin/devops/executions` - 获取执行历史
- `GET /api/admin/devops/executions/{id}` - 获取执行详情
- `GET /api/admin/devops/executions/{id}/logs` - 获取执行日志
- `GET /api/admin/devops/executions/{id}/logs/stream` - 实时日志流
- `POST /api/admin/devops/executions/{id}/cancel` - 取消执行

### 定时任务 API

- `GET /api/admin/devops/scheduled-tasks` - 获取定时任务列表
- `POST /api/admin/devops/scheduled-tasks` - 创建定时任务
- `PUT /api/admin/devops/scheduled-tasks/{id}` - 更新定时任务
- `DELETE /api/admin/devops/scheduled-tasks/{id}` - 删除定时任务
- `POST /api/admin/devops/scheduled-tasks/{id}/enable` - 启用定时任务
- `POST /api/admin/devops/scheduled-tasks/{id}/disable` - 禁用定时任务

## 前端 UI 设计

### 设计原则

- **风格一致性**: 遵循现有管理后台的深色主题风格（slate-900 背景，slate-800 边框）
- **响应式布局**: 支持不同屏幕尺寸，使用 Tailwind CSS 响应式类
- **交互反馈**: 提供清晰的加载状态、成功/失败提示
- **实时更新**: 使用 SSE 或 WebSocket 实现实时日志流和状态更新

### 组件设计细节

#### 1. 状态指示器
- 🟢 运行中/成功
- 🔴 停止/失败
- 🟡 等待中/警告
- ⚪ 未执行

#### 2. 实时日志查看器（LogViewer.tsx）
- 支持自动滚动到底部
- 支持手动滚动查看历史
- 支持搜索和过滤（按关键字、日志级别）
- 支持日志级别颜色标记（ERROR红色、WARN黄色、INFO蓝色）
- 支持复制日志内容
- 支持下载日志文件

#### 3. 执行历史列表（ExecutionHistory.tsx）
- 表格展示：时间、脚本名称、执行者、状态、执行时长、操作
- 支持筛选：按时间范围、脚本、执行者、状态
- 支持排序：按时间、状态、执行时长
- 支持分页
- 点击查看详情，弹出模态框显示完整信息

#### 4. 确认对话框
- 高风险操作（生产部署、数据库恢复）显示警告样式
- 要求输入确认文字（如"确认部署"）
- 显示操作影响范围

#### 5. 响应式设计
- 移动端：单列布局，Tab 导航改为下拉菜单
- 平板：两列布局
- 桌面：多列布局，充分利用屏幕空间

## 集成点

### 与现有脚本集成

- 不修改现有脚本
- 通过配置文件定义脚本元数据
- 脚本执行时传递参数和环境变量
- 收集脚本的标准输出和错误输出

### 与现有构建系统集成

- 复用 `scripts/build/` 目录下的构建脚本
- 复用构建配置（`build-config.yml`）
- 复用构建缓存机制

### 与现有部署系统集成

- 复用 `deploy/` 目录下的部署脚本
- 复用部署配置
- 复用环境变量配置

## 性能考虑

1. **异步执行**: 脚本执行采用异步方式，避免阻塞请求
2. **日志流**: 使用 SSE 或 WebSocket 实现实时日志流
3. **日志存储**: 大日志文件存储在文件系统，数据库只存储元数据
4. **历史记录分页**: 执行历史记录支持分页查询
5. **缓存**: 脚本列表和配置信息可以缓存

## 安全考虑

1. **权限控制**: 严格的权限验证，防止未授权操作
2. **命令注入防护**: 参数验证和转义
3. **环境隔离**: 生产环境操作需要额外确认
4. **审计日志**: 完整的操作审计记录
5. **资源限制**: 脚本执行资源限制（CPU、内存、时间）

## 监控和告警

1. **执行监控**: 监控脚本执行状态和性能
2. **失败告警**: 脚本执行失败时发送告警
3. **资源监控**: 监控服务器资源使用情况
4. **定时任务监控**: 监控定时任务执行情况
