# Design: 优化Mobile端UX体验

## Context

当前Mobile版本存在多个严重的UX问题，包括TabBar遮挡、导航失效、登录页面比例不协调等。需要建立统一的Mobile UX规范，并修复现有问题。

## Goals

1. **修复严重问题**: 解决TabBar遮挡、导航失效等影响核心功能的问题
2. **建立UX规范**: 制定完整的Mobile UX设计规范
3. **统一视觉风格**: 实现扁平化、简洁、科技感的设计风格
4. **提升用户体验**: 确保所有页面提供流畅、一致的体验

## Non-Goals

- 不重构整个Mobile架构（在现有架构基础上优化）
- 不改变核心功能逻辑（只优化UI/UX）
- 不强制所有页面立即符合规范（渐进式改进）
- **不改动 `MobileConnectionSpaceScreen`（心域连接星空页面）的视觉设计和交互体验**：该页面的星空动画、布局和视觉风格已经比较满意，只修复TabBar遮挡等技术问题，保持现有设计不变

## Decisions

### 决策1：TabBar遮挡问题解决方案
**决定**: 使用统一的底部内边距和安全区域适配

**理由**:
- TabBar高度固定（约64px + 安全区域）
- 所有页面内容区域需要预留底部空间
- 使用CSS变量或Tailwind类统一管理

**实现方式**:
```css
/* 内容区域统一使用 */
.content-area {
  padding-bottom: calc(64px + env(safe-area-inset-bottom));
}

/* 或使用Tailwind */
pb-[calc(4rem+env(safe-area-inset-bottom))]
```

### 决策2：导航功能修复策略
**决定**: 统一导航状态管理，修复路由和状态同步问题

**理由**:
- 当前导航状态可能未正确同步
- 需要确保TabBar点击和返回键都能正确工作

**实现方式**:
- 检查导航状态管理逻辑
- 确保路由和状态同步
- 添加导航历史管理

### 决策3：设计风格定位
**决定**: 扁平化、简洁、科技感

**具体表现**:
- **扁平化**: 
  - 减少阴影层级（使用subtle shadow）
  - 简化视觉层次
  - 使用纯色和渐变，避免3D效果
- **简洁**:
  - 充足的留白
  - 清晰的视觉层次
  - 减少装饰性元素
- **科技感**:
  - 使用渐变背景（from-indigo-600 to-purple-600）
  - 使用毛玻璃效果（backdrop-blur）
  - 使用柔和的发光效果（shadow-purple-500/30）

### 决策4：按钮尺寸规范
**决定**: 遵循iOS和Material Design规范，最小触摸目标44x44px

**理由**:
- iOS HIG要求最小44x44px
- Material Design要求最小48x48px
- 44x44px是移动端通用标准

**实现方式**:
- 主要按钮：高度48-56px
- 次要按钮：高度44px
- 图标按钮：最小44x44px
- 使用Tailwind类：`min-w-[44px] min-h-[44px]`

### 决策5：安全区域适配
**决定**: 统一使用env()函数处理安全区域

**理由**:
- iOS设备有刘海屏和底部指示器
- Android设备也有不同的安全区域
- 需要统一处理

**实现方式**:
- 顶部：`pt-[calc(1rem+env(safe-area-inset-top))]`
- 底部：`pb-[calc(1rem+env(safe-area-inset-bottom))]`
- 左右：`pl-[env(safe-area-inset-left)]` / `pr-[env(safe-area-inset-right)]`

### 决策6：MobileConnectionSpaceScreen特殊处理
**决定**: 保持 `MobileConnectionSpaceScreen`（心域连接星空页面）的现有视觉设计和交互体验，只修复技术问题

**理由**:
- 用户对该页面的星空动画和视觉效果比较满意
- 该页面的设计已经符合"科技感"的定位
- 只需要修复TabBar遮挡等技术问题，不需要改变视觉设计

**实现方式**:
- 检查并修复TabBar遮挡问题（添加底部内边距）
- 检查并修复安全区域适配问题
- 保持现有的Canvas星空动画逻辑不变
- 保持现有的布局和视觉风格不变
- 保持现有的交互逻辑不变

## Risks / Trade-offs

### 风险1：影响现有功能
**风险**: 修复布局问题可能影响现有功能

**缓解措施**:
- 充分测试所有页面
- 渐进式修复，逐个页面验证
- 保留原有功能逻辑

### 风险2：性能影响
**风险**: 添加安全区域计算可能影响性能

**缓解措施**:
- 使用CSS变量缓存计算结果
- 避免重复计算
- 使用Tailwind的JIT编译优化

### 风险3：兼容性问题
**风险**: 不同设备的安全区域不同

**缓解措施**:
- 使用env()函数自动适配
- 提供fallback值
- 在多种设备上测试

## Migration Plan

1. **阶段1**: 建立Mobile UX规范文档
2. **阶段2**: 修复TabBar遮挡问题（所有页面）
3. **阶段3**: 修复导航功能问题
4. **阶段4**: 优化登录页面
5. **阶段5**: 统一视觉风格（渐进式改进）
