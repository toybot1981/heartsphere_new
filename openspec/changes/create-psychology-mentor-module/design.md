# Design: Psychology Mentor Module

## Context

当前系统已有：
1. **多个独立模块**：main、mentis、edu、company、admin，每个模块都有独立的业务定位
2. **mentis模块**：超级智能体模块，端口8082，专注于Computer-Use能力
3. **心理健康支持系统提案**：计划在main项目中构建心理健康支持场景，需要专业治疗能力
4. **文档存在但代码缺失**：`docs/03-心理导师系统/` 下有详细的功能文档，但代码未实现

**用户需求**：
- 需要专业的心理治疗功能
- 支持5种主流治疗流派
- 提供智能会话管理和疗法推荐
- 包含丰富的临床案例和知识库

## Goals / Non-Goals

### Goals

**模块独立性**：
- 创建与mentis平级的独立模块
- 拥有独立的后端和前端服务
- 拥有独立的数据库和端口配置
- 遵循项目现有的技术栈和架构模式

**专业治疗功能**：
- 支持5种主流心理治疗流派（CBT、DBT、ACT、心理动力学、人本主义）
- 提供专业的治疗会话管理（诊前评估、实时对话、会话总结）
- 实现智能的疗法推荐功能
- 提供丰富的临床案例库（17个案例）

**知识库系统**：
- 构建深度心理学知识库
- 支持生成1000+字的专业学术解析
- 包含治疗理论、干预技术、案例库等内容

**AI对话能力**：
- 集成AI模型（通义千问等）
- 实现流式对话响应
- 支持心理学事实提取（情绪模式、认知扭曲、应对策略）

### Non-Goals

- 不实现完整的电子病历系统（初期版本）
- 不实现跨机构的角色协作（初期版本仅限系统内）
- 不实现复杂的心理评估和诊断功能（初期版本聚焦支持而非诊断）
- 不实现实时视频或语音治疗（初期版本聚焦文本交互）
- 不替代专业心理治疗师或精神科医生（系统提供支持，但不进行诊断）

## Decisions

### Decision 1: 模块结构设计
**What**: 创建与mentis平级的独立模块，采用相同的前后端分离架构

**Rationale**:
- mentis模块已证明独立模块架构的可行性
- 保持项目结构一致性，便于维护
- 独立部署和扩展，不影响其他模块

**Alternatives considered**:
- 集成到main项目：会增加main项目的复杂度，不利于独立部署
- 集成到mentis模块：业务定位不同，不应该混合

**Implementation**:
- 创建 `psychology-mentor/` 目录
- 后端：Spring Boot应用，包名 `com.heartsphere.psychology`
- 前端：React + TypeScript + Vite应用
- 端口：后端8083，前端3003（避免与mentis的8082/3002冲突）

### Decision 2: 数据库设计
**What**: 使用独立数据库 `heartsphere_psychology`，采用MySQL存储结构化数据，Redis存储短期记忆，MongoDB存储长期记忆

**Rationale**:
- 独立数据库便于数据管理和隐私保护
- MySQL适合存储结构化数据（疗法、案例、会话记录等）
- Redis适合存储短期记忆（会话上下文）
- MongoDB适合存储长期记忆（用户画像、心理学事实等）

**Alternatives considered**:
- 共享数据库：不利于数据隔离和隐私保护
- 仅使用MySQL：无法满足记忆系统的需求

**Implementation**:
- 创建独立数据库 `heartsphere_psychology`
- 使用Flyway进行数据库迁移
- 配置Redis和MongoDB连接

### Decision 3: 技术栈选择
**What**: 使用与mentis相同的技术栈（Spring Boot 3.2.0、React 18+、TypeScript等）

**Rationale**:
- 保持技术栈一致性，降低学习成本
- 复用shared模块，减少重复代码
- 遵循项目规范

**Implementation**:
- 后端：Spring Boot 3.2.0 + Java 17
- 前端：React 18+ + TypeScript + Vite
- 数据库：MySQL 8.0+、Redis、MongoDB
- AI集成：Spring AI（支持通义千问等）

### Decision 4: API设计
**What**: 设计RESTful API，遵循项目API规范，支持与其他模块集成

**Rationale**:
- RESTful API是标准化的接口设计
- 便于与其他模块（如main项目的心理健康支持系统）集成
- 支持未来扩展

**Implementation**:
- API路径前缀：`/api/psychology/`
- 使用SpringDoc OpenAPI生成API文档
- 遵循项目的统一响应格式

### Decision 5: 与心理健康支持系统的集成
**What**: 通过HTTP API集成，保持系统独立性

**Rationale**:
- 保持系统独立性，便于独立部署和维护
- 通过API集成，降低耦合度
- 符合项目架构原则（项目间通过HTTP通信）

**Implementation**:
- 提供完整的RESTful API
- main项目的心理健康支持系统通过HTTP调用心理导师系统
- 支持将治疗师包装为Agent，参与多智能体协作

## Risks / Trade-offs

### Risk 1: 数据库设计复杂度
**风险**: 需要设计多个表，关系复杂

**缓解措施**:
- 参考现有文档中的数据库设计
- 使用Flyway进行版本管理
- 分阶段实现，先实现核心表

### Risk 2: AI模型集成
**风险**: AI模型调用可能不稳定，影响用户体验

**缓解措施**:
- 实现重试机制
- 实现降级方案
- 监控API调用情况

### Risk 3: 数据隐私和安全
**风险**: 心理健康数据高度敏感，需要严格的隐私保护

**缓解措施**:
- 使用独立数据库，数据隔离
- 实现数据加密
- 符合相关隐私法规要求
- 提供数据删除和导出功能

### Risk 4: 专业知识准确性
**风险**: 知识库内容不准确或过时，可能导致提供错误建议

**缓解措施**:
- 知识库内容来源权威（心理学教材、专业期刊、治疗手册等）
- 建立内容审核机制
- 明确说明这是支持而非诊断
- 设置免责声明

## Migration Plan

### Phase 1: 基础框架搭建（1-2天）
1. 创建目录结构
2. 配置后端Spring Boot应用
3. 配置前端React应用
4. 配置数据库连接

### Phase 2: 数据库设计和迁移（2-3天）
1. 设计数据库表结构
2. 创建Flyway迁移脚本
3. 初始化种子数据（5种疗法、17个案例等）
4. 测试数据库迁移

### Phase 3: 后端核心服务实现（3-4天）
1. 实现实体类和Repository
2. 实现Service层（疗法服务、会话服务等）
3. 实现Controller层（REST API）
4. 实现AI对话服务

### Phase 4: 前端界面实现（3-4天）
1. 实现疗法选择界面
2. 实现会话界面
3. 实现案例库界面
4. 实现用户画像界面

### Phase 5: AI功能和知识库（3-4天）
1. 集成AI模型（Spring AI）
2. 实现流式对话响应
3. 实现心理学事实提取
4. 实现知识库生成功能

### Phase 6: 测试和文档（2-3天）
1. 单元测试
2. 集成测试
3. API文档
4. 用户文档
