# Change: 增强技能应用与调试体系

## Why

当前系统拥有完整的技能定义与管理框架，但缺少以下关键能力：

1. **技能应用引擎缺陷**：角色在与用户对话时，技能的激活、选择、执行过程缺乏清晰的执行逻辑和优先级管理
2. **调试可见性不足**：开发者无法看到技能被激活的原因、时机和执行结果，导致调试困难
3. **用户体验缺陷**：用户不了解AI何时使用了技能以及为什么使用该技能，缺乏透明的反馈机制
4. **记忆与技能协同不足**：技能应用与记忆管理缺乏良好的集成，无法基于对话历史动态调整技能使用策略

## What Changes

### 后端变更
1. **技能应用引擎** - 在对话处理过程中实现智能的技能选择与应用流程
   - 实现技能评分机制：根据对话内容、上下文、用户历史评估技能匹配度
   - 实现技能优先级管理：管理多个技能的竞争与选择
   - 实现技能执行跟踪：记录技能被激活、执行、完成的全过程
   - **BREAKING**: 修改 AI 响应处理流程，集成技能应用引擎

2. **技能执行记录** - 持久化保存技能应用的完整生命周期
   - 记录技能激活原因、参数、执行结果
   - 支持查询技能执行历史与分析统计

3. **技能调试服务** - 提供实时调试数据接口
   - 提供技能激活状态查询
   - 提供技能执行过程追踪
   - 提供内存监控和分析数据

### 前端变更
1. **技能调试框** - 在聊天窗口中增加技能调试面板
   - 实时显示当前会话中被激活的技能及其激活原因
   - 显示技能执行状态（待激活、执行中、已完成、失败）
   - 显示技能参数和执行结果
   - 支持展开/折叠查看详细信息
   - 与记忆调试框并列显示

2. **技能选择透明化** - 在对话中显示技能应用情况
   - 在 AI 响应中标记使用的技能
   - 显示技能使用的原因和相关参数
   - 支持用户反馈技能选择是否恰当

3. **记忆-技能关联显示** - 展示技能应用与记忆系统的协同
   - 显示对话中哪些记忆触发了技能应用
   - 显示技能应用后对记忆系统的影响

## Impact

- **Affected specs**: 
  - 新增: `skill-application-engine` (技能应用引擎)
  - 修改: `skill-system` (技能系统 - 扩展执行记录)
  - 新增: `skill-debugging` (技能调试)
  - 修改: `chat-window` (聊天窗口 - 增加调试框)
  - 修改: `memory-system` (记忆系统 - 增加关联追踪)

- **Affected code**:
  - 后端: `main/backend/src/main/java/com/heartsphere/ai/` - AI 处理核心
  - 后端: 新增技能应用引擎模块
  - 后端: 新增技能执行记录表与 API
  - 前端: `main/frontend/src/components/ChatWindow.tsx` - 聊天窗口
  - 前端: 新增调试框组件
  - 前端: 新增技能执行追踪 Hook

- **Database**: 新增 `skill_execution_records` 表用于记录技能执行历史

- **Breaking Changes**: 
  - AI 响应处理流程修改（需要更新依赖的服务调用方）
  - 聊天记录数据结构修改（需要增加技能应用元数据字段）
