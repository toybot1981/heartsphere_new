#### 容量规划
```

年增长量: 100 万 × 100 × 365 = 36.5 亿 条记录
表大小: ~500 GB/年（每条记录 ~150 字节）

建议：
- 1 年后进行归档（移到归档表或数据仓库）
- 3 年内可能需要分表处理
```

  - 建议实现自动归档机制

- 🟡 **中风险**: 备份体积增加
  - JSON 字段会增加备份大小
  - 建议采用增量备份策略

#### 建议
- ⚠️ **需要改进** - 缺少容量规划和分表策略
- 📌 **关键需求**：
  - [ ] 明确记录保留期（建议 90 天）
  - [ ] 设计自动归档机制
  - [ ] 制定分表计划（基于 conversation_id 或 user_id）
