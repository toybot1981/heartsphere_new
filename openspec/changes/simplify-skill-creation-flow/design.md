# Design: 简化技能创建流程

## 架构设计

### 创建方式选择

用户打开 Skill Creator 时，首先看到一个选择界面，提供三种创建方式：

```
┌─────────────────────────────────────┐
│   专业技能创建器                    │
├─────────────────────────────────────┤
│                                     │
│  ┌──────────┐  ┌──────────┐        │
│  │ AI生成   │  │ 文件导入 │        │
│  │ (推荐)   │  │          │        │
│  └──────────┘  └──────────┘        │
│                                     │
│  ┌──────────┐                      │
│  │ 手动编辑 │                      │
│  └──────────┘                      │
│                                     │
└─────────────────────────────────────┘
```

### 方式1: AI自动生成（首选）

**流程**：
1. 用户输入自然语言描述（例如："创建一个天气查询技能，可以查询指定城市的天气情况"）
2. 系统调用AI服务，生成完整的技能定义
3. 显示生成结果，允许用户编辑和调整
4. 用户确认后保存

**技术实现**：
- 前端：提供文本输入框，调用后端API
- 后端：构建提示词，调用 AI 服务（`/api/ai/text/generate`），解析返回的JSON/YAML格式技能定义
- AI提示词模板：包含技能定义的结构化要求，引导AI生成符合规范的技能

**示例提示词**：
```
你是一个技能创建助手。根据用户的描述，生成一个完整的技能定义（JSON格式）。

技能定义应包含以下字段：
- skillId: 技能唯一标识（小写字母、数字、连字符，1-64字符）
- name: 技能名称
- description: 技能描述
- category: 技能分类（UTILITY/HEALTHCARE/EDUCATION/SOCIAL/CREATIVE等）
- skillType: 技能类型（ACTIVE/PASSIVE/AUTOMATIC）
- instruction: 详细的技能指令（Markdown格式）
- mcpToolConfig: MCP工具配置（如果需要工具调用）
- executionConfig: 执行配置
- license: 许可证信息
- version: 版本号

用户描述：{userDescription}

请生成完整的技能定义JSON。
```

### 方式2: 文件导入（次选）

**流程**：
1. 用户选择导入方式：
   - 方式A：上传 skill.md 文件
   - 方式B：直接粘贴 md 内容
2. 系统解析内容（YAML front matter + Markdown 指令）
3. 自动填充表单字段
4. 用户检查和编辑
5. 保存

**技术实现**：
- 前端：
  - 文件上传组件，支持拖拽上传和点击选择
  - 文本输入框，支持粘贴 md 内容（大文本区域，支持 Markdown 预览）
  - 两种方式可以切换
- 后端：解析 YAML front matter 和 Markdown 内容，映射到技能定义字段
- 解析逻辑：
  - 提取 YAML front matter（在 `---` 之间的内容）
  - 提取 Markdown 指令部分（YAML 之后的内容）
  - 映射字段：`skill_id` -> `skillId`, `name` -> `name`, 等

**UI设计**：
```
┌─────────────────────────────────────┐
│   文件导入                           │
├─────────────────────────────────────┤
│  [上传文件] [粘贴内容]  ← 标签切换   │
│                                     │
│  ┌─────────────────────────────┐   │
│  │  拖拽文件到此处或点击选择    │   │
│  │  支持 .md 文件，最大 1MB     │   │
│  └─────────────────────────────┘   │
│                                     │
│  或                                │
│                                     │
│  ┌─────────────────────────────┐   │
│  │  粘贴 skill.md 内容：        │   │
│  │  ┌─────────────────────────┐ │   │
│  │  │ ---                    │ │   │
│  │  │ skill_id: ...          │ │   │
│  │  │ ...                    │ │   │
│  │  │ ---                    │ │   │
│  │  │                        │ │   │
│  │  │ # 技能说明             │ │   │
│  │  │ ...                    │ │   │
│  │  └─────────────────────────┘ │   │
│  │  [预览] [解析]              │   │
│  └─────────────────────────────┘   │
│                                     │
│  📋 格式示例                        │
│  💾 下载模板                        │
└─────────────────────────────────────┘
```

**文件格式示例**：
```markdown
---
skill_id: weather-query
name: 天气查询
description: 查询指定城市的天气情况
category: UTILITY
skill_type: ACTIVE
license: MIT
version: 1.0.0
---

# 天气查询技能

## 功能说明
查询指定城市的当前天气情况。

## 使用方法
用户说："查询北京的天气"
```

### 方式3: 手动编辑（最后）

**优化点**：
- 保留现有的分步骤流程
- 为每个字段提供详细的 placeholder 和示例
- 添加字段说明和最佳实践提示
- 支持从 AI 生成或文件导入的结果继续编辑

**改进示例**：
```typescript
<TextInput
  label="技能ID *"
  placeholder="例如: weather-query, todo-manager, image-generator"
  helperText="只能包含小写字母、数字和单连字符，1-64字符。建议使用描述性的名称，如 'weather-query' 而不是 'skill1'"
/>
```

## 数据流

### AI生成流程
```
用户输入描述 
  → 前端调用 /api/admin/skills/creator/generate-from-description
  → 后端构建提示词
  → 调用 AI 服务 (/api/ai/text/generate)
  → 解析 AI 返回的 JSON
  → 验证和规范化
  → 返回技能定义
  → 前端显示并允许编辑
```

### 文件导入流程

**方式A：上传文件**
```
用户选择文件
  → 前端读取文件内容
  → 前端调用 /api/admin/skills/creator/parse-from-md
  → 后端解析 YAML + Markdown
  → 映射到技能定义字段
  → 验证和规范化
  → 返回技能定义
  → 前端填充表单
```

**方式B：粘贴内容**
```
用户粘贴 md 内容
  → 用户点击"解析"按钮
  → 前端调用 /api/admin/skills/creator/parse-from-md（传递文本内容）
  → 后端解析 YAML + Markdown
  → 映射到技能定义字段
  → 验证和规范化
  → 返回技能定义
  → 前端填充表单
```

**API设计**：
```typescript
// 请求体支持两种格式
interface ParseFromMdRequest {
  // 方式A：上传文件
  file?: File;
  
  // 方式B：粘贴内容
  content?: string;
}
```

## 技术考虑

### AI服务调用
- Admin 模块需要能够调用 AI 服务
- 如果 admin 模块无法直接访问 main 模块的 AI 服务，可以考虑：
  1. 在 admin 模块中集成 AI 服务客户端
  2. 通过 HTTP 调用 main 模块的 AI 服务接口
  3. 创建共享的 AI 服务模块

### 错误处理
- AI生成失败：提供重试机制，允许用户修改描述后重新生成
- 文件解析失败：显示具体错误信息，提示用户检查文件格式
- 字段验证：在AI生成和文件导入后，进行完整的字段验证

### 性能优化
- AI生成可能需要较长时间，使用流式响应或进度提示
- 文件解析应该快速完成，对于大文件进行大小限制

## 向后兼容

- 保留现有的手动编辑流程，作为"方式3"
- 现有的模板选择功能可以保留，作为手动编辑的辅助功能
- 现有的验证和质量分析功能继续使用
