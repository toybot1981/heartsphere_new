## ADDED Requirements

### Requirement: 技能创建方式选择
系统 SHALL 在技能创建器启动时提供三种创建方式供用户选择，按优先级排序：AI自动生成（首选）、文件导入（次选）、手动编辑（最后）。

#### Scenario: 用户选择创建方式
- **WHEN** 管理员打开技能创建器
- **THEN** 系统显示创建方式选择界面
- **AND** 系统提供三个选项：
  - **AI自动生成**（标记为推荐）：通过自然语言描述自动生成技能
  - **文件导入**：上传 skill.md 文件自动解析
  - **手动编辑**：分步骤手动填写表单
- **AND** 系统为每个选项提供简要说明和推荐提示
- **AND** 用户选择任一方式后，系统进入对应的创建流程

### Requirement: AI自动生成技能
系统 SHALL 支持用户输入自然语言描述，通过AI服务自动生成完整的技能定义。

#### Scenario: 通过描述生成技能
- **WHEN** 用户选择"AI自动生成"方式
- **THEN** 系统显示描述输入界面
- **AND** 用户输入技能描述（例如："创建一个天气查询技能，可以查询指定城市的天气情况"）
- **AND** 用户点击"生成"按钮
- **THEN** 系统调用AI服务，生成完整的技能定义
- **AND** 系统显示生成进度提示
- **AND** 生成完成后，系统显示生成的技能定义（包括基础信息、指令、MCP配置等）
- **AND** 用户可以在生成结果的基础上进一步编辑和调整
- **AND** 用户确认后，系统保存技能定义

#### Scenario: AI生成内容验证
- **WHEN** AI生成技能定义后
- **THEN** 系统自动验证生成内容的格式和完整性
- **AND** 系统检查必需字段是否已生成（skillId, name, description等）
- **AND** 系统验证字段格式是否符合规范（skillId格式、描述长度等）
- **AND** 如果验证失败，系统显示错误信息并允许用户修改描述后重新生成
- **AND** 如果验证通过，系统允许用户继续编辑或直接保存

#### Scenario: AI生成失败处理
- **WHEN** AI生成过程中发生错误
- **THEN** 系统显示友好的错误提示
- **AND** 系统提供重试机制，允许用户修改描述后重新生成
- **AND** 系统提供切换到手动编辑模式的选项

### Requirement: 文件导入技能
系统 SHALL 支持用户通过上传 skill.md 文件或直接粘贴 md 内容，自动解析并填充技能定义表单。

#### Scenario: 上传 skill.md 文件
- **WHEN** 用户选择"文件导入"方式
- **THEN** 系统显示文件导入界面，提供两种导入方式：
  - **方式A**：上传文件（支持拖拽上传和点击选择）
  - **方式B**：粘贴内容（大文本输入框）
- **AND** 用户选择"上传文件"方式
- **AND** 用户上传 skill.md 文件
- **THEN** 系统解析文件内容：
  - 提取 YAML front matter（在 `---` 之间的内容）作为元数据
  - 提取 Markdown 指令部分（YAML 之后的内容）作为指令
  - 映射字段（skill_id -> skillId, skill_type -> skillType 等）
- **AND** 系统自动填充表单字段
- **AND** 用户可以在填充结果的基础上进一步编辑
- **AND** 用户确认后，系统保存技能定义

#### Scenario: 粘贴 md 内容
- **WHEN** 用户选择"文件导入"方式
- **THEN** 系统显示文件导入界面，提供两种导入方式
- **AND** 用户选择"粘贴内容"方式
- **AND** 用户粘贴 skill.md 的完整内容到文本输入框
- **THEN** 系统解析粘贴的内容：
  - 提取 YAML front matter（在 `---` 之间的内容）作为元数据
  - 提取 Markdown 指令部分（YAML 之后的内容）作为指令
  - 映射字段（skill_id -> skillId, skill_type -> skillType 等）
- **AND** 系统自动填充表单字段
- **AND** 用户可以在填充结果的基础上进一步编辑
- **AND** 用户确认后，系统保存技能定义

#### Scenario: 导入方式切换
- **WHEN** 用户在文件导入界面
- **THEN** 系统允许用户在"上传文件"和"粘贴内容"两种方式之间切换
- **AND** 切换时，系统清空之前的内容和解析结果
- **AND** 系统提供格式示例和说明，帮助用户理解正确的格式

#### Scenario: 文件格式验证
- **WHEN** 用户上传文件或粘贴内容
- **THEN** 系统验证格式：
  - **文件上传**：文件扩展名必须是 .md，文件大小不超过限制（例如：1MB）
  - **粘贴内容**：内容长度不超过限制（例如：100KB）
  - 内容必须包含有效的 YAML front matter（以 `---` 开始和结束）
  - YAML front matter 必须包含必需字段（至少 skill_id 或 name）
- **AND** 如果格式不符合要求，系统显示错误信息并提示用户检查格式
- **AND** 系统提供文件格式示例和模板下载
- **AND** 系统在文本输入框中提供格式提示和示例

#### Scenario: 文件解析错误处理
- **WHEN** 文件或内容解析过程中发生错误
- **THEN** 系统显示具体的错误信息（例如：YAML格式错误、缺少必需字段、文件读取失败等）
- **AND** 系统提供部分解析结果（如果可能）
- **AND** 系统高亮显示错误位置（对于粘贴内容，可以定位到具体行）
- **AND** 系统允许用户修改后重新解析
- **AND** 系统允许用户切换到手动编辑模式继续完成

### Requirement: 手动编辑模式优化
系统 SHALL 优化现有的手动编辑流程，为每个字段提供详细的 placeholder 和示例。

#### Scenario: 改进的表单字段
- **WHEN** 用户选择"手动编辑"方式
- **THEN** 系统显示分步骤的表单界面
- **AND** 每个输入字段都包含：
  - 详细的 placeholder（例如："例如: weather-query, todo-manager"）
  - 字段说明和格式要求
  - 最佳实践提示（例如："建议使用描述性的名称，如 'weather-query' 而不是 'skill1'"）
- **AND** 系统提供字段示例和参考链接
- **AND** 用户可以从AI生成或文件导入的结果继续编辑

#### Scenario: 智能提示和验证
- **WHEN** 用户在手动编辑模式下输入内容
- **THEN** 系统实时验证输入格式
- **AND** 系统显示字段级别的错误和警告
- **AND** 系统提供智能提示（例如：根据已输入的内容建议分类、类型等）
- **AND** 系统在用户输入时提供自动完成建议（如果适用）

## MODIFIED Requirements

### Requirement: 技能创建流程入口
系统 SHALL 在技能创建器启动时首先显示创建方式选择界面，而不是直接进入模板选择步骤。

#### Scenario: 创建流程入口变更
- **WHEN** 管理员打开技能创建器
- **THEN** 系统首先显示创建方式选择界面（AI生成/文件导入/手动编辑）
- **AND** 用户选择创建方式后，系统进入对应的创建流程
- **AND** 如果用户选择手动编辑，系统显示原有的模板选择步骤（可选）
- **AND** 如果用户选择AI生成或文件导入，系统跳过模板选择步骤
