# Design: 系统化提升角色能力体系

## Context

### 模块架构决策

**角色能力体系作为独立模块**：`com.heartsphere.capability`

**理由**：
- 功能完整，有独立的数据模型和业务逻辑
- 符合现有模块组织原则（类似 `skill`、`memory`、`multiagent`）
- 便于维护和扩展
- 通过事件驱动和 ID 关联保持模块独立性

**模块组织原则**：
- 独立包结构：`com.heartsphere.capability`
- 不建立 JPA 关系，只通过 ID 关联其他模块实体
- 通过事件驱动和服务接口集成其他模块
- 保持其他模块的独立性（不反向依赖）

详细架构设计见 `MODULE_ARCHITECTURE.md`。

### 现有系统

当前系统已经具备了多个支撑角色能力的核心系统，但它们相对独立：

1. **技能系统** (`skill-system`)
   - 完整的技能定义、执行、应用引擎
   - 技能评分和选择机制
   - 技能执行记录和调试

2. **记忆系统** (`memory-system`)
   - 多主体记忆（用户、角色、参与者）
   - 长期记忆和短期记忆管理
   - 记忆检索和关联

3. **意识系统** (`agent-consciousness`) - 开发中
   - 自我认知、记忆连续性
   - 意图与目标设定
   - 元认知与反思

4. **多智能体协同** (`multi-agent-collaboration`)
   - 基于 AgentScope 的协作框架
   - 任务分解和路由
   - 智能体间通信

5. **导师/挚友系统** (`character-companionship`, `character-mentorship`) - 已实现
   - 关系阶段系统：STRANGER → FRIEND → CLOSE_FRIEND → MENTOR
   - 挚友能力系统：情感连接、陪伴支持
   - 导师能力系统：主动指导、个性化教育
   - 智能模式切换：挚友模式/导师模式

**问题**：
- 这些系统各自工作，缺乏有机整合
- 角色能力无法基于经验持续提升
- 缺乏对角色综合能力的评估和优化
- 不同角色无法形成差异化的能力特征
- **导师/挚友能力与能力体系缺乏整合**：导师能力和挚友能力未纳入统一的能力体系

## Goals / Non-Goals

### Goals

1. **能力整合**：将技能、记忆、意识、协作等能力有机整合，形成统一的能力体系
2. **能力成长**：角色能力应该基于经验持续提升，支持专业化发展
3. **能力协同**：能力之间应该相互促进，产生协同效应
4. **能力评估**：建立多维度能力评估体系，支持能力优化
5. **个性化发展**：不同角色应该形成差异化的能力特征

### Non-Goals

1. **不替代现有系统**：不重构现有技能、记忆、意识系统，而是在它们之上构建整合层
2. **不强制所有角色**：能力成长和个性化是可选的，支持渐进式采用
3. **不过度复杂化**：保持系统简单，避免过度设计

## Decisions

### Decision 1: 能力模型设计

**选择**：采用多维度能力模型，包含技能、记忆、意识、协作、关系五个维度

**理由**：
- 覆盖角色能力的核心方面
- **整合导师/挚友能力**：将现有的导师能力和挚友能力纳入关系维度
- 支持能力的量化评估
- 便于能力的可视化展示

**能力维度**：
- **技能维度**：技能熟练度、成功率、使用频率
- **记忆维度**：记忆质量、检索精度、关联度
- **意识维度**：意识成熟度、自主性、反思能力
- **协作维度**：协作效率、互补性、沟通能力
- **关系维度**：挚友能力、导师能力、关系管理能力

**替代方案**：
- 单一能力值：过于简化，无法反映能力差异
- 更多维度：增加复杂度，收益递减

### Decision 2: 能力协同机制

**选择**：通过事件驱动的协同机制，而非直接耦合

**理由**：
- 保持各系统的独立性
- 降低系统间耦合
- 便于扩展和维护

**实现方式**：
- 技能执行事件 → 触发记忆更新
- 记忆检索事件 → 影响技能选择
- 意识状态变化 → 影响能力使用策略

### Decision 3: 能力成长机制

**选择**：基于经验值的能力成长系统，而非基于学习的模型训练

**理由**：
- 更可控和可解释
- 避免模型训练的复杂性
- 支持实时能力调整

**实现方式**：
- 记录能力使用经验（成功/失败次数、用户反馈等）
- 基于经验值计算能力等级
- 能力等级影响能力效果（如技能成功率、记忆检索精度等）

### Decision 4: 能力评估体系

**选择**：多维度评估 + 自动化优化建议

**理由**：
- 全面了解角色能力状态
- 提供可操作的优化建议
- 支持能力的持续改进

**评估维度**：
- 技能维度：熟练度、成功率、使用频率
- 记忆维度：记忆质量、检索精度、关联度
- 意识维度：成熟度、自主性、反思能力
- 协作维度：协作效率、互补性、沟通能力

### Decision 5: 能力个性化机制

**选择**：基于使用模式学习的个性化，而非预设配置

**理由**：
- 更真实地反映角色的实际能力特征
- 支持角色的自然成长和演化
- 避免过度配置的复杂性

**实现方式**：
- 记录能力使用模式和偏好
- 基于成功率和用户反馈调整偏好
- 支持能力特征的渐进式形成

### Decision 6: 能力可视化设计

**选择**：多层次可视化 + 实时监控 + 调试工具

**理由**：
- 满足不同用户的需求（概览、详情、调试）
- 提供实时反馈和监控
- 支持问题诊断和优化

**可视化层次**：
- 概览层：能力雷达图、成长轨迹
- 详情层：使用统计、协同效果
- 调试层：使用链路、性能分析、优化建议

## Risks / Trade-offs

### Risk 1: 系统复杂度增加

**风险**：整合多个系统可能增加系统复杂度

**缓解措施**：
- 采用事件驱动的松耦合架构
- 保持各系统的独立性
- 提供清晰的API和文档

### Risk 2: 性能影响

**风险**：能力协同和评估可能影响系统性能

**缓解措施**：
- 异步处理能力评估和优化
- 缓存能力评估结果
- 限制评估频率

### Risk 3: 能力成长不平衡

**风险**：某些能力可能过度成长，导致角色能力失衡

**缓解措施**：
- 设置能力成长上限
- 支持能力平衡调整
- 提供能力重置机制

## Migration Plan

### Phase 1: 能力整合框架（3-4周）

1. 创建能力模型和数据结构
2. 实现能力协同引擎（事件驱动）
3. 集成技能、记忆、意识系统的基础协同
4. 提供能力查询API

### Phase 2: 能力成长系统（3-4周）

1. 实现经验值系统
2. 实现能力等级计算
3. 实现能力效果调整
4. 支持专业化发展路径

### Phase 3: 能力评估与优化（2-3周）

1. 实现多维度评估体系
2. 实现自动化优化建议
3. 提供能力优化API
4. 集成到现有系统

### Phase 4: 个性化与可视化（2-3周）

1. 实现个性化系统
2. 创建能力可视化面板
3. 完善调试工具
4. 用户界面集成

### Rollback Plan

- 每个阶段独立部署，支持回滚
- 能力系统作为可选功能，不影响现有系统
- 通过特性开关控制启用/禁用

## Open Questions

1. **能力成长速度**：如何平衡能力成长的速度，避免过快或过慢？
2. **能力上限**：是否需要设置能力上限？如何设置？
3. **能力重置**：是否支持能力重置？在什么情况下需要重置？
4. **跨角色能力共享**：是否支持角色间的能力共享和传承？
5. **能力评估频率**：能力评估应该多久执行一次？实时还是定期？
