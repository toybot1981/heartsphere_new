## ADDED Requirements

### Requirement: 专业 Skill Creator 工具
系统 SHALL 提供专业的技能创建工具，参考 Claude 官方 Skill Creator 规范，帮助管理员创建高质量、结构化的技能定义。

#### Scenario: 管理员使用专业创建器创建技能
- **WHEN** 管理员在技能管理页面点击"专业创建器"按钮
- **THEN** 系统显示分步骤的创建向导界面
- **AND** 系统提供模板选择功能，允许管理员选择技能类型模板
- **AND** 管理员可以按步骤填写技能信息（基础信息、元数据、指令、MCP 工具配置等）
- **AND** 系统实时验证输入内容并显示错误和警告
- **AND** 管理员可以保存草稿并在后续继续编辑
- **AND** 管理员完成所有步骤后，系统生成完整的技能定义并存储到数据库

### Requirement: 技能结构标准化
系统 SHALL 支持 Claude Skills 规范的结构化格式，包括元数据、指令和资源三个层级。

#### Scenario: 技能包含完整的元数据
- **WHEN** 管理员创建技能时填写元数据信息
- **THEN** 系统支持以下元数据字段：
  - **必需字段**：name（技能名称）、description（技能描述，1-1024字符）
  - **可选字段**：license（许可证）、compatibility（兼容性信息，JSON格式）、metadata（自定义元数据，JSON格式）
- **AND** 系统将元数据存储到 `skill_definitions` 表的相应字段
- **AND** 系统支持将完整的 SKILL.md 格式内容存储到 `skill_content` 字段

#### Scenario: 技能支持多层级指令
- **WHEN** 管理员在创建器中编写技能指令
- **THEN** 系统支持 Markdown 格式的指令内容
- **AND** 系统支持多层级指令（Level 1-3），存储在 `skill_instructions` 表
- **AND** 系统提供 Markdown 编辑器，支持语法高亮和预览

#### Scenario: 技能支持资源管理
- **WHEN** 管理员在创建器中添加技能资源
- **THEN** 系统支持上传脚本、参考文档等资源文件
- **AND** 系统将资源信息存储到 `skill_resources` 表
- **AND** 系统支持资源文件的版本管理

### Requirement: 技能验证机制
系统 SHALL 实现多层级验证机制，确保创建的技能符合 Claude Skills 规范和质量要求。

#### Scenario: 格式验证
- **WHEN** 管理员输入技能ID
- **THEN** 系统验证技能ID格式：
  - 长度：1-64字符
  - 格式：小写字母、数字和单连字符（正则：`^[a-z0-9]+(-[a-z0-9]+)*$`）
  - 唯一性：技能ID在系统中必须唯一
- **AND** 如果格式不符合要求，系统显示错误提示并阻止提交

#### Scenario: 描述验证
- **WHEN** 管理员输入技能描述
- **THEN** 系统验证描述长度：1-1024字符
- **AND** 系统分析描述质量（关键词、结构、完整性）
- **AND** 系统显示质量评分和建议改进意见
- **AND** 如果描述不符合要求，系统显示警告或错误

#### Scenario: MCP 工具验证
- **WHEN** 管理员选择 MCP 工具
- **THEN** 系统从已配置且启用的 MCP 服务器中获取可用工具列表
- **AND** 系统验证所选工具是否在可用工具列表中
- **AND** 系统验证所选工具对应的 MCP 服务器是否可用（连接测试）
- **AND** 如果工具不可用或未配置，系统显示错误提示并阻止保存
- **AND** 系统显示工具的描述、参数等信息，帮助管理员选择

#### Scenario: 返回合理性验证
- **WHEN** 管理员完成技能创建
- **THEN** 系统验证技能指令中不包含 FunctionCall 格式的返回
- **AND** 系统检查技能是否返回实际执行结果而非工具调用标记
- **AND** 如果检测到不合理的返回格式，系统显示警告和建议

#### Scenario: 完整性验证
- **WHEN** 管理员尝试完成技能创建
- **THEN** 系统检查所有必需字段是否已填写
- **AND** 系统检查元数据完整性
- **AND** 系统检查指令内容是否为空
- **AND** 如果缺少必需信息，系统显示错误列表并阻止提交

### Requirement: 模板系统
系统 SHALL 提供技能模板库，支持按分类选择模板并快速创建技能。

#### Scenario: 选择模板创建技能
- **WHEN** 管理员在创建器开始时选择模板
- **THEN** 系统显示可用模板列表，按分类组织（UTILITY、HEALTHCARE、EDUCATION等）
- **AND** 管理员可以选择模板并预览模板内容
- **AND** 管理员应用模板后，系统自动填充表单字段（元数据、指令结构、Function Schema示例等）
- **AND** 管理员可以基于模板继续编辑和定制

#### Scenario: 模板内容
- **WHEN** 系统提供技能模板
- **THEN** 每个模板包含：
  - 预填充的元数据（名称、描述、分类等）
  - 指令结构示例（Markdown格式）
  - MCP 工具配置示例
  - 执行配置示例
- **AND** 模板内容符合 Claude Skills 规范

### Requirement: 创建流程管理
系统 SHALL 支持分步骤的创建流程，允许保存草稿和恢复编辑。

#### Scenario: 分步骤创建
- **WHEN** 管理员使用专业创建器
- **THEN** 系统提供以下创建步骤：
  1. 基础信息：技能ID、名称、描述、分类
  2. 元数据配置：许可证、兼容性、版本信息
  3. 指令编写：Markdown格式的指令内容
  4. MCP 工具配置：选择可用的 MCP 工具，配置工具参数
  5. 执行配置：执行类型、配置参数
  6. 资源管理：可选的脚本、参考文档
  7. 预览与验证：最终预览和格式验证
- **AND** 管理员可以在步骤间自由导航
- **AND** 系统显示当前进度和已完成步骤

#### Scenario: 草稿保存和恢复
- **WHEN** 管理员在创建过程中点击"保存草稿"
- **THEN** 系统将当前填写的内容保存为草稿
- **AND** 系统为草稿分配唯一标识
- **AND** 管理员可以在后续时间恢复草稿继续编辑
- **AND** 系统显示草稿列表，支持删除和恢复操作

#### Scenario: 最终生成和存储
- **WHEN** 管理员完成所有步骤并通过验证
- **THEN** 系统生成完整的技能定义：
  - 将表单数据转换为数据库实体
  - 生成完整的 SKILL.md 格式内容（YAML元数据 + Markdown指令）
  - 存储到 `skill_definitions` 表及相关表
- **AND** 系统显示创建成功消息
- **AND** 管理员可以立即在技能管理页面看到新创建的技能

### Requirement: 质量分析和建议
系统 SHALL 提供技能质量分析功能，帮助管理员改进技能描述和内容。

#### Scenario: 描述质量分析
- **WHEN** 管理员输入技能描述
- **THEN** 系统分析描述质量：
  - 检查关键词覆盖度
  - 检查描述结构（是否有明确的功能说明）
  - 检查描述长度是否合适
  - 生成质量评分（0-100分）
- **AND** 系统显示质量报告，包括：
  - 当前评分
  - 改进建议（如"建议添加使用场景说明"）
  - 参考示例

#### Scenario: 内容完整性检查
- **WHEN** 管理员完成技能创建
- **THEN** 系统检查内容完整性：
  - 指令内容是否详细充分
  - MCP 工具配置是否完整
  - 是否缺少重要的元数据
  - 是否有降级方案（如果 MCP 不可用）
- **AND** 系统显示完整性报告和建议

### Requirement: 数据库扩展
系统 SHALL 扩展技能定义表，支持完整的 Claude Skills 元数据字段。

#### Scenario: 新增元数据字段
- **WHEN** 系统执行数据库迁移
- **THEN** `skill_definitions` 表新增以下字段：
  - `license`（VARCHAR(100)）：许可证信息
  - `compatibility`（VARCHAR(255)）：兼容性信息（JSON格式）
  - `metadata`（TEXT）：自定义元数据（JSON格式）
  - `skill_content`（TEXT）：完整的 SKILL.md 格式内容
- **AND** 所有新字段允许为 NULL，保持向后兼容
- **AND** 现有技能数据不受影响

#### Scenario: 数据迁移
- **WHEN** 系统升级到新版本
- **THEN** 现有技能数据自动迁移，新字段初始化为 NULL
- **AND** 系统移除 `function_schema` 字段（如果存在）
- **AND** 系统添加 `mcp_tool_config` 字段（TEXT，JSON格式，存储 MCP 工具配置）
- **AND** 管理员可以通过编辑功能补充新字段内容
- **AND** 系统支持批量更新现有技能，生成 `skill_content` 字段

### Requirement: MCP 工具集成
系统 SHALL 支持技能使用 MCP 协议调用工具，完全移除 Function Calling 支持。

#### Scenario: MCP 工具选择
- **WHEN** 管理员在创建器中配置技能工具
- **THEN** 系统显示所有已配置且启用的 MCP 服务器列表
- **AND** 系统为每个 MCP 服务器显示其提供的可用工具列表
- **AND** 管理员可以选择一个或多个 MCP 工具
- **AND** 系统显示每个工具的描述、参数定义等信息
- **AND** 管理员可以配置工具参数映射和默认值

#### Scenario: MCP 工具可用性验证
- **WHEN** 管理员选择 MCP 工具并尝试保存技能
- **THEN** 系统验证所选工具是否在可用工具列表中
- **AND** 系统测试所选工具对应的 MCP 服务器连接
- **AND** 如果工具不可用或服务器连接失败，系统显示错误并阻止保存
- **AND** 系统显示具体的错误原因（工具不存在、服务器未启用、连接失败等）

#### Scenario: MCP 工具配置存储
- **WHEN** 管理员完成 MCP 工具配置
- **THEN** 系统将 MCP 工具配置存储到 `mcp_tool_config` 字段（JSON格式）
- **AND** 配置包含：
  - MCP 服务器配置ID
  - 工具名称列表
  - 工具参数映射
  - 默认参数值
- **AND** 系统验证 JSON 格式正确性

### Requirement: 技能返回合理性
系统 SHALL 确保技能返回实际执行结果，而非 FunctionCall 格式信息。

#### Scenario: 返回格式验证
- **WHEN** 管理员编写技能指令
- **THEN** 系统检测指令中是否包含 FunctionCall 格式的返回（如 `<|FunctionCallBegin|>`、`<|FunctionCallEnd|>`）
- **AND** 如果检测到 FunctionCall 格式，系统显示警告：
  - "技能不应返回 FunctionCall 格式，应返回实际执行结果"
  - 提供修改建议和示例
- **AND** 系统建议使用 MCP 工具调用，并返回工具执行的实际结果

#### Scenario: 降级方案支持
- **WHEN** 管理员配置技能时，如果某个功能没有对应的 MCP 工具
- **THEN** 系统允许管理员通过自然语言描述的方式定义功能
- **AND** 系统在指令中明确说明：如果 MCP 工具不可用，使用大模型根据描述执行任务
- **AND** 系统验证描述是否清晰、完整，能够指导大模型执行任务
- **AND** 系统在技能元数据中标记该技能支持降级方案

#### Scenario: 执行结果验证
- **WHEN** 技能执行完成后
- **THEN** 系统验证返回结果不包含 FunctionCall 标记
- **AND** 系统验证返回结果是有效的执行结果（非空、格式正确）
- **AND** 如果返回结果不合理，系统记录警告日志
