# Design: 角色长期学习系统架构设计

## Context

### 现状分析

1. **当前记忆系统架构**：
   ```
   会话上下文（Redis）
   ↓
   用户专属记忆（MySQL + HSMem）
        ├─ user_memories 表
        ├─ HSMem 文件系统
        └─ chat_messages 表
   ```
   - 每个角色与每个用户的记忆完全隔离
   - 角色无法从其他用户的对话中学习
   - 记忆没有"质量评估"，缺乏去伪存真的机制

2. **问题**：
   - **信息孤岛**：多个用户与同一角色的对话产生的知识无法共享
   - **重复学习**：相同的知识被反复提取和存储，造成浪费
   - **无法进化**：角色无法通过经验积累变得更聪明
   - **缺乏反馈环**：用户的正面/负面反馈无法帮助角色改进

3. **核心诉求**：
   - 从"个体化"到"共享化"：有些知识应该被所有用户共享
   - 从"被动记忆"到"主动学习"：角色应该主动识别和升级知识
   - 从"静态资产"到"动态进化"：知识应该不断被验证、优化、更新

### 关键概念

**个体记忆 vs 角色资产**：

| 维度 | 个体记忆 | 角色资产 |
|------|---------|---------|
| **所有权** | 用户 A 专有 | 所有用户共享 |
| **内容** | 用户偏好、隐私信息、个人故事 | 通用知识、最佳实践、行业见解 |
| **例子** | "这个用户喜欢午后聊天" | "在讨论财务时应该强调风险管理的重要性" |
| **更新频率** | 较低（用户个性稳定） | 较高（不断验证和优化） |
| **访问权限** | 只有角色与该用户的对话可访问 | 角色所有对话可访问 |

## Goals / Non-Goals

### Goals

1. **实现知识提升机制**：
   - 从单一对话中识别可被升级为"角色资产"的知识
   - 评估知识的通用性和可信度
   - 定期聚合和优化资产

2. **构建角色经验系统**：
   - 追踪角色的学习进度（Level：新手 → 初级 → 中级 → 高级 → 专家）
   - 记录关键学习事件和里程碑
   - 根据资产数量和质量计算经验值

3. **增强 AI 提示词生成**：
   - 在生成 AI 响应时，同时注入用户专属记忆和角色通用资产
   - 动态调整资产的优先级和相关性权重
   - 基于用户反馈不断优化注入策略

4. **提供反馈和优化环路**：
   - 支持用户对 AI 响应的评价（有帮助/没帮助）
   - 将反馈转化为资产的信任度评分
   - 支持管理员或角色创建者审核和编辑资产

### Non-Goals

- 不改变 HSMem 系统的核心架构
- 不重构现有的用户-角色对话系统
- 不实现复杂的自监督学习或深度学习（保持可理解性）
- 不创建角色之间的知识共享（每个角色有独立的资产库）

## Decisions

### Decision 1: 知识资产的分类体系

**选择**：4 类可升级的知识资产

```
角色资产（Character Assets）
├─ Domain Knowledge（领域知识）
│  ├─ 概念解释和定义
│  ├─ 最佳实践
│  └─ 常见陷阱
├─ Interaction Skills（交互技巧）
│  ├─ 高效沟通的方式
│  ├─ 处理敏感话题的技巧
│  └─ 个性化应答模式
├─ Decision Rules（决策规则）
│  ├─ 在特定情景下的推荐行动
│  ├─ 权衡和trade-off指南
│  └─ 问题解决流程
└─ Experience Patterns（经验模式）
   ├─ 成功案例（"当用户问X时，Y策略奏效"）
   ├─ 失败案例（"不应该做什么"）
   └─ 边界情况处理
```

**理由**：
- 覆盖角色学习的主要方面
- 便于分类查询和优先级排序
- 支持细粒度的反馈和改进

### Decision 2: 经验值系统设计

**选择**：基于资产数量和质量的四级系统

```
等级      | 资产数量 | 平均质量分 | 特征
----------|---------|-----------|----------------
新手(L1)  | 0-5     | -         | 学习初期，知识还在积累
初级(L2)  | 6-20    | ≥ 60%     | 有基础知识，但经验不足
中级(L3)  | 21-50   | ≥ 70%     | 知识系统完整，可靠性较高
高级(L4)  | 51-100  | ≥ 80%     | 经验丰富，高度可信
专家(L5)  | >100    | ≥ 85%     | 顶级专家，知识深度和广度
```

**理由**：
- 清晰的里程碑激励角色"成长"
- 质量分评估避免低质量资产堆积
- 用户可直观理解角色的"成熟度"

### Decision 3: 资产升级的触发条件

**选择**：多条件综合判断

一段对话的内容可被升级为资产，需要满足：
1. **通用性**：与用户个人信息无关，对其他用户也有价值
   - 检查：是否包含用户名、隐私、个人偏好等敏感词汇
2. **准确性**：内容在对话中被多次验证或获得用户确认
   - 检查：对话中是否有"对，就是这样"、"完全同意"等确认
3. **新颖性**：不与现有资产重复
   - 检查：语义相似度 < 0.8
4. **可行性**：内容是可以被下一次对话直接应用的
   - 检查：是否包含具体的建议或规则

**理由**：
- 确保升级的资产质量
- 避免隐私泄露
- 减少知识重复和冗余

### Decision 4: 提示词注入策略

**选择**：三层注入优先级

```
优先级   | 注入来源 | 权重 | 用途
---------|---------|------|-----
P0(高)   | 该用户专属记忆 | 100% | 个性化应答
P1(中)   | 角色通用资产（相关性高） | 80% | 提供专业洞察
P2(低)   | 角色通用资产（相关性低） | 50% | 补充背景知识
```

**实现**：
1. 解析用户输入，识别关键话题
2. 查询用户与角色的专属记忆（P0）
3. 查询与话题相关的角色资产（P1、P2）
4. 按优先级排序，限制总 Token 数（如 1000 tokens）
5. 生成包含多层记忆的系统提示词

**理由**：
- 优先保证个性化（用户专属记忆）
- 再提升通用价值（角色资产）
- Token 限制确保效率

### Decision 5: 反馈环和迭代

**选择**：支持用户评分和自动衰减

```
资产生命周期：
  创建 → 使用 → 评价 → 优化 → 再使用 → ...

评价信号：
  - ✓ 有帮助（信任度 +10）
  - ~ 中立（信任度 不变）
  - ✗ 没帮助（信任度 -10，可能标记为需要审核）
  - ⚠️ 有问题（信任度 -20，自动降权）

自动衰减：
  - 未被使用 >30 天的资产，相关性评分自动下降
  - 长期得不到正面评价的资产，可被标记为"待审核"
```

**理由**：
- 持续优化资产质量
- 激励高质量资产的使用
- 及时发现和修复问题资产

## Risks / Trade-offs

### Risk 1: 隐私泄露

**风险**：在提升个体记忆为通用资产时，可能误升包含隐私信息的内容

**缓解**：
- 使用敏感词检测（如用户名、电话、身份证等）
- 语义检测：检查内容是否涉及个人相关的动词（"我"、"我的"等）
- 人工审核机制（特别是早期）

### Risk 2: 资产质量下降

**风险**：升级过量低质量资产会污染角色的知识库

**缓解**：
- 严格的升级条件（见 Decision 3）
- 定期审计资产库，移除低信任度资产
- 提供管理界面让角色创建者手工调整

### Risk 3: 计算和存储成本

**风险**：
- 为每个用户都查询用户记忆 + 角色资产会增加数据库查询
- 存储角色资产库会增加存储需求

**缓解**：
- 使用缓存（Redis）缓存热门资产
- 异步计算资产的相关性评分（不阻塞主流程）
- 定期清理低相关性的旧资产

### Risk 4: 角色个性的模糊化

**风险**：过度依赖共享资产可能使不同角色变得相似

**缓解**：
- 保留角色特有的"个性化表达规则"（如说话风格、偏好等）
- 资产库只存储"内容"，不存储"表达风格"
- 在 prompt engineering 中明确强调角色特点

### Trade-off 1: 隐私 vs 协作学习

**选择倾向**：隐私优先
- 严格的隐私检测，宁可漏升也不乱升
- 用户和角色创建者都应了解哪些知识会被升级

### Trade-off 2: 自动化 vs 人工审核

**选择倾向**：早期以人工为主，后期逐步自动化
- MVP 阶段：所有资产升级都需要管理员确认
- 成熟阶段：根据质量评分自动升级，仅低质量资产需审核

## Open Questions

1. **资产的版本管理**：
   - 是否需要追踪每个资产的演变历史？
   - 如何处理相互矛盾的资产版本？

2. **跨角色的知识共享**：
   - 不同角色之间是否应该共享某些资产？
   - 如何避免一个角色的错误知识影响其他角色？

3. **用户反馈的收集**：
   - 除了"有帮助/没帮助"外，还需要其他类型的反馈吗？
   - 反馈应该是可选的还是强制的？

4. **资产库的规模限制**：
   - 一个角色最多应该存储多少个资产？
   - 当资产库达到上限时，如何处理新的升级请求？

5. **角色创建者的干预**：
   - 角色创建者应该有哪些权限（编辑、删除、禁用资产）？
   - 创建者手工添加的资产如何与自动提升的资产区分？
