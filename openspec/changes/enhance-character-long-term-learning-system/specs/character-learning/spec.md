# Spec Delta: 角色长期学习系统规范

## ADDED Requirements

### Requirement: 角色知识资产管理
系统 SHALL 为每个角色维护一个知识资产库，用于存储从多个用户对话中提升的通用知识。

#### Scenario: 创建角色资产
- **WHEN** 系统检测到一段对话内容满足升级条件（通用性、准确性、新颖性、可行性）
- **THEN** 系统 SHALL 创建一个知识资产，包含：
  - 资产类型（Domain Knowledge/Interaction Skills/Decision Rules/Experience Patterns）
  - 标题和内容摘要
  - 来源对话的引用
  - 初始信任度评分（由升级算法确定）
  - 标记为"待审核"状态

#### Scenario: 管理员审核资产
- **WHEN** 管理员查看待审核的资产列表
- **THEN** 管理员 SHALL 能够：
  - 查看资产的完整内容和来源对话
  - 选择通过审核（标记为"已批准"），此后该资产可被用于 AI 提示词注入
  - 选择拒绝审核（记录拒绝原因），被拒绝的资产可被标记为隐藏或删除

#### Scenario: 查询相关资产
- **WHEN** 生成 AI 响应时需要相关的角色资产
- **THEN** 系统 SHALL：
  - 根据用户输入的关键词，检索与该关键词相关的所有资产
  - 按相关性评分和信任度排序
  - 返回前 N 个资产（如前 3 个，受 Token 预算限制）
  - 资产应该包含信息：标题、摘要、类型、信任度、来源

### Requirement: 经验值和角色等级系统
系统 SHALL 根据角色的知识资产质量和数量，为其分配经验等级（L1-L5），直观反映角色的"成熟度"。

#### Scenario: 计算角色经验等级
- **WHEN** 调用计算角色等级的接口或定期更新统计数据时
- **THEN** 系统 SHALL：
  - 统计该角色的知识资产总数
  - 计算平均信任度（所有资产的信任度均值）
  - 根据下表确定等级：
    | 等级 | 资产数量 | 平均信任度 |
    |------|---------|-----------|
    | L1新手 | 0-5 | - |
    | L2初级 | 6-20 | ≥60% |
    | L3中级 | 21-50 | ≥70% |
    | L4高级 | 51-100 | ≥80% |
    | L5专家 | >100 | ≥85% |
  - 更新角色记录中的 experience_level 字段
  - 如果等级有提升，记录一个"LEVEL_UP"事件到学习历史

#### Scenario: 获取角色学习统计
- **WHEN** 用户查看角色详情页时
- **THEN** 页面 SHALL 显示：
  - 角色的当前经验等级（L1-L5）及对应的文字描述
  - 知识资产总数和各类型分布（如 8 个 Domain Knowledge，5 个 Interaction Skills）
  - 平均信任度百分比
  - 最后学习更新的时间

### Requirement: 多层记忆优先级注入
系统在生成 AI 响应时，MUST 同时注入用户专属记忆和角色通用资产，并按优先级排序。

#### Scenario: 生成 AI 提示词时注入多层记忆
- **WHEN** 调用 generateAIResponse 生成 AI 回复时
- **THEN** 系统 SHALL：
  1. 查询用户与该角色的专属记忆（P0 优先级，权重 100%）
  2. 查询该角色与当前对话主题相关的知识资产（P1 优先级，权重 80%）
  3. 查询相关性较低的知识资产作为补充（P2 优先级，权重 50%）
  4. 按优先级排序，并限制总 Token 数量（如 1000 tokens）
  5. 在系统提示词中清晰标注每层记忆的来源（如 "[用户专属记忆]"、"[角色资产-高相关性]"）
  6. 将多层记忆的完整信息记录到 debugInfo 中，用于后续的反馈分析

#### Scenario: Token 预算不足时的处理
- **WHEN** 多层记忆的总 Token 数超过预设的上限（如 1000 tokens）
- **THEN** 系统 SHALL：
  - 优先保留 P0（用户专属记忆）的内容
  - 逐步移除 P2（低相关性资产）、P1（中等相关性资产）的内容
  - 最终保证用户专属记忆的完整注入

### Requirement: 用户反馈收集和资产优化
系统 SHALL 收集用户对 AI 回复的反馈，并用于更新知识资产的信任度。

#### Scenario: 提交反馈
- **WHEN** 用户看到 AI 回复后，点击"有帮助"或"没帮助"按钮
- **THEN** 系统 SHALL：
  - 记录用户的评价（positive/negative）
  - 识别本次对话中注入了哪些知识资产
  - 可选地让用户提供更详细的反馈说明
  - 将反馈数据提交到后端

#### Scenario: 根据反馈更新资产信任度
- **WHEN** 后端接收到反馈数据时
- **THEN** 系统 SHALL：
  - 确定该反馈涉及的知识资产
  - 更新每个资产的反馈计数（positive_feedback_count / negative_feedback_count）
  - 重新计算信任度评分：
    - 基础分 = (positive_feedback_count - negative_feedback_count) / total_feedback_count * 100
    - 考虑使用次数的衰减权重
  - 如果某个资产连续获得多个负面反馈，自动标记为"需要审核"

#### Scenario: 自动衰减
- **WHEN** 定期运行衰减任务（如每天凌晨 2 点）
- **THEN** 系统 SHALL：
  - 查找 30+ 天未被使用的资产
  - 降低其相关性评分（如每天降低 1-2 分）
  - 长期（如 60 天）未使用且评分过低的资产，可标记为"可删除"状态

### Requirement: 隐私保护和敏感信息检测
系统在将个体记忆升级为角色资产前，MUST 进行隐私检测，确保不泄露用户隐私信息。

#### Scenario: 检测并阻止隐私泄露
- **WHEN** 系统试图将一段对话内容升级为知识资产时
- **THEN** 系统 SHALL：
  - 扫描内容中的敏感词汇（如用户名、电话、邮箱、身份证号、地址、银行卡等）
  - 检测第一人称代词（我、我的、我们）的频繁出现
  - 如果检测到敏感信息，应该：
    - 阻止升级
    - 记录一条"升级失败"的日志，说明原因（如"检测到个人隐私信息"）
    - 不向用户展示失败原因（避免信息泄露）

#### Scenario: 敏感词配置
- **WHEN** 管理员需要自定义敏感词列表
- **THEN** 系统 SHALL：
  - 提供管理界面编辑全局敏感词列表
  - 支持为不同的角色设置角色特定的敏感词（如某些角色可能讨论特定的隐私信息）
  - 立即应用更新，无需重启系统

### Requirement: 知识资产去重
系统 SHALL 检测和处理可能重复或高度相似的知识资产。

#### Scenario: 检测相似资产
- **WHEN** 系统试图创建新的知识资产时
- **THEN** 系统 SHALL：
  - 计算新资产与已有资产的相似度（基于摘要的语义相似性）
  - 如果相似度 > 80%，标记为"高度相似"
  - 在审核界面显示相似的现有资产，帮助审核员判断

#### Scenario: 处理重复资产
- **WHEN** 管理员确认两个资产内容重复
- **THEN** 系统 SHALL：
  - 支持合并两个资产，取信任度较高的版本作为保留版本
  - 支持将一个资产标记为"已过期"，其反馈重定向到新版本
  - 记录合并操作到学习历史

## MODIFIED Requirements

### Requirement: 长期记忆检索和注入（修改）
原规范中的 ChatWindow 记忆检索 SHALL 增强，支持多层记忆的优先级注入。

**修改内容**：
- 原有的"用户与该角色的个体记忆"检索应该保持不变，但标记为 P0（最高优先级）
- 新增"角色的通用知识资产"检索作为 P1、P2 的补充
- 在系统提示词生成时，清晰标注各层记忆的来源和优先级
- 实现 Token 预算管理，确保总 Token 数可控

#### Scenario: 增强的记忆注入流程
- **WHEN** 生成 AI 响应时
- **THEN** 系统 SHALL 按以下顺序构建系统提示词：
  1. 基础系统提示（角色背景、个性等）
  2. 用户专属记忆（P0，个性化应答）
  3. 高相关性的角色资产（P1）
  4. 低相关性的角色资产或补充知识（P2）
  5. 用户当前消息内容
