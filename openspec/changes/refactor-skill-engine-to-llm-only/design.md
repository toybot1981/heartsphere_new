# Design: 重构技能引擎为纯 LLM 驱动

## 架构变更

### 当前架构（需要移除）

```
技能应用流程：
  ├─ LLM 驱动（主要）
  │   ├─ Level 1: 元数据筛选
  │   ├─ Level 2: 指令评估
  │   └─ Level 3: 资源决策
  └─ 规则驱动（降级/备用）
      ├─ 关键词匹配
      ├─ 字符串包含
      └─ 评分机制
```

### 新架构（纯 LLM 驱动）

```
技能应用流程：
  └─ LLM 多阶段发现和调用
      ├─ 阶段1: 技能发现（Discovery）
      │   └─ LLM 分析用户意图，发现可能相关的技能
      ├─ 阶段2: 技能评估（Evaluation）
      │   └─ LLM 深度评估技能适用性和参数
      ├─ 阶段3: 技能选择（Selection）
      │   └─ LLM 选择最合适的技能组合
      └─ 阶段4: 技能执行（Execution）
          └─ LLM 调用技能并处理结果
```

## 代码清理

### 需要删除的类和方法

1. **SkillApplicationEngine**：
   - 删除规则匹配逻辑
   - 删除 `evaluateSkills` 方法中的关键词匹配
   - 删除 `SkillScore` 中的规则评分计算
   - 保留执行记录相关功能（如果需要）

2. **SkillScoringService**：
   - 删除整个类（规则评分不再需要）
   - 或者重构为 LLM 评分的辅助工具

3. **LLMSkillApplicationEngine**：
   - 删除 `fallbackToRuleBased` 方法
   - 删除 `ruleBasedEngine` 字段
   - 删除降级逻辑
   - 简化为纯 LLM 驱动

4. **SkillEngineConfig**：
   - 删除规则驱动引擎的配置
   - 删除降级相关的配置
   - 简化为 LLM 驱动配置

5. **SkillSelectionConfig**：
   - 删除规则驱动配置
   - 只保留 LLM 驱动配置

### 需要更新的类

1. **SkillRegistry**：
   - 删除 `toFunctionDefinitionFromSchema` 方法（处理 function_schema）
   - 只保留 `toFunctionDefinitionFromMcpConfig` 方法
   - 更新查询方法，只返回新格式技能

2. **SkillController**：
   - 删除对 function_schema 的查询和转换
   - 更新 API 文档，说明只支持新格式

3. **CharacterSkillController**：
   - 更新绑定验证，确保只绑定新格式技能

## LLM 多阶段发现和调用

### 阶段1: 技能发现（Discovery）

**目标**：从所有可用技能中发现可能相关的技能

**实现**：
- 输入：用户消息、对话上下文、所有可用技能的元数据（Level 1）
- LLM 提示词：分析用户意图，从技能列表中找出可能相关的技能
- 输出：候选技能列表（带相关性评分）

**提示词示例**：
```
分析用户消息，从以下技能列表中发现可能相关的技能。

用户消息：{userMessage}
对话上下文：{conversationContext}

可用技能：
{skillMetadataList}

请返回JSON格式：
{
  "candidates": [
    {
      "skillId": "...",
      "relevanceScore": 0-100,
      "reason": "为什么这个技能可能相关"
    }
  ]
}
```

### 阶段2: 技能评估（Evaluation）

**目标**：深度评估候选技能的适用性

**实现**：
- 输入：候选技能列表、技能的详细指令（Level 2）
- LLM 提示词：评估每个技能是否真正适合当前场景
- 输出：评估后的技能列表（带置信度评分）

**提示词示例**：
```
评估以下技能是否适合当前场景。

用户消息：{userMessage}
对话上下文：{conversationContext}

候选技能：
{skillInstructionsList}

请返回JSON格式：
{
  "evaluatedSkills": [
    {
      "skillId": "...",
      "confidence": 0-100,
      "applicable": true/false,
      "reason": "评估理由",
      "parameters": {...} // 如果适用，提取参数
    }
  ]
}
```

### 阶段3: 技能选择（Selection）

**目标**：选择最合适的技能组合

**实现**：
- 输入：评估后的技能列表、技能的完整信息（Level 3，包括资源）
- LLM 提示词：选择最合适的技能组合，考虑技能之间的协同
- 输出：最终选择的技能列表和执行顺序

**提示词示例**：
```
从以下评估后的技能中选择最合适的技能组合。

用户消息：{userMessage}
对话上下文：{conversationContext}

评估后的技能：
{skillFullInfoList}

请返回JSON格式：
{
  "selectedSkills": [
    {
      "skillId": "...",
      "priority": 1-10,
      "executionOrder": 1,
      "reason": "选择理由"
    }
  ]
}
```

### 阶段4: 技能执行（Execution）

**目标**：执行选定的技能并处理结果

**实现**：
- 输入：选定的技能、参数、上下文
- 执行：调用 MCP 工具或执行指令
- 输出：执行结果，由 LLM 整合到对话中

## 数据清理

### 旧技能删除策略

1. **识别旧技能**：
   - 使用 `function_schema` 的技能
   - 缺少 `skill_content` 的技能
   - 缺少 `mcp_tool_config` 但需要工具调用的技能

2. **备份数据**：
   - 创建备份表
   - 备份所有旧技能数据
   - 备份角色技能绑定

3. **删除旧技能**：
   - 物理删除旧技能记录
   - 清理相关的绑定记录（如果绑定到已删除的技能）

4. **验证清理**：
   - 确保没有遗留的旧技能
   - 确保所有剩余技能都符合新规范

## 前后端更新

### 后端更新

1. **移除旧格式支持**：
   - 删除所有 `function_schema` 相关的查询和转换
   - 删除规则匹配相关的服务和方法
   - 更新所有 API，只返回新格式技能

2. **简化引擎**：
   - 移除降级机制
   - 移除规则驱动引擎
   - 只保留 LLM 驱动引擎

3. **更新配置**：
   - 移除规则驱动配置
   - 简化配置项

### 前端更新

1. **管理端**：
   - 移除 `functionSchema` 字段的显示和编辑
   - 更新技能列表，只显示新格式技能
   - 更新创建器，只支持新格式

2. **主工程**：
   - 移除对旧格式字段的显示
   - 更新技能管理界面
   - 更新技能详情显示

## 迁移策略

### 阶段1: 数据准备
- 备份所有旧技能
- 识别需要删除的技能
- 生成迁移报告

### 阶段2: 代码更新
- 更新后端代码，移除规则匹配
- 更新前端代码，移除旧格式支持
- 更新配置，移除规则驱动配置

### 阶段3: 数据清理
- 删除所有旧技能
- 清理相关绑定
- 验证数据完整性

### 阶段4: 测试验证
- 测试 LLM 驱动的技能发现和调用
- 验证系统功能正常
- 性能测试

## 向后兼容性

**注意**：此变更不保持向后兼容，因为：
- 完全删除旧技能
- 完全移除规则匹配
- 系统只支持新格式技能

**迁移建议**：
- 在测试环境先执行迁移
- 提供数据备份和恢复机制
- 准备回滚方案
