## ADDED Requirements

### Requirement: 纯 LLM 驱动的技能引擎
系统 SHALL 完全基于 LLM 进行技能发现和调用，不再支持规则匹配机制。

#### Scenario: LLM 多阶段技能发现
- **WHEN** 用户发送消息，系统需要选择技能
- **THEN** 系统使用 LLM 进行多阶段发现：
  - **阶段1（发现）**：LLM 分析用户意图，从所有可用技能中发现可能相关的技能（基于技能元数据）
  - **阶段2（评估）**：LLM 深度评估候选技能的适用性（基于技能指令）
  - **阶段3（选择）**：LLM 选择最合适的技能组合（基于完整技能信息）
  - **阶段4（执行）**：系统执行选定的技能并处理结果
- **AND** 系统不再使用规则匹配（关键词匹配、字符串包含等）
- **AND** 系统不再降级到规则驱动

#### Scenario: 技能发现阶段
- **WHEN** 系统进入技能发现阶段
- **THEN** 系统调用 LLM，提供用户消息、对话上下文和所有可用技能的元数据（Level 1）
- **AND** LLM 分析用户意图，返回可能相关的技能列表（带相关性评分）
- **AND** 系统根据相关性评分筛选候选技能（例如：只保留评分 > 50 的技能）

#### Scenario: 技能评估阶段
- **WHEN** 系统进入技能评估阶段
- **THEN** 系统调用 LLM，提供候选技能列表和技能的详细指令（Level 2）
- **AND** LLM 评估每个技能是否真正适合当前场景
- **AND** LLM 返回评估结果（置信度、是否适用、参数提取等）
- **AND** 系统根据评估结果筛选技能（例如：只保留适用且置信度 > 70 的技能）

#### Scenario: 技能选择阶段
- **WHEN** 系统进入技能选择阶段
- **THEN** 系统调用 LLM，提供评估后的技能列表和完整技能信息（Level 3）
- **AND** LLM 选择最合适的技能组合，考虑技能之间的协同
- **AND** LLM 返回最终选择的技能列表和执行顺序
- **AND** 系统按照执行顺序执行技能

### Requirement: 移除规则匹配机制
系统 SHALL 完全移除规则匹配机制，包括关键词匹配、字符串包含、规则评分等。

#### Scenario: 移除规则匹配代码
- **WHEN** 系统评估技能适用性
- **THEN** 系统不再使用关键词匹配
- **AND** 系统不再使用字符串包含判断
- **AND** 系统不再使用规则评分机制
- **AND** 系统完全依赖 LLM 进行判断

#### Scenario: 移除降级机制
- **WHEN** LLM 调用失败或返回错误
- **THEN** 系统不再降级到规则驱动
- **AND** 系统返回错误或空结果，而不是使用规则匹配
- **AND** 系统记录错误日志，便于排查问题

### Requirement: 删除所有旧格式技能
系统 SHALL 删除所有不符合新规范的旧格式技能，只保留符合 Claude Skills 规范的新技能。

#### Scenario: 识别和删除旧技能
- **WHEN** 系统执行技能清理
- **THEN** 系统识别所有旧格式技能：
  - 使用 `function_schema` 的技能
  - 缺少 `skill_content` 的技能
  - 缺少 `mcp_tool_config` 但需要工具调用的技能
- **AND** 系统在删除前备份所有旧技能数据
- **AND** 系统删除所有旧格式技能
- **AND** 系统清理相关的角色技能绑定（如果绑定到已删除的技能）
- **AND** 系统验证删除操作成功

#### Scenario: 验证剩余技能
- **WHEN** 删除旧技能后
- **THEN** 系统验证所有剩余技能都符合新规范：
  - 包含 `skill_content` 字段
  - 如果使用工具调用，包含 `mcp_tool_config` 字段
  - 包含完整的元数据字段（license, compatibility, metadata 等）
- **AND** 系统生成验证报告

## MODIFIED Requirements

### Requirement: 技能引擎架构
系统 SHALL 采用纯 LLM 驱动的技能引擎架构，移除所有规则匹配和降级机制。

#### Scenario: 引擎架构简化
- **WHEN** 系统需要评估和应用技能
- **THEN** 系统只使用 LLM 驱动的引擎
- **AND** 系统不再维护规则驱动引擎
- **AND** 系统不再维护降级机制
- **AND** 系统架构更加简洁和可维护

### Requirement: 技能查询和过滤
系统 SHALL 只返回符合新规范的技能，不再支持旧格式技能的查询。

#### Scenario: 技能列表查询
- **WHEN** 前端调用技能列表 API
- **THEN** 系统只返回符合新规范的技能
- **AND** 系统不返回使用 `function_schema` 的技能
- **AND** 系统不返回缺少 `skill_content` 的技能
- **AND** 系统验证返回的技能都符合新规范

## REMOVED Requirements

### Requirement: 规则匹配机制
系统 SHALL 不再支持基于规则的技能匹配，包括关键词匹配、字符串包含、规则评分等。

#### Scenario: 移除规则匹配
- **WHEN** 系统评估技能适用性
- **THEN** 系统不再使用关键词匹配
- **AND** 系统不再使用字符串包含判断
- **AND** 系统不再使用规则评分机制
- **AND** 相关代码已被删除

### Requirement: 规则驱动引擎
系统 SHALL 不再维护规则驱动的技能引擎作为降级方案。

#### Scenario: 移除规则驱动引擎
- **WHEN** LLM 调用失败
- **THEN** 系统不再降级到规则驱动引擎
- **AND** 规则驱动引擎相关代码已被删除
- **AND** 系统返回错误或空结果
