# Design: Manus 风格前端交互界面

## Context

参考 Manus AI 的界面设计（详见用户提供的截图），需要重新设计 Mentis 前端界面，采用 Manus 的布局风格和交互模式。Manus 的界面特点：
- 左侧边栏：导航菜单、项目列表、任务列表
- 右侧主内容区：对话界面、任务详情、虚拟机终端
- 统一的会话模型：不区分会话类型，根据需求动态显示相关界面
- 智能界面切换：根据任务分解和工具执行环境自动显示相关界面

## Goals / Non-Goals

### Goals
- 完全采用 Manus 的布局和风格
- 统一会话操作（不区分标准会话、任务会话、VM 会话）
- 动态显示任务列表（任务分解时自动显示）
- 动态显示虚拟机界面（需要虚拟机执行时自动创建和显示）
- 根据工具执行环境智能切换界面
- 实时显示 AI 思考过程、任务进度、虚拟机状态

### Non-Goals
- 不实现 Manus 的所有功能（聚焦核心界面和交互）
- 不改变后端 API 结构（仅前端界面重构）
- 不实现 Manus 的协作和分享功能（除非明确要求）

## Decisions

### Decision 1: 布局结构

**选择**: 三栏布局（左侧边栏 + 中间主内容区 + 右侧可选面板）

**布局结构**:
```
┌─────────────────────────────────────────────────────────┐
│  Top Bar: Logo, Version, Actions (协作/分享/设置)        │
├──────────┬──────────────────────────┬──────────────────┤
│          │                          │                  │
│  Left    │    Main Content Area     │  Right Panel     │
│  Sidebar │    (对话/任务/虚拟机)      │  (可选: 任务详情)  │
│          │                          │                  │
│  - 导航   │  - 对话消息流            │  - 任务详情       │
│  - 项目   │  - 任务进度              │  - 执行日志       │
│  - 任务   │  - 虚拟机终端            │  - 工具调用       │
│          │  - 输入框                │                  │
│          │                          │                  │
└──────────┴──────────────────────────┴──────────────────┘
```

**理由**:
- 与 Manus 布局一致
- 左侧提供导航和上下文，中间提供主要内容，右侧提供详细信息
- 支持响应式设计（小屏幕时可折叠侧边栏）

### Decision 2: 统一会话模型

**选择**: 单一会话类型，根据内容动态显示界面

**实现方式**:
- 所有会话使用相同的界面结构
- 根据会话内容自动显示相关组件：
  - 有任务分解 → 显示任务列表
  - 有虚拟机操作 → 显示虚拟机界面
  - 纯对话 → 仅显示对话界面
- 会话状态统一管理（不区分类型）

**理由**:
- 简化用户操作，无需选择会话类型
- 根据实际需求自动适配，更智能
- 与 Manus 的设计理念一致

### Decision 3: 动态界面切换

**选择**: 基于工具执行环境和任务状态自动切换界面

**切换逻辑**:
1. **初始状态**: 仅显示对话界面
2. **任务分解时**: 自动在左侧显示任务列表，主内容区显示任务详情
3. **虚拟机执行时**: 自动创建虚拟机，在主内容区显示虚拟机终端和屏幕
4. **多任务并行**: 支持同时显示多个界面（对话 + 任务 + 虚拟机）

**理由**:
- 用户无需手动切换界面，系统自动适配
- 提供更好的上下文感知
- 减少用户操作步骤

### Decision 4: 实时更新机制

**选择**: WebSocket + SSE 双通道实时更新

**更新内容**:
- **WebSocket**: 双向通信（用户输入、控制命令）
- **SSE**: 单向推送（AI 思考过程、任务进度、虚拟机状态、截图）

**理由**:
- WebSocket 支持双向通信，适合交互操作
- SSE 适合服务器向客户端推送大量更新
- 分离关注点，提高性能

### Decision 5: 虚拟机界面集成

**选择**: 集成 noVNC 或自定义 VNC 客户端

**显示方式**:
- **终端视图**: 实时显示命令执行（文本终端）
- **桌面视图**: VNC 屏幕预览（完整桌面）
- **切换按钮**: 支持在终端和桌面视图间切换

**理由**:
- noVNC 是成熟的 Web VNC 客户端
- 支持实时屏幕预览，用户体验好
- 如果 noVNC 集成困难，可降级到截图方式

## Architecture

### 组件结构

```
MentisMainPage (主页面)
├── TopBar (顶部工具栏)
│   ├── Logo
│   ├── Version Info
│   └── Action Buttons (协作/分享/设置)
├── LeftSidebar (左侧边栏)
│   ├── NavigationMenu (导航菜单)
│   │   ├── 新建任务
│   │   ├── 搜索
│   │   └── 库
│   ├── ProjectList (项目列表)
│   └── TaskList (任务列表 - 动态显示)
│       ├── TaskItem (任务项)
│       └── TaskProgress (任务进度)
├── MainContentArea (主内容区)
│   ├── ConversationView (对话视图 - 默认)
│   │   ├── MessageList (消息列表)
│   │   │   ├── UserMessage
│   │   │   ├── AgentMessage
│   │   │   └── SystemMessage
│   │   └── InputArea (输入区)
│   ├── TaskDetailView (任务详情视图 - 动态显示)
│   │   ├── TaskSteps (任务步骤)
│   │   ├── TaskProgress (任务进度)
│   │   └── ExecutionLog (执行日志)
│   └── VirtualComputerView (虚拟机视图 - 动态显示)
│       ├── VmTerminal (虚拟机终端)
│       ├── VmScreen (虚拟机屏幕 - VNC)
│       └── VmControls (虚拟机控制)
└── RightPanel (右侧面板 - 可选)
    ├── TaskDetailPanel (任务详情面板)
    ├── ExecutionLogPanel (执行日志面板)
    └── ToolCallPanel (工具调用面板)
```

### 状态管理

```typescript
interface SessionState {
  // 会话基本信息
  id: string;
  title: string;
  createdAt: Date;
  updatedAt: Date;
  
  // 会话内容
  messages: Message[];
  tasks?: Task[];  // 动态：任务分解时存在
  virtualComputer?: VirtualComputer;  // 动态：虚拟机执行时存在
  
  // UI 状态
  activeView: 'conversation' | 'task' | 'virtual-computer';
  showRightPanel: boolean;
  rightPanelContent?: 'task-detail' | 'execution-log' | 'tool-calls';
}
```

### 数据流

```
用户输入
  ↓
发送到后端 API
  ↓
后端处理（Planner/Executor/Monitor）
  ↓
流式返回更新
  ├─→ AI 思考过程 → 显示在对话界面
  ├─→ 任务分解 → 显示任务列表
  ├─→ 工具执行 → 显示执行日志
  └─→ 虚拟机操作 → 显示虚拟机界面
```

## Risks / Trade-offs

### Risk 1: 界面复杂度增加
**缓解措施**:
- 采用组件化设计，每个界面独立组件
- 使用状态管理库（如 Zustand 或 Redux）统一管理状态
- 充分的代码注释和文档

### Risk 2: 实时更新性能问题
**缓解措施**:
- 使用虚拟滚动优化长列表性能
- 消息去重和节流
- 图片懒加载和压缩

### Risk 3: VNC 集成复杂度
**缓解措施**:
- 优先使用成熟的 noVNC 库
- 如果集成困难，降级到截图方式
- 提供降级方案文档

### Risk 4: 响应式设计挑战
**缓解措施**:
- 使用 Tailwind CSS 响应式工具类
- 移动端采用折叠侧边栏
- 小屏幕时隐藏右侧面板

## Migration Plan

### Phase 1: 基础布局 (1周)
- 实现三栏布局结构
- 实现左侧边栏（导航、项目、任务列表）
- 实现顶部工具栏
- 实现基础样式（Manus 风格）

### Phase 2: 统一会话界面 (2周)
- 实现会话列表组件
- 实现对话界面（消息列表、输入框）
- 实现会话状态管理
- 集成 WebSocket/SSE 实时更新

### Phase 3: 任务列表显示 (1周)
- 实现任务列表组件
- 实现任务详情视图
- 实现任务进度显示
- 实现任务状态更新

### Phase 4: 虚拟机界面 (2周)
- 集成 noVNC 或实现自定义 VNC 客户端
- 实现虚拟机终端视图
- 实现虚拟机屏幕预览
- 实现虚拟机控制按钮

### Phase 5: 动态布局系统 (1周)
- 实现动态界面切换逻辑
- 实现多面板同时显示
- 实现响应式布局
- 优化性能和用户体验

### 总计: 7周（约1.75个月）

## Open Questions

1. **VNC 客户端选型**？
   - 当前决策：优先 noVNC，备选截图方式
   - 需要评估：noVNC 的集成难度和性能

2. **任务列表显示时机**？
   - 当前决策：任务分解时自动显示
   - 需要确认：是否支持手动隐藏/显示

3. **虚拟机创建时机**？
   - 当前决策：需要虚拟机执行时自动创建
   - 需要确认：是否支持手动创建/销毁

4. **右侧面板显示规则**？
   - 当前决策：根据内容自动显示
   - 需要确认：是否支持用户手动控制
