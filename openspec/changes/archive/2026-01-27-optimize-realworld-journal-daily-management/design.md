# Design: 优化现实世界日志功能，便于日常管理

## Context

现实世界（RealWorldScreen / MobileRealWorldScreen）是心域中的日记场景，承载日志的创建、编辑、删除、列表展示及标签、搜索、模板、镜面洞察等能力。日志数据通过 `journalApi` 拉取，前端以 `JournalEntry`（含 `entryDate`、`timestamp` 等）管理。用户希望将现实世界作为本地办公主载体，当前阶段仅优化日志，便于日常管理；备忘、邮件等后续再做。

## Goals / Non-Goals

### Goals
- 提供以日期为核心的快捷筛选（今日、本周、本月、可选日期范围），与关键词、标签筛选组合使用。
- 优化列表展示：按日期分组、多种排序选项，条目多时保证流畅。
- 提供「写今日」等快捷入口，默认当天日期，可关联模板，减少操作步骤。
- 优化模板选择与创建默认值，新建默认 `entryDate` 为当天。
- PC 与 Mobile 能力对齐，交互按端适配。

### Non-Goals
- 不实现备忘、邮件管理或其它现实世界新模块。
- 不做日志后端 API 的破坏性变更；若需日期范围检索，优先前端筛选或最小化 API 扩展。
- 不做通用「办公套件」级功能，仅围绕日志的日常管理体验。

## Decisions

### Decision 1: 日期筛选以前端为主
**Why**：现有 `journalApi` 拉取全量列表，改造成本低；用户条目量在可接受范围内时，前端按 `entryDate` / `timestamp` 筛选即可满足今日 / 本周 / 本月等需求。

**Implementation**：
- 在 RealWorldScreen / MobileRealWorldScreen 中维护「日期范围」状态（如 today / week / month / custom）。
- 对 `entries` 做二次过滤：先应用关键词、标签，再按日期范围过滤。
- 若后续数据量增大或后端已有日期范围接口，再考虑服务端筛选。

### Decision 2: 列表分组与排序
**Why**：按日/周分组便于「按时间回顾」；多排序选项满足「最近写过」与「按日记日期浏览」等不同习惯。

**Implementation**：
- 分组：按日记日期（`entryDate`）分组，支持「按日」或「按周」展示；组内按选定排序规则排列。
- 排序：至少支持「按日记日期倒序」「按更新时间倒序」；默认按日记日期倒序。
- 若列表很长，引入虚拟列表或分页，避免一次性渲染过多 DOM。

### Decision 3: 「写今日」与模板
**Why**：高频场景是「今天记一笔」；模板可减少空白页焦虑，与现有 `journalTemplates` 一致。

**Implementation**：
- 「写今日」：一键进入创建态，`entryDate` 固定为当天，标题可预填「今日」或留空。
- 可选「从模板写今日」：选模板后 prefilled 标题/内容，`entryDate` 仍为当天。
- 新建日记（不论入口）默认 `entryDate` 为当天，与「写今日」一致。

### Decision 4: PC 与 Mobile 共享逻辑、分端适配 UI
**Why**：避免两套实现漂移，便于后续维护；两端交互习惯不同，UI 可差异化。

**Implementation**：
- 日期筛选、排序、分组、默认 `entryDate` 等逻辑可抽成 hook 或工具函数，PC/Mobile 共用。
- 筛选条、分组列表、快捷按钮等组件可按端实现不同布局（如 Mobile 折叠、抽屉），但能力对齐。

## Risks / Trade-offs

- **前端筛选数据量**：若用户条目很多，全量拉取再过滤可能有性能压力。缓解：先做前端实现，必要时加虚拟列表/分页；再评估后端按日期范围查询。
- **`entryDate` 与 `updatedAt`**：排序若按「更新时间」，需确保 API 返回 `updatedAt` 且前端统一使用；若缺失，可暂仅支持按日记日期排序。

## Migration Plan

1. 实现日期筛选（今日 / 本周 / 本月 / 自定义）及与搜索、标签的组合。
2. 实现列表分组与排序，并做了结。
3. 实现「写今日」及模板快捷入口，统一新建默认 `entryDate`。
4. 在 Mobile 上复用逻辑并适配 UI。
5. 补充使用说明（若有），并做简单回归。

## Open Questions

- 日期范围「自定义」是否在首版支持（如日期选择器），还是先做今日/本周/本月？
- 「按周」分组的周起止（周一 vs 周日）是否需可配置？
- 虚拟列表 / 分页的阈值（条目数）定多少？
