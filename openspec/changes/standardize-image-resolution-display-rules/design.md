# Design: 标准化图片分辨率展示规则

## Context

系统已经实现了多分辨率图片生成功能，生成了三种标准分辨率版本：
- 200×200 小缩略图（质量 0.85）
- 800×600 中等质量图（质量 0.85）
- 1920×1080 高质量图（质量 0.9）

但是不同项目（admin、main、edu等）中图片展示规则不统一，导致：
1. 代码重复：每个项目都有自己的分辨率选择逻辑
2. 规则不一致：相同场景在不同项目中使用不同分辨率
3. 维护困难：修改规则需要在多个项目中同步

## Goals / Non-Goals

### Goals
- 统一所有项目的图片分辨率展示规则
- 定义标准化的展示场景类型
- 建立场景到分辨率的映射规则
- 提供统一的工具函数和组件
- 确保向后兼容，支持渐进式迁移

### Non-Goals
- 不修改多分辨率生成逻辑（已有规范）
- 不强制所有项目立即迁移（支持渐进式）
- 不改变现有的文件命名规范（已有规范）

## Decisions

### Decision 1: 展示场景类型定义
**选择**: 使用枚举类型定义标准场景

**标准场景**:
- `thumbnail`: 缩略图（列表、卡片等小尺寸展示）
- `list`: 列表项（列表中的图片项）
- `detail`: 详情页/对话框（中等尺寸展示）
- `background`: 移动端背景（移动端全屏背景）
- `chatBackground`: ChatWindow背景（PC端聊天窗口背景）
- `original`: 原图（特殊需求，不推荐）

**理由**:
- 覆盖所有常见使用场景
- 语义清晰，易于理解
- 易于扩展新场景

### Decision 2: 场景到分辨率映射规则
**选择**: 固定映射规则，支持设备类型判断

**映射规则**:
- `thumbnail` / `list` → 200×200 小缩略图
- `detail` → 800×600 中等质量图
- `background` → 800×600 中等质量图（移动端）
- `chatBackground` → 1920×1080 高质量图（PC）或 800×600 中等质量图（移动端）
- `original` → 原图

**回退策略**:
1. 优先使用目标分辨率版本
2. 如果不存在，按优先级回退：
   - 小缩略图场景：回退到原图
   - 中等质量场景：回退到小缩略图 → 原图
   - 高质量场景：回退到中等质量图 → 小缩略图 → 原图

**理由**:
- 平衡图像质量和加载性能
- 覆盖所有设备类型（PC/移动端）
- 确保始终有可用的图片版本

### Decision 3: 统一实现方式
**选择**: 在 shared 模块或 main 项目中提供统一工具，其他项目引用

**实现方式**:
1. 在 `main/frontend/utils/imageResolution.ts` 中提供统一实现
2. 其他项目（admin、edu等）通过共享或复制方式使用
3. 所有项目使用相同的类型定义和函数签名

**理由**:
- 避免代码重复
- 统一维护，一处修改全局生效
- 支持跨项目复用

**替代方案**: 每个项目独立实现
- 优点：项目间解耦
- 缺点：规则可能不一致，维护成本高

### Decision 4: 组件集成方式
**选择**: 在 `LazyImage` 组件中集成分辨率选择逻辑

**实现方式**:
- `LazyImage` 组件接收 `purpose` 和 `variants` 参数
- 组件内部调用 `selectImageResolution()` 函数
- 自动根据场景选择合适的分辨率

**理由**:
- 使用简单，开发者无需关心细节
- 统一行为，避免误用
- 易于维护和更新

## Risks / Trade-offs

### Risk 1: 迁移成本
**影响**: 现有代码需要逐步迁移到新规则

**缓解措施**:
- 保持向后兼容，现有代码可继续工作
- 提供迁移指南和示例代码
- 支持渐进式迁移，不强制一次性完成

### Risk 2: 规则过于严格
**影响**: 某些特殊场景可能需要不同的规则

**缓解措施**:
- 提供 `original` 场景用于特殊需求
- 允许组件级覆盖（通过直接指定 URL）
- 规则可以通过配置扩展（未来）

### Risk 3: 跨项目依赖
**影响**: 如果使用共享模块，项目间可能产生依赖

**缓解措施**:
- 优先使用复制方式（避免运行时依赖）
- 如果使用共享，确保版本兼容性
- 提供独立的工具函数，不依赖其他模块

## Migration Plan

### Phase 1: 统一工具函数（不影响现有功能）
1. 完善 `main/frontend/utils/imageResolution.ts`
2. 确保类型定义完整
3. 添加完整的场景映射规则
4. 添加回退策略

### Phase 2: 统一组件实现（渐进式）
1. 更新 `main/frontend/components/LazyImage.tsx` 使用统一规则
2. 更新 `admin/frontend/src/components/LazyImage.tsx` 使用统一规则
3. 更新其他项目的图片组件（如有）

### Phase 3: 文档和规范（可选）
1. 编写使用指南
2. 更新开发文档
3. 提供迁移示例

### Rollback Plan
- 如果出现问题，可以：
  1. 回退到项目特定的实现
  2. 保持现有代码不变
  3. 逐步修复问题后重新迁移

## Open Questions

1. **共享方式**: 使用共享模块还是复制代码？建议先复制，确保项目独立性。
2. **配置化**: 是否需要支持配置化的映射规则？当前使用固定规则，未来可扩展。
3. **新场景**: 如何添加新场景？通过扩展枚举类型和映射规则。
