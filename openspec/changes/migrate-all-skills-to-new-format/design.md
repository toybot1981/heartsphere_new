# Design: 迁移所有技能到新格式

## 迁移策略

### 整体流程

```
1. 备份旧技能数据
   ↓
2. 读取所有旧技能
   ↓
3. 对每个旧技能：
   a. 提取关键信息（描述、功能、参数等）
   b. 调用 AI 生成新格式技能
   c. 验证生成结果
   d. 保存新技能
   ↓
4. 迁移角色技能绑定
   ↓
5. 删除旧技能（或标记为已废弃）
   ↓
6. 生成迁移报告
```

## AI 生成策略

### 输入信息提取

从旧技能中提取以下信息用于 AI 生成：
- **基础信息**：skillId, name, description, category, skillType
- **功能描述**：description 字段的详细内容
- **参数信息**：function_schema 中的参数定义（如果存在）
- **执行配置**：execution_config 中的配置信息
- **触发关键词**：auto_trigger_keywords
- **使用场景**：从 description 中提取的使用场景信息

### AI 提示词设计

```
你是一个技能迁移助手。根据旧技能的信息，生成一个符合 Claude Skills 规范的新技能定义（JSON格式）。

旧技能信息：
- 技能ID: {oldSkillId}
- 名称: {name}
- 描述: {description}
- 分类: {category}
- 类型: {skillType}
- 参数定义: {functionSchema}（如果存在）
- 执行配置: {executionConfig}（如果存在）
- 触发关键词: {autoTriggerKeywords}（如果存在）

请生成一个完整的新格式技能定义，要求：
1. 保持技能的核心功能和用途不变
2. 使用新的字段结构：
   - skillId: 保持原值或优化（小写字母、数字、连字符，1-64字符）
   - name: 保持原值或优化
   - description: 优化描述，使其更清晰、完整（1-1024字符）
   - category: 保持或优化分类
   - skillType: 保持或优化类型
   - instruction: 生成详细的 Markdown 格式指令，说明技能的功能、使用方法、参数等
   - mcpToolConfig: 如果有参数定义，尝试匹配或创建 MCP 工具配置（JSON格式）
   - executionConfig: 保持或优化执行配置
   - license: 设置为 "MIT"（默认）
   - version: 设置为 "2.0.0"（表示新格式版本）
   - skillContent: 生成完整的 SKILL.md 格式内容（YAML front matter + Markdown 指令）

3. 确保所有字段符合新规范要求
4. 如果原技能有 function_schema，尝试转换为 mcp_tool_config

请返回完整的技能定义 JSON。
```

### 生成结果处理

1. **解析 AI 返回的 JSON**
2. **验证字段格式**：
   - skillId 格式验证
   - description 长度验证
   - 必需字段检查
3. **补充缺失字段**：
   - 如果 AI 未生成某些字段，使用默认值或从旧技能继承
4. **生成 skill_content**：
   - 如果 AI 未生成 skill_content，根据其他字段自动生成
5. **保存新技能**

## 角色技能绑定迁移

### 迁移策略

1. **建立映射关系**：
   - 旧技能 skillId -> 新技能 skillId
   - 如果 skillId 保持不变，直接更新绑定
   - 如果 skillId 改变，需要更新绑定中的 skillId

2. **迁移绑定数据**：
   - 保持 characterId 不变
   - 更新 skillId 为新技能的 skillId
   - 保持其他配置不变（isEnabled, autoTrigger, priority 等）

3. **处理冲突**：
   - 如果新技能已存在绑定，合并配置或提示用户

## 数据备份和恢复

### 备份策略

1. **备份表**：创建 `skill_definitions_backup` 表
2. **备份时机**：在开始迁移前备份所有旧技能
3. **备份内容**：完整的技能定义数据
4. **备份验证**：验证备份数据的完整性

### 恢复机制

1. **保留备份数据**：至少保留 30 天
2. **恢复接口**：提供恢复单个或批量技能的能力
3. **恢复验证**：恢复后验证数据完整性

## 删除策略

### 选项1：物理删除（推荐）

- 直接删除旧技能记录
- 优点：彻底清理，减少数据冗余
- 缺点：无法恢复（需要依赖备份）

### 选项2：软删除

- 标记旧技能为已废弃（添加 `is_deprecated` 字段）
- 优点：可以恢复
- 缺点：数据仍然存在

**建议采用选项1（物理删除）+ 完整备份**

## 迁移验证

### 验证项

1. **格式验证**：
   - 新技能必须包含所有必需字段
   - 字段格式符合规范
   - skill_content 格式正确

2. **功能验证**：
   - 新技能的功能描述与原技能一致
   - 参数定义（如果有）正确转换

3. **绑定验证**：
   - 所有角色技能绑定已正确迁移
   - 没有孤立的绑定记录

4. **数量验证**：
   - 新技能数量 >= 旧技能数量（可能一个旧技能生成多个新技能，或合并）

## 错误处理

### 生成失败处理

- 如果 AI 生成失败，记录错误并跳过该技能
- 提供手动迁移选项
- 生成失败报告

### 验证失败处理

- 如果验证失败，不保存新技能
- 记录失败原因
- 提供修复建议

### 回滚机制

- 如果迁移过程中发生严重错误，支持回滚
- 恢复备份数据
- 恢复角色技能绑定

## 性能考虑

### 批量处理

- 分批处理技能（例如：每批 10 个）
- 使用异步处理提高效率
- 显示进度和状态

### AI 调用优化

- 批量调用 AI 服务（如果支持）
- 缓存生成结果
- 重试机制

## 迁移报告

生成详细的迁移报告，包括：
- 迁移的技能总数
- 成功迁移数量
- 失败数量及原因
- 新技能列表
- 删除的旧技能列表
- 绑定的迁移情况
- 建议和注意事项
