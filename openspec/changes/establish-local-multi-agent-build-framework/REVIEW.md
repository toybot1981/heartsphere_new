### 6. 技术细节补充建议

#### 1. Mock LLM 服务实现细节

**建议在 design.md 中补充**：

```markdown
### Mock LLM Service Implementation

#### 架构选择
- **方案 A**：独立 HTTP 服务（推荐）
  - 优点：与真实 API 接口一致，易于切换
  - 缺点：需要额外进程管理
- **方案 B**：嵌入式 Mock（Spring Boot Test）
  - 优点：集成简单，无需额外进程
  - 缺点：仅适用于测试环境

#### API 兼容性
- 支持 DashScope API 格式
- 支持 OpenAI API 格式
- 支持 Gemini API 格式（如需要）
- 统一的配置接口，通过配置切换格式

#### 响应模板系统
- 基于请求内容匹配模板（关键词、正则表达式）
- 支持延迟模拟（可配置延迟时间）
- 支持错误模拟（可配置错误率）
- 模板存储在 `tools/mock-llm-service/templates/` 目录
```

#### 2. 构建缓存策略细节

**建议在 design.md 中补充**：

```markdown
### Build Cache Strategy

#### 缓存粒度
- **文件级缓存**：基于文件 hash，检测单个文件变更
- **模块级缓存**：基于模块版本和依赖版本
- **全局缓存**：跨模块共享的构建产物

#### 缓存失效策略
- **时间失效**：默认 7 天 TTL
- **依赖变更失效**：检测 pom.xml、package.json 变更
- **手动失效**：提供 `cache-clean.sh` 脚本

#### 缓存存储
- 缓存目录：`.build-cache/`（加入 .gitignore）
- 缓存格式：JSON 元数据 + 构建产物
- 缓存大小限制：默认 10GB，可配置
```

### 7. 风险评估补充

#### 需要补充的风险

1. **Mock 服务维护成本**
   - **风险**：Mock 服务需要与真实 API 保持同步，维护成本高
   - **缓解**：
     - 提供自动化工具从真实 API 响应生成 Mock 模板
     - 定期更新 Mock 模板（建议每周）
     - 提供 Mock 模板版本管理

2. **构建缓存存储空间**
   - **风险**：构建缓存可能占用大量磁盘空间
   - **缓解**：
     - 设置缓存大小限制
     - 自动清理过期缓存
     - 提供缓存压缩选项

3. **多平台兼容性**
   - **风险**：脚本在不同操作系统（macOS、Linux、Windows）可能不兼容
   - **缓解**：
     - 使用跨平台脚本工具（如使用 Python 或 Node.js 脚本）
     - 提供平台特定的脚本变体
     - 充分测试多平台兼容性
