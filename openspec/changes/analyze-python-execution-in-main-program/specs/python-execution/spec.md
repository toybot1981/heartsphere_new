## ADDED Requirements

### Requirement: Python 脚本执行能力
系统 SHALL 提供统一的 Python 脚本执行能力，支持多种执行策略，并根据场景自动选择最优策略。

#### Scenario: 直接执行 Python 脚本
- **WHEN** 用户请求执行简单的 Python 脚本，且本地环境已安装 Python 和所需依赖
- **THEN** 系统使用直接执行策略，通过 ProcessBuilder 调用系统 python3 命令执行脚本
- **AND** 返回执行结果（标准输出、标准错误、退出码）

#### Scenario: 虚拟机执行 Python 脚本
- **WHEN** 用户请求执行需要隔离环境或自动安装依赖的 Python 脚本
- **THEN** 系统使用虚拟机执行策略，在 E2B 虚拟机中执行脚本
- **AND** 自动检测并安装缺失的 Python 依赖
- **AND** 返回执行结果（标准输出、标准错误、执行状态）

#### Scenario: 自动策略选择
- **WHEN** 用户请求执行 Python 脚本，未明确指定执行策略
- **THEN** 系统根据脚本特征、配置和场景自动选择执行策略
- **AND** 优先使用配置指定的策略
- **AND** 如果配置未指定，根据脚本复杂度、依赖需求等自动选择
- **AND** 如果直接执行失败，自动降级到虚拟机执行

#### Scenario: 执行超时处理
- **WHEN** Python 脚本执行时间超过配置的超时时间
- **THEN** 系统终止脚本执行
- **AND** 返回超时错误信息
- **AND** 清理相关资源（临时文件、进程等）

#### Scenario: 资源限制
- **WHEN** 在虚拟机中执行 Python 脚本
- **THEN** 系统限制脚本的资源使用（CPU、内存、磁盘）
- **AND** 如果资源使用超过限制，终止脚本执行
- **AND** 返回资源限制错误信息

### Requirement: 执行策略配置管理
系统 SHALL 支持配置 Python 执行策略和相关参数，支持多级配置（系统级、会话级、请求级）。

#### Scenario: 系统级配置
- **WHEN** 管理员配置系统默认的 Python 执行策略
- **THEN** 系统使用该配置作为默认策略
- **AND** 所有未明确指定策略的请求都使用该默认策略

#### Scenario: 会话级配置
- **WHEN** 为特定会话配置 Python 执行策略
- **THEN** 该会话的所有 Python 执行请求都使用该策略
- **AND** 会话级配置优先于系统级配置

#### Scenario: 请求级配置
- **WHEN** 单个执行请求明确指定执行策略
- **THEN** 系统使用请求指定的策略执行
- **AND** 请求级配置优先于会话级和系统级配置

#### Scenario: 配置参数
- **WHEN** 配置 Python 执行参数（超时时间、资源限制等）
- **THEN** 系统在执行时应用这些参数
- **AND** 支持配置的参数包括：超时时间、内存限制、CPU 限制、允许的 Python 库白名单、禁止的操作黑名单

### Requirement: 安全机制
系统 SHALL 提供多层安全防护，确保 Python 脚本执行的安全性。

#### Scenario: 输入验证
- **WHEN** 用户提交 Python 脚本执行请求
- **THEN** 系统验证脚本内容，检查是否包含危险操作
- **AND** 如果检测到禁止的操作（如文件系统访问、网络访问等），拒绝执行
- **AND** 返回安全错误信息

#### Scenario: 沙箱隔离
- **WHEN** 在虚拟机中执行 Python 脚本
- **THEN** 脚本在隔离的虚拟机环境中执行
- **AND** 脚本无法访问主机系统资源
- **AND** 脚本执行完成后，虚拟机环境自动清理

#### Scenario: 审计日志
- **WHEN** 执行 Python 脚本
- **THEN** 系统记录审计日志，包括：执行时间、执行策略、脚本内容摘要、执行结果、执行耗时
- **AND** 审计日志用于安全审计和问题排查

### Requirement: 错误处理和降级
系统 SHALL 提供完善的错误处理机制，支持执行失败时的降级策略。

#### Scenario: 直接执行失败降级
- **WHEN** 直接执行 Python 脚本失败（如缺少依赖、环境问题等）
- **THEN** 系统自动降级到虚拟机执行
- **AND** 在虚拟机中重新执行脚本
- **AND** 返回虚拟机执行的结果

#### Scenario: 错误信息返回
- **WHEN** Python 脚本执行失败
- **THEN** 系统返回详细的错误信息，包括：错误类型、错误消息、堆栈跟踪（如果可用）
- **AND** 错误信息帮助用户诊断问题

#### Scenario: 资源清理
- **WHEN** Python 脚本执行完成或失败
- **THEN** 系统清理相关资源，包括：临时文件、进程、虚拟机资源（如果使用）
- **AND** 确保不会留下残留资源

### Requirement: 统一执行接口
系统 SHALL 提供统一的 Python 执行接口，所有 Python 执行都通过此接口进行。

#### Scenario: 接口调用
- **WHEN** 需要执行 Python 脚本
- **THEN** 调用统一的 `PythonExecutionService.executeScript()` 方法
- **AND** 传入执行请求（脚本内容、执行策略、参数等）
- **AND** 返回统一的执行结果

#### Scenario: 多模块使用
- **WHEN** 不同模块（工具系统、技能系统、任务执行系统）需要执行 Python 脚本
- **THEN** 都通过统一的接口执行
- **AND** 执行行为一致，便于维护和扩展

#### Scenario: 策略扩展
- **WHEN** 需要添加新的执行策略（如容器执行）
- **THEN** 实现新的策略类，注册到策略选择器
- **AND** 无需修改调用方代码
- **AND** 策略选择器自动识别并使用新策略
