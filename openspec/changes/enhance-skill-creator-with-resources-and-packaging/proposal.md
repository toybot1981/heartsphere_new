# Change: 增强技能创建器：资源管理和验证功能

## Why

参照 Claude 官方的 skill-creator，当前系统的技能创建工具还缺少以下关键功能：

1. **技能资源管理缺失** - 虽然已有系统资源管理，但缺少专门针对技能的资源管理（scripts/, references/, assets/），无法在创建技能时上传和管理这些资源文件
2. **渐进式披露验证缺失** - 缺少对技能是否符合渐进式披露原则的验证（SKILL.md 长度、资源组织等）
3. **技能验证不完整** - 当前验证主要关注字段格式，缺少对技能结构、资源引用、描述质量等的全面验证
4. **技能迭代支持不足** - 缺少基于使用反馈的迭代机制和工具

**注意**：打包功能和初始化功能在当前系统中意义不大：
- **打包功能**：技能存储在数据库中，不是文件系统，没有跨系统分发的需求。如果需要备份，可以直接备份数据库或导出 JSON。
- **初始化功能**：已有 AI 生成功能可以直接生成完整技能定义，已有文件导入功能可以从 skill.md 导入，手动编辑模式已有模板系统。初始化功能只是创建空模板，不如 AI 生成有用。

参考 Claude 官方的 skill-creator 最佳实践，我们需要补充资源管理和增强验证功能，使技能创建工具更加完善和专业。

## What Changes

- **技能资源管理** - 在技能创建器中支持上传和管理 scripts/, references/, assets/ 资源文件
  - 支持文件上传（Python脚本、Markdown文档、模板文件等）
  - 支持资源分类和预览
  - 支持资源引用和链接
  - 资源存储在技能资源表中，与技能定义关联


- **增强技能验证** - 扩展验证功能，参考 Claude 官方的验证规则
  - 验证 YAML frontmatter 格式和必需字段
  - 验证技能命名规范（hyphen-case，最大64字符）
  - 验证描述质量（长度、格式、关键词等）
  - 验证渐进式披露原则（SKILL.md 长度、资源组织）
  - 验证资源文件引用和存在性
  - 验证目录结构规范性

- **技能迭代支持** - 提供基于使用反馈的迭代机制
  - 记录技能使用统计
  - 提供技能质量评估报告
  - 支持技能版本管理
  - 提供改进建议

## Impact

- **Affected specs**: 
  - 修改 `skill-creation` 能力规范，新增资源管理、打包、初始化相关需求
  
- **Affected code**: 
  - `admin/backend`: 
    - 新增 `SkillResourceService` - 管理技能资源（scripts/references/assets）
    - 扩展 `SkillValidationService` - 增强验证功能
    - 新增技能资源表（skill_resources）
  - `admin/frontend`: 
    - 扩展 `SkillCreator` 组件，新增资源管理步骤
    - 增强验证反馈和错误提示
  - 数据库：
    - 新增 `skill_resources` 表，存储技能资源文件
    - 扩展 `skill_definitions` 表，添加资源引用字段（可选）

- **Affected data**: 
  - 技能资源文件需要存储（文件系统或对象存储）
